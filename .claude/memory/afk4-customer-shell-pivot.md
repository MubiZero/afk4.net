`Player.Shell` on the gaming PC was re-architected from pure WPF/XAML to a thin native host + React UI in WebView2 (reusing the Customer.Web design system). Enforcement (lock/kiosk, process policy, lease, offline-lease) stays in `Agent.Service` (separate process). Player.Shell is the non-authoritative "face" — server/Agent own billing/session-rights/policy; the shell talks to Agent.Service via named pipe for state and POSTs `/api/me/*` for self-service. Goal: smartshell.gg-class self-service UX.

**ALL BUILT & MERGED to main** (subagent-driven, TDD, per-task + final reviews):
- **Foundation + self-service (PR #65):** native WebView2 host `src/AFK4.Player.Shell/Web/` (kiosk hardening, watchdog/lock, native fallback), narrow whitelisted bridge `PlayerShellWebHostBridge`/`shellBridge.ts`, React app `src/AFK4.Player.Shell.Web`. Login via bridge `auth:signIn` (`POST /api/public/player/sign-in`, org from pipe-state; token held NATIVE in `PlayerApiAuthClient`, injected as Bearer on the API origin via `WebResourceRequested` — web only sees `{authenticated,displayName,phoneVerified}`). Self extend (`POST /api/me/sessions/{id}/extend`, 409 reconcile) + top-up (`/api/me/wallet/top-up-intent` dcgate, QR + poll, webhook-authoritative). New player catalog `GET /api/me/branches/{id}/tariffs|/packages`. WiX WebView2 launch-condition; old MainWindow/PlayerShellViewModel retired.
- **Unit F cycle 1 — SHOP (PR #66):** wallet-debit ordering of POS products flagged `PosProductEntity.AvailableInShell`; `ShopOrderEntity`/lines + migration, `EfShopOrderService` (place in serializable tx, optimistic-concurrency transitions → 409), SignalR push to operator; player `/api/me/shop/*`, operator `/api/branches/{id}/shop/*` (perm `ManageShopOrders`, Owner+BranchManager); shell `ShopScreen`, operator `ShopOrdersWorkspace`. Standalone accounting (own ledger + StockMovements, not PosSale); cancel reverses ledger + restores stock. Requires Active|Paused session.
- **Unit F cycle 2 — LOYALTY/CASHBACK (PR #67):** cashback = real spendable wallet money (`LedgerEntryTypeNames.Cashback`); org-wide config `OrganizationLoyaltySettingsEntity` (1 row/org, percent in **basis points**, separate owner toggles for top-up vs shop, no tiers, no clawback wiring); accrual at success (top-up confirm / shop `accepted→delivered`), atomic with source. Owner GET/**POST** `/api/owner/loyalty-settings` (perm `loyalty.settings.manage`, Owner-only, 0–10000 bps); player `GET /api/me/loyalty`. Shell `LoyaltyScreen`, operator `LoyaltySettingsWorkspace`.
- **Unit F cycle 3 — NEWS/banners (PR #68):** org-wide, owner-authored only (`/api/owner/news`, perm `news.manage`); optional `BranchId` target (null=all); title+body+optional image URL (no upload/CTA); `IsPublished` + optional `PublishAtUtc`/`ExpiresAtUtc` (query-time filter, no cron). `NewsItemEntity`, `EfNewsService`, owner POST/PATCH/DELETE, player `GET /api/me/news`. Shell `NewsScreen`, operator `NewsWorkspace` (branch dropdown from `GET /api/owner/branches`).

Only thing left for the whole epic; blocked by the WiX v7 OSMF EULA gate at MSI build (licensing, not code).
