**Хотелка юзера (2026-07-06, всплыла при обсуждении «VIP»)** — не булев VIP-флаг, а **полноценная подсистема статусов/лояльности клиентов**:
- Владелец **создаёт свои типы статусов** (VIP, Именинник, Уборщик, Постоянный… — произвольные).
- Каждый статус даёт **преференцию**: процентная скидка / бонус к депозиту / бонусные минуты игры / прочее.
- Присвоение: **ручное** И **авто по правилам** (день рождения, «10 дней подряд → 10% скидка», и т.п. — движок условий).
- Применяется в **Кассе и сессиях** (скидка при списании за игру/покупки).

**Почему отдельный эпик, а не часть редизайна Клиентов:** лезет в биллинг (скидки при списании — money-зона под guard'ами), пересекается с уже существующим кэшбэком (`OrganizationLoyaltySettingsEntity` — org-wide %, не per-client), требует движок правил для авто-присвоения. Свой цикл brainstorm→spec→plan.

**Что есть сейчас (база почти нулевая):** только org-wide кэшбэк-процент + per-client `PostpaidCreditLimitMinorUnits` (кредитный лимит). Нет ни статусов, ни tier, ни скидок per-client, ни движка правил. Строить с нуля.

**Решение по порядку:** делается ПОСЛЕ мержа UI-редизайна Клиентов (таблица+drawer, см. [[operator-clients-redesign-tabledrawer]]). Тогда таблица Клиентов легко получит колонку «Статус» + фильтр. Временный `isVip` в редизайне НЕ вводим, чтобы не плодить техдолг под снос.

**Статус:** бэклог, НЕ начат. Брейншторм ещё не проводился (только зафиксирована идея).
