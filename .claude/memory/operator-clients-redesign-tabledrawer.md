Полная пересборка раздела **«Клиенты»** оператор-аппа. Пользователь забраковал прошлый редизайн
(список+карточка-воркспейс) целиком — «отвратительно». Итерации макетов (статичный HTML на реальных
токенах проекта, отдавались по локальному URL, НЕ headless) сошлись на **mock-v7 — УТВЕРЖДЁН пользователем**.

**Утверждённый каркас (mock-v7):**
- **Широкая таблица клиентов** на всю ширину (не список+карточка): колонки **Клиент** (аватар+имя+телефон, теги VIP/Новый/Неактивен) · **Баланс** · **Долг** · **Потрачено** (lifetime spend из ledger, приглушённо) · **Сейчас / пакет** (играет `PC-01 · до 11:20` зелёным, иначе банк времени `Ночной 5ч · 150 мин`) · **Визит**. Долг = левый красный кант строки.
- **Узкий drawer справа (~372px)** выбранного клиента — родной паттерн приложения (Карта/Брони: широкая сетка + узкий drawer). Содержит ТОЛЬКО деньги: баланс(герой) → долг(callout) → быстрое пополнение с пресетами `+100/+200/+500` + своя сумма + **одна** primary «Пополнить» → «Списать долг» тихой ссылкой (только при долге) → **«Последние операции» (4 строки)** + «вся история →» (полный журнал по клику).
- **Разгрузка drawer:** управляющее уехало в меню «…»: Создать бронь, Изменить профиль, Задать ПИН, Ручная корректировка, Деактивировать.
- **Контекст в drawer = пилюли `.status-pill`** (реюз из `06-map-grid.css`, боковое меню Карты): «играет» = `ok` (зелёная, как «онлайн»), «бронь» = `neutral` (как «разблокирован»).

**Ключевые решения:**
- **Продажа пакетов УБРАНА из Клиентов → только в Кассе** (одно действие — одно место). В таблице пакет лишь *показывается* (колонка «Сейчас/пакет»), продать нельзя.
- **Историю ужать** (исходное требование юзера): в drawer только последние 4-6, полная — по кнопке/модалке. Корень проблемы «пустой широкий центр»: у клиента мало данных; таблица заполняет ширину реальными данными, drawer компактен.
- Именование по смыслу: «Потрачено», не «Оборот» (#27).

**ОТКРЫТЫЙ пункт на доводку:** **стиль строк таблицы** пользователю не нравится (высоко/воздушно 58px + большой зазор имя↔числа = «спредшит»). Договорились: правится ПОСТФАКТУМ (косметика CSS одного компонента, не трогает данные/логику/структуру) — на живом React. Не потерять.

**Доступность данных для колонок (разведка кода 2026-07):**
- **Баланс, Долг** — ✅ есть в `PlayerSearchResultDto` (walletBalanceMinorUnits, debtBalanceMinorUnits).
- **«Сейчас играет на PC»** — ✅ чистый фронт: `sessions.timeline(branchId)` уже грузится branch-wide, надо матчить по `playerAccountId` для ВСЕХ строк (сейчас `buildClientContext` делает это для одного). НЕ джойнить по floor-map (там только playerDisplayName-строка, коллизии).
- **«Новый» тег** — 🟡 дёшево: `createdAtUtc` есть в `PlayerAccountDto`, нет в `PlayerSearchResultDto` — прокинуть поле в DTO списка, фронт решает по threshold.
- **Банк времени пакета (минуты в строке)** — 🟡 в списке только `activePackageCount` (число), минуты (`remainingIncludedSeconds`+`remainingBonusSeconds`) есть только в `getPlayerPackages(id)` (per-client). Нужен агрегат минут в списке ИЛИ N+1 (не масштаб).
- **Последний визит** — 🟡 нового поля нет; считать на бэке (`lastActivityAtUtc` = последняя сессия/ledger).
- **Потрачено (lifetime spend)** — 🔴 агрегата нет НИГДЕ; честно на фронте нельзя (ledger пагинирован). Нужен серверный агрегат по ledger (gameplay_charge+package_purchase+postpaid_debt − reversals — семантику определить). enum типов: top_up, gameplay_charge, package_purchase, package_consumption, bonus_grant/consumption, refund, manual_correction, postpaid_debt, debt_payment, wallet_payment, reversal, cashback.

**Механика ДОЛГА (факты из кода, для продуктового решения):** wallet и debt — ДВА РАЗДЕЛЬНЫХ виртуальных счёта в одной ledger-таблице (`LedgerAccountTypeNames.Wallet`/`Debt`), баланс = SUM(amount) по accountType. Могут сосуществовать (баланс 450 И долг 280 одновременно). **topUp НЕ гасит долг автоматически** — payDebt отдельное явное действие (для кассы/аудита разные деньги). Долг возникает ТОЛЬКО через postpaid_debt-режим (играть в кредит) или ручную коррекцию; в prepaid_wallet нехватка баланса НЕ создаёт долг (сессию просто нельзя начать). Долг хранится положительным числом. **Убрать долг из МОДЕЛИ нельзя дёшево** = переписать всю money-зону (биллинг/проектор/API, под guard'ами) + сломать постоплату. Можно только из UI (показывать условно).

**VIP:** базы НЕТ вообще (ни флага, ни tier, ни лояльности per-client). Есть только org-wide кэшбэк-процент (`OrganizationLoyaltySettingsEntity`) + per-client `PostpaidCreditLimitMinorUnits` (кредитный лимит, не статус). VIP строить с нуля.

**РАЗВИЛКИ РЕШЕНЫ (юзер, 2026-07-06):**
- **Долг** — оставляем КАК ЕСТЬ (раздельный счёт, показываем условно когда ≠0). Не сливаем, не переименовываем. 0 бэкенда.
- **Потрачено** — ВЫКИНУТО (колонки нет). Дорогой агрегат ledger не нужен.
- **VIP** — НЕ делаем в этом редизайне. Переросло в отдельный эпик «система кастомных статусов клиентов» → [[operator-client-statuses-epic]], делается ПОСЛЕ. В таблице временного `isVip` НЕ городить (техдолг). Теги в таблице пока только **Новый** и **Неактивен**.

**ФИНАЛЬНЫЙ состав таблицы:** Клиент (аватар/имя/телефон + теги Новый/Неактивен) · Баланс · Долг (условно) · Сейчас/пакет · Визит. (Убрано против mock-v7: колонка Потрачено, тег VIP.)

**Бэкенд для v7 (минимальный, безопасный):**
- `createdAtUtc` → добавить в `PlayerSearchResultDto` (тег «Новый», threshold на фронте). Дёшево.
- `lastActivityAtUtc` → добавить в `PlayerSearchResultDto` (колонка «Визит», серверный расчёт последней сессии/ledger). Средне.
- «Сейчас/пакет»: играет на PC = фронт (`sessions.timeline` join по playerAccountId для всех строк); активный пакет когда не играет = нужны имя+остаток минут в списке (сейчас только `activePackageCount`) — решить в спеке: обогатить DTO ИЛИ упростить колонку до счётчика пакетов.
- НЕ нужно: агрегат трат, isVip.
