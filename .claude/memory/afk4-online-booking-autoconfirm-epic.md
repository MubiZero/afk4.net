**Канонический док в репо (в гите, для команды):** `docs/superpowers/specs/2026-06-18-online-booking-autoconfirm-hold.md`. Эта память — быстрый указатель; источник правды там.

**Идея (владелец, 2026-06-18):** онлайн-бронь должна ставиться клиентом из мобильного приложения сразу, без подтверждения оператором — «свободно время → бронируй, если есть баланс». Меньше работы оператору, больше удобства юзеру.

**Что УЖЕ есть на бэке** (`src/AFK4.Platform.Api/Reservations/EfReservationService.cs`):
- `CreateOnlineAsync` — самостоятельная онлайн-бронь игроком уже реализована; игрок выбирает место (SeatId обязателен).
- **Проверка занятости уже работает**: `FindConflictAsync` ловит пересечения по месту/времени + `ValidateReservationShapeAsync`. То есть «если слот свободен» — серверный инвариант уже есть.
- НО создаётся в статусе `pending` (ждёт оператора) — строка с комментарием «Online source → Pending state».
- Баланс НИГДЕ не проверяется.

**Slice 1 — СДЕЛАНО (2026-06-18, commit 81de0123):** `CreateOnlineAsync` авто-подтверждает онлайн-бронь (`confirmed` вместо `pending`), **если кошелёк положительный и нет долга** (`ShouldAutoConfirmOnlineAsync` через `LedgerBalanceProjector.GetWalletSummaryAsync`). Иначе остаётся `pending`. Read-only по деньгам, 3 теста (`EfReservationOnlineAutoConfirmTests`). Балансовый гейт здесь — «есть ли деньги вообще» (>0, без долга), НЕ «≥ ориентир. стоимости».

**Slice 2 — НЕ СДЕЛАНО (холд денег, БЭКЛОГ, кросс-модульный, ГЕЙТ НА МОБИЛКУ). Решения владельца зафиксированы (2026-06-18):**
- **Сумма холда (Q1):** считать от **billing-выбора игрока в приложении** — игрок сам выбирает тариф (стандартный/ночной/…) ИЛИ пакет времени (напр. пакет на 3 ч) + ПК + время; холд = выбранный тариф × длительность (или резерв пакет-времени). НЕ фикс-депозит, НЕ branch-default-тариф — точная сумма из выбора. ⇒ **бронь должна нести billing-выбор** (зеркало старта сессии: tariffRuleVersionId/billingMode/tariffVersionId/playerPackageId), а заполняет его мобильный self-service UI.
- **No-show (Q2):** авто-возврат холда **через 15 мин после старта** брони, если игрока не посадили (фоновый hosted service, образец `AutoProtectionHostedService`); бронь → no-show.
- **Недостаток баланса (Q3):** **отклонять бронь** (hard reject), а не pending. «Бронь только с деньгами».
- **Механика холда:** ledger-запись (AccountType=wallet, negative, EntryType="reservation_hold"), привязка к брони (нужен ReservationId на LedgerEntryEntity ИЛИ через Reason; миграция); релиз через `ReversesLedgerEntryId`; на посадке холд → предоплата сессии (интеграция с session billing).
- **БЛОКЕР:** холд завязан на мобильный флоу бронирования (пикер тарифа/пакета) — без него бронь не несёт billing-выбора, оценивать нечего. ⇒ делать **вместе с мобильным self-service booking** (или мобильный флоу первым), НЕ на операторе вслепую. Связано с [[afk4-customer-shell-pivot]].

**Влияние на экран оператора:** лейн «онлайн-заявки без места» (online+pending+без места) сжимается — авто-подтверждённые лягут блоками `confirmed` на таймлайн. Лейн оставлен как запасной клапан.

**Статус: Slice 1 в main-ветке фичи; Slice 2 (холд) — БЭКЛОГ, ждёт продуктовых решений.** Связано с [[afk4-customer-shell-pivot]] (мобильный self-service) и reservations API.
