Эпик «реворк склада оператора»: склад вынесен из вкладки Кассы в **отдельный корневой раздел рейла «Склад»** (`WorkspaceId 'stock'`, виден при `inventory.view` | `inventory.stock.manage`). Раздел = 4 вкладки (наполняются по слайсам) + правая «Сводка» (StockWorkspace владеет своим внутренним layout'ом в колонке 2 — 3-я колонка shell НЕ задействована, она бы связала App.tsx с табами Склада).

**Каноны:**
- Спека: `docs/superpowers/specs/2026-06-25-operator-inventory-rework-design.md`
- План S0: `docs/superpowers/plans/2026-06-25-operator-stock-s0-rail-and-levels.md`
- Мокапы (живые, dark-тема оператора): `.superpowers/brainstorm/3236934-1782385059/content/*.html` (stock-shell-v5=Остатки, receiving=Приёмка, journal=Журнал, inventory-count=Инвентаризация, pos-scan=сканер в корзину, product-barcodes=штрихи в Товарах).

**Решения (durable):**
- Себестоимость — **средневзвешенная скользящая** (`PosProductEntity.AvgCostMinorUnits`, пересчёт в `CreateStockMovementAsync` только при `purchase`; первый приход → avg=себест прихода). Стоимость остатка = остаток×avg; маржа=(цена−avg)/цена.
- **Money на проводе:** `price` = nested `MoneyDto` (`readMoney(p,'price')?.minorUnits`), а `avgCostMinorUnits` = ПЛОСКОЕ число (`readNumber`). Не перепутать — на этом был prod-баг (Цена/Маржа пусты), пойман финальным ревью.
- Сканер штрихов — **USB-HID-клавиатура** (печатает цифры+Enter, без API); **несколько штрихов на товар** (коллекция, новая таблица `ProductBarcodeEntity`); пик того же товара = +1 к кол-ву.
- Без справочника поставщиков (текстовое поле на накладной).
- Разведение: `Управление → Товары` = только каталог (имя/цена/категория/порог/штрихи); складские движения/история уезжают в раздел Склад.

**Слайсы (все ЗАКРЫТЫ):** S0 каркас+Остатки v2 (**PR #116**); **S1 Приёмка PR #117**; **S2 Журнал PR #118**; **S3 Штрих-коды PR #120** (`df4401ad`); **S4 Инвентаризация PR #121** (merge `1c91bf4c`). **Эпик «Склад» завершён — следующий зум-аут на разделы рейла Отчёты / Управление.**

**S4 durable (PR #121) — чистый фронт (как S2), БЕЗ миграций/эндпоинтов/контрактов:** `inventoryModel.ts` (зеркало receivingModel): `CountLine.countedText` — сырой текст, пусто = «не пересчитано» (НЕ молчаливо 0/1); `lineDiff`=факт−учёт (null пока не пересчитано); `inventoryTotals` (недостача/излишек в единицах + знаковый `netSumMinorUnits`); `inventoryAdjustments` (только diff≠0, знаковая дельта, себест из avg). **Проведение** = N идемпотентных `createStockMovement(adjustment, quantityDelta=diff, unitCost=avgCost, reason="Инвентаризация")` (тот же паттерн, что приёмка S1) — бэк НЕ пересчитывает avg на `adjustment`, on-hand=SUM(delta); reason обязателен (бэк reject blank), zero-delta reject → pending/diff=0 пропускаются клиентом. **`markPosted`-инвариант:** после успешной строки учётный := факт (diff→0), чтобы ретрай при частичном сбое («Проведено X из Y») НЕ провёл строку дважды. **Сканер в инвентаризации = найти+подсветить+сфокусировать строку, НЕ +1** (спека §2 ограничивает «+1» приёмкой/POS; количество вводится вручную); скан снимает фильтр поиска, чтобы строка точно была видна. Журнал НЕ менялся: инвент-коррекции = чип «Коррекция» + reason-текст после SKU; отрицат. инвент-коррекция в `summarize` журнала суммируется как «Списано» (приемлемо). **Грабли tsc:** TS не связывает `counted===null` с `diff!==null` (разные вызовы `lineCounted`/`lineDiff`) → сужать через `const pending=diff===null` (aliased-const narrowing TS5); снова урок «зелёный `bun test` ≠ зелёная сборка» ([[frontends-on-bun-test]]). **Epic-уборка (спека §5/§7):** POS-порог `stockOnHand<=2` → per-product `isLowStock(item)` = `source==='backend' && reorderThreshold>0 && stockOnHand<=reorderThreshold` (0 = без алертинга); чистая экспортируемая функция (юнит-тест отдельным `.test.ts` — backend-mode мок POS хрупок: компонент грузит игроков/смену). **POST-merge:** миграций нет → Coolify staging НЕ блокируется.

**S3 durable (PR #120):** новая таблица `product_barcodes` (`ProductBarcodeEntity`: голый `Guid ProductId`+индексы, БЕЗ навигации/каскада — доминирующий паттерн репо; колонки PascalCase, snake_case только у `ToTable`). **Lookup штриха — КЛИЕНТСКИЙ:** штрихи едут инлайн в каталоге (`PosProductDto.Barcodes: string[]`, primary-first, грузятся одним словарём как `stockOnHand`), `matchByBarcode` матчит по загруженному каталогу — мгновенно, без round-trip; **серверного by-barcode эндпоинта НЕТ намеренно** (YAGNI — каталог всегда загружен и в POS, и в Приёмке, единственных местах скана; откатываемо). **Уникальность кода `(Org,Branch,Code)` enforce в СЕРВИСЕ** (InMemory-провайдер тестов НЕ enforce'ит DB-индекс) + индекс backstop. Инвариант primary: первый→primary, новый primary демотит, удаление primary→промоут старейшего по CreatedAtUtc. Permission: CRUD штрихов=`inventory.stock.manage`, чтение каталога=`inventory.view`; IDOR-guard на POST (`request.OrganizationId==StaffContext`). **`useBarcodeScanner`** = чистый редьюсер `feedScanner(state,key,timeMs,opts)→{state,scanned?,capture}` (детерминизм через инжект `timeMs` — фейк-таймеров в bun-стеке НЕТ) + тонкий хук (capture-фаза keydown + preventDefault, чтобы цифры не утекали в поля); `MIN_CODE_LENGTH=3`, `MAX_INTER_KEY_MS=50`; **звать БЕЗ inline-opts** (3-й аргумент-объект пере-подписывает листенер каждый рендер). POS-сканер gated на `payOpen`. Уборка: дедуп POS-корзины починен name→productId; поле «Порог заказа» перенесено в карточку товара (закрыт долг спеки §3 — было в DTO, не в форме). Миграция на Linux: `dotnet build` API ПЕРВЫМ → `dotnet ef migrations add --no-build --output-dir Data/Migrations` (иначе пустая) — сработало. **Pre-existing долг эпика (в бэклог, НЕ S3):** POS-каталог `BackendPosWorkspace` хардкодит порог `stockOnHand<=2` (нарушает спеку §5, S0 убрал только в Складе) + авто-кладёт первый товар каталога в чек при backend-загрузке (странный UX).
**POST-merge:** миграция трогает `Data/Migrations/**` → блокирует Coolify Staging Deploy до ручного применения по runbook ([[afk4-env-quirks]]); prod afk4 не задеплоен.

**S2 durable (PR #118):** вкладка «Журнал» (read-only, `viewInventory|manageInventoryStock`) — лента движений, фильтр по типу/поиск, период справа (Сегодня/7дней/Все, дефолт Все), день-группы, итоги, экспорт CSV. Чистая логика в `stock/journalModel.ts` (map/filter/period/group/summary/buildCsv; **детерминизм — `nowMs` параметром, период/группы по UTC**, не `Date.now()` внутри pure). Бэк: `StockMovementDto.CreatedByDisplayName` резолвит сервер в `GetStockMovementsAsync` (справочник `/staff` закрыт правом `ManageBranchStaff` — оператор не достанет → серверный резолв обходит permission; один запрос, org-guard). Период фильтруется КЛИЕНТОМ на окне ≤200 (эндпоинт даты игнорит, `Take(Math.Min(limit,200))`) — кап показан честной нотой. CSV — машинно-читаемый (`minor/100` без NBSP/символа валюты, ISO-дата, UTF-8 BOM для кириллицы в Excel), НЕ через `formatMinorUnits`. Типы-фильтры = реальные `movementType` (мокапный сплит Списания/Корректировки не подделан — оба `adjustment`). Уборка: история движений убрана из `Управление→Товары` (форма записи оставлена до S4), сироты `op.settings.stock.history.*`+`reasonFallback` вычищены. Грабли: финал гейт пропустил красный tg-guard в пакете `packages/i18n` (см. [[frontends-on-bun-test]]).

**S1 durable (PR #117):** вкладка «Приёмка» (видна при `manageInventoryStock`); чистая логика накладной в `stock/receivingModel.ts` (себестоимость строки = сырой `unitCostText`, парс в minor по требованию — иначе инпут переформатируется на keystroke); проведение = N **последовательных** идемпотентных `createStockMovement(purchase)` (свежий ключ на POST, кнопка дизейбл на время; частичный сбой → `remaining.shift()` по успеху оставляет непроведённые строки, «Проведено X из N»); себест преподставлена из `avgCostMinorUnits`. Остатки: ＋→Приёмка с товаром (preload через поднятый `activeTab`+`receivePreload` в `StockWorkspace`, `onConsumePreload` одноразово), «Оформить приёмку»→Приёмка, − → `WriteOffDialog` (`adjustment` −qty, себест из avg, рефетч через `reloadNonce` в deps useEffect). **Все S0-заглушки ＋/−/«Оформить» убраны**, сирота-ключ `orderBtnSoon` вычищен. Сканер НЕ здесь (S3) — полоса = честный ручной поиск, без фейкового «сканер активен»; `addOrAccumulate` = шов под сканер. Грабли: `tsc -b` тайпчекает тесты → типизировать bun-моки (см. [[frontends-on-bun-test]]); финальный гейт обязан включать `bun run build`, не только `bun test`.

**Бэклог (отложено):** **POS авто-кладёт первый товар каталога в чек при backend-загрузке** (`BackendPosWorkspace`, странный UX — единственный остаток POS-долга, порог `<=2` ФИКНУТ в S4); разбивка Сводки по категориям (нужно имя категории в каталог-DTO); отрицательная маржа рендерится emerald-цветом; видимость экономич. колонок по роли; `.cash-stock-*` имена классов в `/stock/` (техдолг); **S1-минорки в долг** — приёмка с нулевой/непроставленной себестоимостью проходит молча (нет UX-валидации «себест не указана»); пустое поле кол-ва молча откатывается к 1.
