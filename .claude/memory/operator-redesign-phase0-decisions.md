Полный овэрхол Operator.App разбит на **«Этапы»**: 0 Фундамент → 1 Карта → 2 Касса → 3 Клиенты → 4 Брони → 5 Отчёты → 6 Управление (каждый: спек→план→PR).

**Сделано:** Этап 0 «Фундамент» ЗАКРЫТ; Этап 1 «Карта» ЗАКРЫТ (карта = только грид, см. [[afk4-operator-map-epic]]); Этап 4 «Брони» ЗАКРЫТ (PR #99, см. [[afk4-online-booking-autoconfirm-epic]]); Этап 3 «Клиенты» ЗАКРЫТ (PR #103–#108, см. [[afk4-operator-clients-epic]]). **Этап 2 «Касса» ЗАКРЫТ: S0 каркас (PR #109) + S1 смена (PR #110) + S2 достройка дыр (PR #111) + S3 слияние POS+Заказы (PR #112, merge `bf3ef2e6`) в main. Впереди по программе: Этап 5 «Отчёты», Этап 6 «Управление».**

**Касса (Этап 2) — состояние:** канон = spec `docs/superpowers/specs/2026-06-24-operator-cash-design.md`. Раздел = единый воркспейс `cash` = шапка-якорь `CashShiftHeader` (статус смены + командная панель Открыть/Внести/Изъять/Закрыть → PanelModal-модалки, оркестрация `CashShiftCommandBar`) + под-вкладки. **S0** (PR #109): каркас, 5 воркспейсов перенесены 1:1. **S1** (PR #110): жизненный цикл смены вынесен из «Платежей» в шапку; вкладка **«Смена»** (`CashShiftWorkspace` = кокпит выручка/сверка/движения/CSV-экспорт/история из `shiftRevenue`); вкладки `payments`+`shifts` слиты в `shift`; `BackendPaymentsWorkspace`+`ShiftsWorkspace` УДАЛЕНЫ; рефреш шапки+вкладки через `shiftNonce`. **S2** (PR #111): вкладка `review` → `journal` **«Журнал кассы»** (`CashJournalWorkspace` = 2 сегмента под правами: **Кассовые операции** = `CashOperationsLedger` поверх `getCashOperationReport` + поиск/сводка/CSV; **Проверка** = `ReviewWorkspace` во встроенном режиме `embedded`); **X-отчёт** = `ShiftReportModal variant='x'` из снимка revenue (кнопка в шапке, gated `isOpen && reports.view`); **Z-сводка** = `variant='z'` после успешного close (снимок выручки + результат close), печать `printShiftReport` (window.open). Билдеры — `cash/shiftReport.ts`. Долг S1 вычищен: −98 `op.payments.*` + мёртвый `op.shell.nav.review`. **S3** (PR #112): вкладки `sales`+`orders` слиты в одну **«Продажи»** = `CashSalesWorkspace` (сегменты `pos`/`orders` под правами, бар скрыт при одном; калька `CashJournalWorkspace`); POS (`BackendPosWorkspace`) и Заказы (`ShopOrdersWorkspace`) получили `embedded`-режим (как `ReviewWorkspace`); `CashTab` сужен до `sales`/`shift`/`journal`; чистка `op.shell.nav.pos`/`shop_orders` → новые `op.cash.sales.*`; S3-долг закрыт (try/catch CSV-экспорта + inline-нотис). **Итоговые вкладки Кассы: `sales`(POS+Заказы)/`shift`/`journal` — 3.** Эпик «Касса» завершён. **Полировка-пасс (PR #114, merge `03ba36ec`):** POS-корзина → «единый чек» (свёрнутый клиент + плоские полосы + один подвал расчёта); общий `PaymentDialog` на расчёт сессии (Карта) и продажу POS; лента заказов = чип «N поз · сумма» + FIFO-скролл; снят молчаливый потолок 5 категорий каталога; уборка (−57 ключей-сирот `op.pos.*`, мёртвый `.pos-quick-*`/`.pos-stock-form` CSS, payment-ключи `op.map.panel.*` → `op.checkout.*`).

**Бэк (готов, money-path не трогаем):** `ShiftEndpoints` (open/current/cash-movements/close — close=полный пересчёт expected vs counted + tolerance + manager sign-off; revenue/current+revenue), `PosEndpoints`, `MoneyActionEndpoints` (refund/correction approval), `ReportEndpoints`+CSV. **Нет на бэке:** X/Z как сущности, инкассация с банком (= cash_out), детализация по номиналам. `shiftRevenue.current` отдаёт shiftId+state+earned+inflow+cash{starting/expected/counted/difference} — хватает шапке и кокпиту.

Durable-факты:
- **Деньги**: `currencySymbol()` — const-мапа в `@afk4/money` (НЕ i18n), TJS→«с.»; единый форматтер.
- **App.test** гонять ОТДЕЛЬНЫМ `bun test`-вызовом (утечка `mock.module` process-wide) — НЕ сливать обратно в общий прогон (см. [[frontends-on-bun-test]]).
- Design-system = канон существующих токенов + примитивы Toast/Skeleton/EmptyState; извлекать по ходу.
- Процессный урок: не доводить пиксели в HTML-мокапах.
- **Деньги парсинг (S1):** `parseMoneyInputMinorUnits` отвергает 0 (строго >0) — для счёта/факта где 0 валиден (закрытие смены с пустой кассой) брать `parseNonNegativeMoneyInputMinorUnits`. `formatMoney(TJS)` рендерит целые БЕЗ дробной части: `115 с.` (не `115,00 TJS`) — тесты ассертить под реальный вывод; `formatMoney(null)` → `0 с.` (гардить null→placeholder в денежных строках, иначе ложно «сошлось»).
- **App.test флак-урок (S1):** действие, дёргающее рефреш через nonce-бамп (`onShiftChanged → shiftNonce++ → перезапуск load-эффектов`), порождает «вторую волну» фетчей; тест обязан её дренировать (await пост-действенного рефетча, напр. счётчик фетчей `>= before+2`), иначе повисшая async утекает в соседние тесты → перемежающийся флак (таймауты, «Unhandled: Unable to find heading»). Контроллерская многопрогонная верификация (App.test 6×) ловит то, что одиночный прогон имплементера пропускает.
- **Тест-паттерн боевого клиента:** компоненты, строящие `createAuthenticatedOperatorClients`, должны принимать инъект-клиент и строить боевой только при `backend && !injected` (фейк-backend в тестах с `config:'x'` бросает «Invalid URL» в `PlatformApiClient` на init); либо строить лениво в обработчике, не на рендере.
- **Деньги формат (уточнение S2):** `formatMoney(123000 minor)` = **«1 230 с.»** — разделитель тысяч = **NBSP (U+00A0)**, не обычный пробел; отрицательное = **«-50 с.»** (ASCII-минус). В тестах ассертить `toContain('230 с.')`/regex под реальный вывод, НЕ точное `getByText('123 с.')`. Поля сверки (counted/difference) гардить `=== null → t('op.cash.shift.notClosed')`, иначе `formatMoney(null)` даёт ложное «0 с.».
- **Встраивание воркспейса в сегмент (S2):** `ReviewWorkspace` получил флаг `embedded` — корень `<section className="review-embed">` вместо `<main className="workspace-screen …">` + скрыт собственный `screen-head` (заголовок даёт хост-вкладка); вся логика byte-identical. Паттерн для повторного использования воркспейса как сегмента без тройного вложения `<main>`.
- **X/Z-отчёты (S2):** X = снимок открытой смены (`isOpen ⟹ revenue≠null` инвариант, кнопка gated этим + revenue≠null); Z строится снимком на момент `close` → стабилен к пост-close `onShiftChanged → revenue=null`. close-Z требует того же дренажа второй волны рефетчей, что и прочие действия. `printShiftReport` = window.open-guarded (false в happy-dom), не бросает.
- **Слияние POS+Заказы (S3) = презентационное, НЕ сшивка данных:** заказ (`ShopOrderDto`) и продажа (`PosSaleDto`) в модели НЕ связаны — заказ оформляет игрок из Player Shell, касса лишь меняет статус (accept→deliver→cancel) БЕЗ оплаты; путь «заказ→продажа в POS» = новая бэк-фича, вне скоупа эпика. Поэтому «слияние» = два независимых сегмента в одной вкладке (`CashSalesWorkspace`), а не общий flow. Развилка из spec (переключатель vs боковая панель) решена в пользу сегментов: боковой рейл заказов рядом с плотным 6-панельным POS зажимает контент И ложно намекает на связь, которой нет.
- **Паттерн «воркспейс как сегмент» (3-е применение, канон):** `embedded?: boolean` → корень `<section className="X-embed">` вместо `<main className="workspace-screen X-screen">` + своя `screen-head` под `{!embedded && (...)}`; тело в `body`-фрагменте, либо динамический корень `const Root = embedded ? 'section' : 'main'` (TS принимает `'section'|'main'` как валидные `JSX.IntrinsicElements`) — последнее дёшево для монолитов (правка ~6 строк, не оборачивать сотни строк). Применён к `ReviewWorkspace` (S2), `BackendPosWorkspace`+`ShopOrdersWorkspace` (S3). Доступ-гейтинг сегментов без регрессии: вкладка-хост видна по `hasAnyPermission(суперсет)`, `createPosSale ∈ canPos И canOrders` ⟹ orders-only-состояние недостижимо, default-сегмент всегда валиден.
- **POS-тест (S3):** `BackendPosWorkspace` (1111 строк) получил ПЕРВЫЙ собственный тест (fixture-режим `backend=null` + проверка embedded). До S3 — только косвенное покрытие через App.test. Предсущ. мёртвый тернарник `source` в `projectPosProduct` (`… ? 'backend' : 'backend'`) вычищен post-S3 (PR #113) вместе с осиротевшим параметром `currencyCode`.
- **Общий `PaymentDialog` (PR #114):** окно приёма оплаты — ОДНО на расчёт сессии (Карта) и продажу POS. Вынесено **телом** (`<>…</>` без `PanelModal`), модалку-обёртку держит вызывающая сторона — иначе переход loading→ready в сессионном чекауте менял тип верхнего компонента (`PanelModal`→`PaymentDialog`) и ремаунтил диалог, отрывая `within(dialog)`-узел тестов. Пропсы счёта (`lines`/`grandTotal`/`walletBalance`/`allowSplit`) → session-agnostic; POS = `allowSplit=false` (бэк `paySaleManual` одно-методный, сплит = бэк-фича). Чистый движок — `checkoutState.ts`.
- **Янтарь только для предупреждений (PR #114):** `--warning` (amber) — НЕ деньги; тоталайзеры/В кассе/Выручка = `--text-strong` (белый), emerald = GO/активное. Amber на сумме читается как «ошибка». Класс правок (#33): применять ко ВСЕМ денежным числам, не к одному экрану.
- **Уборка как закрывающий пасс (PR #114):** после крупной переделки выметать хвост — i18n-сироты (проверять репо-wide + динамические `t(\`…\`)` перед сносом; синхронно чистить запись в `TG_IDENTICAL_TO_RU_ALLOWED`), мёртвый CSS (детектить токены classNme через grep по tsx, НЕ только `className=` — рвётся на template-literal), молчаливые потолки коллекций (`slice(0,5)` категорий = тихая отсечка, #28/#34). Иначе diff выглядит готовым, CI зелёный, а внутри мёртвый груз.
