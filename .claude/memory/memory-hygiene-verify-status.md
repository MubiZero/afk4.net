Статусные пометки в памяти («не смержено», «в работе», «готово, ready-to-merge», «НЕ начат»)
**протухают молча** и к моменту чтения чаще неверны, чем верны.

**Why:** 2026-08-10 ревизия нашла, что почти все такие пометки в блоке Оператора врали — работа
давно в main, ветки удалены. На этой основе я дважды подряд посоветовал пользователю неверный
следующий шаг: «смержить две готовые ветки» (одна была влита ещё в июле, вторая протухла) и
«взять рефокус Клуб+Платежи» (реализован целиком). Причина системная: запись фиксирует момент
написания, а редактируют её только когда случайно вспомнят.

**How to apply:**

1. **Перед тем как опереться на статус — проверь его командой, а не памятью.** Дёшево и быстро:
   - `git merge-base --is-ancestor <sha> main` — работа в main или нет;
   - `git branch -a --contains <sha>` — пусто значит коммит вне всех веток (висячий);
   - существование файла/символа по описанному пути.
2. **Зум-аут «что делать дальше» всегда начинать с этой проверки**, а не с чтения индекса.
   Совет о следующем шаге — самое дорогое место, где память может соврать.
3. **Записывая статус, пиши проверяемый якорь и дату:** SHA, имя ветки, путь к файлу,
   «проверено ГГГГ-ММ-ДД». Без якоря запись нечем перепроверить.
4. **Файл памяти о работе НЕЛЬЗЯ оставлять только в feature-ветке.** Память версионируется в гите
   ([[memory-in-git-setup]]); файл, добавленный коммитом непомерженной ветки, исчезает вместе с
   ней, а индекс остаётся ссылаться в пустоту (так пропал
   [[operator-pos-receipts-panel]] на полтора месяца). Коммитить память в main отдельным коммитом.
5. **Периодическая ревизия дешева, делай её при любом сомнении:** битые ссылки индекса —
   `grep -o '](\([^)]*\.md\))' MEMORY.md`, каждый файл на месте; все SHA из памяти — прогнать
   проверкой ancestor'а; все ветки — какие ещё живы вне main.
6. **Переименование продукта убивает пути в старых записях.** Оператор `AFK4.Operator.App.Web` →
   `AFK4.OrganizationAdmin.Web` + WPF-хост `.App` (коммит `a6257364`), панель платформы
   `AFK4.Platform.Web` → `AFK4.PlatformControl.Web` (`b15c5861`), env-префикс `AFK4_OPERATOR_*` →
   `AFK4_ORGANIZATION_ADMIN_*`
7. **Спеки и планы закрытых работ удаляются из репозитория** (уборка `a8e0042b` и подобные). Ссылка
   на `docs/superpowers/{specs,plans}/…` в старой записи — не ошибка записи, а признак, что работа
   давно закрыта; искать документ в истории гита, а не считать память сломанной.: любая запись старше этого места указывает
   в никуда, даже если по сути верна.
