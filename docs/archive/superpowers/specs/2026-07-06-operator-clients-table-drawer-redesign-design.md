# Оператор «Клиенты» — пересборка на таблицу + drawer

**Дата:** 2026-07-06
**Статус:** дизайн согласован (mock-v7 + развилки), ждёт ревью → план
**Заменяет:** `2026-07-03-operator-clients-center-column-redesign-design.md` (тот подход — список+карточка-воркспейс — забракован пользователем целиком)

## Цель

Переписать раздел «Клиенты» оператор-аппа с раскладки «узкий список + широкая карточка-воркспейс» на **широкую таблицу клиентов + узкий drawer выбранного клиента** — родной паттерн приложения (Карта/Брони: широкая сетка + узкий drawer). Это структурно решает корневую проблему прошлых итераций: у одного клиента мало данных, поэтому широкая правая карточка всегда была полупустой. Таблица заполняет ширину реальными данными по многим клиентам, drawer держит деньги компактно.

## Предыстория (что привело к решению)

Прошлый редизайн (список+карточка) прошёл полный цикл и был отвергнут («отвратительно»). Провели серию статичных HTML-макетов на реальных токенах проекта (v1–v7, отдавались по локальному URL). Сошлись на **mock-v7**. Ключевые повороты по ходу: продажу пакетов убрать (дублирует Кассу); история не должна доминировать; корень «пустого центра» — не оформление, а что показывать и какой ширины.

## Архитектура

Раздел = компактная шапка-якорь (метрики Клиентов/Депозиты/Долги) + основная область из двух зон:
- **Таблица клиентов** (`minmax(0,1fr)`) — на всю ширину, скроллится внутри.
- **Drawer** (`~372px`) — узкая правая панель выбранного клиента; при отсутствии выбора таблица занимает всю ширину, drawer показывает empty-state.

Визуальный язык: один приподнятый контейнер на зону (`--shadow-card` + `--border-soft` + `--surface-elevated`), внутри — хэйрлайны, без card-in-card. Атомы `.ui-*` (btn/chip/card/field/money/ledger), пилюли `.status-pill` (реюз из `06-map-grid.css`).

## Состав таблицы (финальный)

Колонки:
1. **Клиент** — аватар (инициалы) + имя + телефон; inline-теги **Новый** и **Неактивен**.
2. **Баланс** — `walletBalanceMinorUnits`, моно, tabular-nums.
3. **Долг** — `debtBalanceMinorUnits`; показывается только когда ≠ 0; строка с долгом получает левый красный кант (`--edge: var(--danger)`).
4. **Сейчас / пакет** — составная: если клиент играет → `PC-01 · до 11:20` (зелёным); иначе если есть активный пакет → `Ночной 5ч · 150 мин` (банк времени); иначе `—`.
5. **Визит** — относительная давность последней активности (`сейчас / вчера / 3 дня / 2 нед.`).

Убрано против mock-v7: колонка **Потрачено** (дорогой агрегат, не нужен), тег **VIP** (переросло в отдельный эпик).

Строка кликабельна, выделение = левый акцентный кант + `--surface-hover`. Неактивные приглушены. Toolbar над таблицей: поиск + сегмент-чипы (Все/Есть долг/Неактивные) + «Новый клиент».

## Состав drawer (выбранный клиент)

Сверху вниз, компактно:
- **Шапка:** аватар + имя + телефон; иконки «…» (меню) и «закрыть».
- **Контекст-пилюли** (`.status-pill`): «Играет · PC-01 · до 11:20» (`ok`, зелёная), «Бронь 19:00 · VIP-03» (`neutral`). Только когда есть.
- **Деньги:** баланс (герой, моно) → долг (callout, только при ≠0) → **быстрое пополнение** (пресеты +100/+200/+500 + своя сумма + одна primary «Пополнить») → «Списать долг N» тихой ссылкой (только при долге).
- **Последние операции:** 4–6 записей (`.ui-ledger-row` compact) + ссылка «вся история →» (полный журнал — модалка/разворот).
- **Меню «…»:** Создать бронь · Изменить профиль · Задать ПИН · Ручная корректировка · Деактивировать.

## Ключевые решения

- **Продажа пакетов — только в Кассе.** Из Клиентов удаляется inline-покупка (`PackagesSection` buy-форма). В таблице пакет лишь показывается.
- **Долг — как есть.** Wallet и debt — раздельные счета (подтверждено кодом: `LedgerAccountTypeNames.Wallet`/`Debt`, независимые SUM; topUp не гасит долг; долг только через postpaid_debt/коррекцию). Не сливаем, не переименовываем. Показываем условно (когда ≠0), поэтому предоплатные клубы его не видят.
- **Потрачено — не делаем.** Агрегата нет нигде, честный расчёт требует прохода по всей пагинированной истории. Снято.
- **VIP/статусы — отдельный эпик после.** Не булев флаг, а система кастомных статусов с преференциями (см. память `operator-client-statuses-epic`). Временный `isVip` не вводим (техдолг). В таблице пока только Новый/Неактивен.
- **Именование по смыслу** (#27): «Потрачено» а не «Оборот» (снято, но принцип держим для будущих колонок).

## Данные и бэкенд

Что уже есть в `PlayerSearchResultDto`: `playerAccountId, displayName, phoneNumber, walletBalanceMinorUnits, debtBalanceMinorUnits, activePackageCount, isActive`.

Чистый фронт:
- **«Сейчас играет на PC»** для всех строк — `sessions.timeline(branchId)` уже грузится branch-wide; матчить по `playerAccountId` для каждой строки (сейчас `buildClientContext` делает это для одного). НЕ джойнить по floor-map (там только строка-имя, коллизии).

Требует бэкенда (расширение проекции operator-search, не money-write):
- **`createdAtUtc`** в `PlayerSearchResultDto` — поле уже есть в `PlayerAccountDto`, прокинуть в список. Тег «Новый» (threshold на фронте, напр. < 7 дней). Дёшево.
- **`lastActivityAtUtc`** в `PlayerSearchResultDto` — серверный расчёт по последней сессии клиента (семантика «визита»). Колонка «Визит». Средне (подзапрос к сессиям).
- **Активный пакет в списке** (для «Сейчас/пакет» когда не играет): нужны имя + остаток минут. Сейчас только `activePackageCount`. **Решение (рекомендуемое):** обогатить DTO полями активного пакета с максимальным остатком (`activePackageName`, `activePackageRemainingMinutes`) — оператору полезно видеть банк времени. **Альтернатива (дешевле):** оставить только счётчик, колонка показывает «2 пакета». Рекомендую обогащение.

НЕ нужно: агрегат трат, isVip, движок статусов.

Overview-метрики шапки (Клиентов/Депозиты/Долги) — считаются на фронте по загруженной странице (как сейчас, `buildClientOverview`); семантику не меняем.

## Компоненты (судьба)

- **Заменяются:** `ClientList.tsx` → `ClientsTable`; `ClientDetail.tsx` + `WalletZone.tsx` → `ClientDrawer` (+ пресеты пополнения).
- **Удаляется:** inline-покупка в `PackagesSection.tsx` (список активных пакетов может остаться read-only виджетом в drawer или свернуться в колонку).

- **Остаются ~как есть:** модалки (NewClient/EditProfile/Correction/PayDebt/Pin/Refund/ActiveStateConfirm), `ClientActionsMenu` (+ пункты Бронь/Коррекция), `LedgerRow` (уже есть `compact`).

## Открытые пункты (не блокируют план)

1. **Стиль строк таблицы** — пользователю не нравился вид строк в макете (высоко/воздушно + большой зазор имя↔числа). Договорено: доводится ПОСТФАКТУМ на живом React (косметика CSS одного компонента, не трогает данные/логику/структуру).
2. **«Сейчас/пакет» когда не играет** — обогащать DTO активным пакетом (рекоменд.) vs счётчик пакетов (дешевле). Финализировать при ревью спеки/плане.
3. **«Вся история»** — модалка поверх drawer vs отдельный разворот. Решить в плане.

## Объём (честно)

Заметная пересборка players-экрана: замена 3 крупных компонентов, удаление продажи пакетов, ~3 новых поля в бэкенд-DTO + их расчёт, переписка значительной части тестов раздела. Не мелкая правка. Реализация — через subagent-driven-development (фрешный субагент на задачу + ревью).
