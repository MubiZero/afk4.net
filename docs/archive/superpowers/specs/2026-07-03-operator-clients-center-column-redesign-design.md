# Operator «Клиенты» — редизайн центральной колонки (карточка-воркспейс)

**Статус:** одобрено (брейншторм, 2026-07-03).
**Связанные:** [`2026-06-22-operator-clients-overhaul-design.md`](2026-06-22-operator-clients-overhaul-design.md) (исходный overhaul, master-detail), эпик [`2026-07-01-operator-ui-kit-design.md`](2026-07-01-operator-ui-kit-design.md) (атомы `.ui-*`). Раздел «Клиенты» уже на общих атомах (S1).

## 1. Проблема

На широком экране (≥1280px) раздел делит ширину так:
`список 320px | карточка minmax(480,680) | рейл «История» 1fr`.

**Самую широкую колонку получает самый «жидкий» контент.** Строка истории — это
`время · тип · сумма`, ей хватает ~360px, а она растянута на ~40% экрана → огромные дыры между
описанием и суммой (см. скриншоты). Карточка, где идёт вся реальная работа (баланс, долг,
пополнение, пакеты), зажата потолком 680px. Внутри карточка ещё и **вкладочная** (Кошелёк /
Пакеты / [История]) — пакеты и действия не видны одновременно, история дублируется между рейлом,
вкладкой и мини-лентой кошелька.

Это не косметика: перекос по ширине и вкладочность — структурная проблема раскладки.

## 2. Решение (одна фраза)

Убрать отдельный правый рейл. Карточка занимает **всю** оставшуюся ширину и внутри становится
**tabless-воркспейсом** из трёх зон сверху вниз: **личность → деньги+действия → низ в две колонки
Пакеты | История**. История переезжает внутрь карточки правой колонкой и ужимается до своей
плотности.

Итоговая раскладка раздела: `список 300px | карточка (весь остаток)`. Третьей колонки нет.

## 3. Раскладка карточки (`ClientDetail`)

Карточка — вертикальный стек с внутренней прокруткой (`.clients-detail-panel`), зоны:

### 3.1 Шапка-личность (как сейчас, сохраняется)
Аватар-инициалы · имя (крупно) · телефон · статус-метка (для inactive) · справа кнопка **Бронь** +
меню `⋯` (`ClientActionsMenu`: Редактировать профиль / Установить PIN / Активировать-Деактивировать).
Под шапкой — баннер деактивации (для inactive) и `ClientContextStrip` («играет на РС-XX · ближайшая
бронь») — оба без изменений.

### 3.2 Зона денег + действий (ядро редизайна) — новый компонент `WalletZone`
Заменяет вкладку «Кошелёк». Ряд:

- Плитка **Баланс** (крупная сумма, `<Money>` mono).
- Плитка **Долг** (крупная сумма). Красный акцент (`--danger-soft-*`) **только когда долг > 0**;
  при нулевом долге — нейтральная плитка.
- Блок **быстрого пополнения inline**: одно поле суммы + кнопка «Пополнить» (primary). Причина
  **необязательна** (сохраняем принятое product-решение: пусто → дефолт при сабмите). Поля причины
  в inline-блоке нет — она уходит в необязательное состояние на submit.

Под рядом — **вторичные действия кнопками**:
- **Погасить долг** (danger-outline) — виден **только при долге > 0**; открывает диалог.
- **Ручная корректировка** (ghost) — виден при праве `canManualCorrect`; открывает существующий
  `CorrectionModal`.

Возврат (`RefundModal`) остаётся построчным в Истории (кнопка на строке `LedgerRow`, как сейчас) —
не выносим в зону денег.

### 3.3 Низ — две колонки `Пакеты | История` (grid 1fr 1fr)

**Пакеты** (`PackagesSection`, без изменений логики): активные пакеты + инлайн-продажа
(селект опции / превью цены-времени / «Хватает депозита» / кнопка «Купить»). Просто переезжает
в свою колонку-панель.

**История** (`HistorySection`, без изменений логики): фильтр-чипы (`Все / Пополнение / Списание /
Пакет / Долг / Возврат`) + лента `LedgerRow` (время · тип · детали · сумма со знаком) + «Показать
ещё». Своя прокрутка. Данные/фильтр/пагинация — из оркестратора, как сейчас.

## 4. Диалог погашения долга — новый `PayDebtModal`

Сейчас погашение долга — всегда развёрнутая inline-форма в `WalletSection`. В новой модели это
кнопка → диалог. Новый компонент `players/PayDebtModal.tsx` по образцу `CorrectionModal`: обёртка
`PanelModal`, два поля (сумма долга + причина, оба уже есть в стейте оркестратора:
`debtPaymentAmount` / `debtPaymentReason`), submit danger-стилем, вызывает
`runClientAction('writeOffDebt', …)`. Причина погашения — как сейчас (плейсхолдер-дефолт).
Никакой новой бизнес-логики: тот же экшен, только в модалке вместо inline.

## 5. Что удаляется / упрощается

- **`ClientLedgerRail.tsx`** — удаляется (рейл больше не нужен; история внутри карточки).
- **`WalletSection.tsx`** — «расщепляется»: действия пополнения → `WalletZone`, форма долга →
  `PayDebtModal`, мини-лента последних операций (`recentEntries` / `showRecent`) → **удаляется**
  (историю всегда показывает колонка 3.3, дублировать незачем).
- **Вкладки** (`ClientDetailTab`, `client-detail-tabs`, `activeTab`, переключение `history↔wallet`)
  — удаляются полностью. Больше нет режима «рейл ↔ вкладка История».
- **`showLedgerRail` / `wideLayout` (min-width:1280)** для раздела — удаляется как драйвер
  раскладки истории. `useMediaQuery` в этом воркспейсе больше не нужен (проверить, что не используется
  для другого).
- Данные журнала грузятся всегда при выбранном клиенте с правом просмотра:
  `ledgerPaneVisible = canViewLedger && selectedClient !== null` (упрощение прежнего условия с
  `showLedgerRail || activeTab==='history'`).

## 6. Адаптив

Одна точка слома у **низа карточки** (`.split`): широко — две колонки рядом; узко (примерно
< 1100px по ширине карточки, финальное значение подобрать на превью) — колонки **в стопку**: сперва
Пакеты, затем История, карточка скроллится целиком. Никаких вкладок на узком (подтверждено).
Список 300px остаётся постоянным на всех ширинах (оператор часто переключает клиентов).

Зона денег (3.2): широко — Баланс | Долг | быстрое-пополнение в ряд; узко — переносится/складывается
(grid с `minmax`), вторичные кнопки заворачиваются (`flex-wrap`).

## 7. Границы (что НЕ трогаем)

- **Бэкенд, money-path, `IsActive`-guard, права, эндпоинты** — ноль изменений. Это чисто
  фронтовая раскладка/презентация.
- **Модалки**: `NewClientModal`, `CorrectionModal`, `RefundModal`, `PinModal`, `EditProfileModal`,
  `ActiveStateConfirmModal` — без изменений (кроме нового `PayDebtModal`).
- **Анти-мигание**: `playersSnapshotCache`, `usePlayersPreload`, snapshot-логика, скелетоны,
  `isLoading`-гейты empty-state — сохраняются как есть (см. [[afk4-operator-clients-epic]]).
- **Атомы**: всё на существующих `.ui-*` / `<Money>` / `<LedgerRow>` / `PanelModal` / `EmptyState` /
  `Skeleton`. Новые CSS-правила — только раскладочные (grid зон), в `12-players.css`; новых атомов не
  вводим.
- **i18n**: используем существующие ключи `op.players.*`; для нового заголовка «быстрое пополнение» и
  заголовка `PayDebtModal` — при необходимости добавить ключи в ru/tg/en (реальный перевод, не копия;
  см. [[tg-i18n-honesty]]).

## 8. Единицы (компоненты)

| Юнит | Роль | Зависит от |
|---|---|---|
| `ClientDetail` (переписать раскладку) | оркестрирует зоны карточки, tabless | WalletZone, PackagesSection, HistorySection, PayDebtModal-триггеры |
| `WalletZone` (новый) | плитки Баланс/Долг + inline-пополнение + вторичные кнопки | `<Money>`, `.ui-*` |
| `PayDebtModal` (новый) | диалог погашения долга | `PanelModal`, `.ui-*` |
| `PackagesSection` (без изменений) | пакеты + продажа | как есть |
| `HistorySection` (без изменений) | журнал + фильтры + пагинация | `LedgerRow` |
| `BackendPlayersWorkspace` (правки) | раскладка `список | карточка`, упрощение ledger-гейта, удаление рейла/вкладок | ClientList, ClientDetail |
| `ClientLedgerRail`, `WalletSection` | **удаляются** | — |

## 9. Критерии готовности

- Раздел: `список 300px | карточка (весь остаток)`; правого рейла нет ни на каких ширинах.
- Карточка tabless: Баланс, Долг, пополнение, Пакеты, История видны **одновременно** на широком окне.
- История ужата до плотности строки (сумма рядом с описанием, без дыр), скроллится сама.
- Быстрое пополнение — одно поле + кнопка, 0 лишних кликов; причина необязательна.
- Погасить долг / Корректировка — кнопки → диалог; Погасить долг виден только при долге.
- Долг-плитка красная только при долге > 0.
- Узкое окно: Пакеты и История в стопку, без вкладок; список постоянен.
- Анти-мигание/preload не сломаны; `bun test` + `bun run build` зелёные; App.test обновлён под
  отсутствие вкладок/рейла.
