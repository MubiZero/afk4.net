# Operator UI-kit — S2 «Склад»: дизайн миграции

**Статус:** одобрено к реализации (полный набор UX-фиксов).
**Родительский эпик:** [`2026-07-01-operator-ui-kit-design.md`](2026-07-01-operator-ui-kit-design.md)
— общий слой атомов `.ui-*` (§5), хелперы `<Money>`/`<LedgerRow>` (§6), дисциплина шкал (§8).
Этот документ — слайс **S2** из §9 родителя («Склад: переезд + полировка», видимые изменения
разрешены).

## 1. Цель

Убрать разрозненность раздела «Склад», переведя его вёрстку на уже готовый общий UI-kit
(атомы `.ui-*` + `<Money>`), и заодно починить конкретные UX-огрехи раскладки. После слайса
«Склад» говорит на том же визуальном языке, что уже нравящиеся Касса/Карта/Брони и
только что сделанные Клиенты (S1). Секционный CSS `22-stock.css` худеет за счёт удаления
дублей, оставшихся после переезда.

Раздел = 4 вкладки (Остатки · Приёмка · Журнал · Инвентаризация) + диалог списания.
Переключение вкладок — `StockWorkspace.tsx` (live keep-alive, не размонтирует).

## 3. Маппинг переезда (класс → атом)

Механическая часть слайса. Во время миграции `22-stock.css` выигрывает каскад (грузится
после `02-ui-kit.css`), поэтому переезд идёт покомпонентно: навесить атом-класс → удалить
локальное правило в `22-stock.css`.

### 3.1 Деньги → `<Money>`
Все семь — моноширинные (`--font-mono` + `tabular-nums`), т.е. 1:1 ложатся на `.ui-money`:

| Локально | Где | На что |
|---|---|---|
| `.money` (себест/цена) | Остатки | `<Money minorUnits currencyCode />` |
| `.valm` (стоимость строки qty×price) | Остатки | `<Money />`; акцент веса — на родителе, не в компоненте |
| `.ctx-big` (большое число сводки) | сводки всех вкладок | значение в слоте `.ui-card--stat` (крупный mono) через `<Money />` |
| `.recv-sum` (сумма строки приёмки) | Приёмка | `<Money />` |
| `.jsum` (сумма движения) | Журнал | `<Money signed />` (модель уже несёт знак движения) |
| `.inv-sum` / `.inv-diff` (разница) | Инвентаризация | `<Money signed />` |

`.money.dim` / `.valm.dim` (пустое/ноль → `--text-quaternary`) — сохранить как поведение:
для нулевых значений оборачивающий узел получает приглушающий класс; сам `<Money>` не
меняем (YAGNI, не плодим проп `dim`).

### 3.2 Кнопки → `.ui-btn`

| Локально | Роль | На что |
|---|---|---|
| `.ctx-btn` (провести приёмку/инвентаризацию, width 100%) | главное действие вкладки | `.ui-btn ui-btn--primary ui-btn--block` |
| `.iact` (+ на строке остатка — приёмка) | иконочное действие | `.ui-btn ui-btn--sm` |
| `.iact.minus` (− на строке — списание) | иконочное деструктивное | `.ui-btn ui-btn--sm ui-btn--danger` |
| `.recv-del` (удалить строку приёмки) | иконочное деструктивное | `.ui-btn ui-btn--sm ui-btn--danger` |
| `.inv-reset` (сброс инвентаризации) | вторичное | `.ui-btn ui-btn--sm ui-btn--ghost` |
| `.seg>button`, `.period>button` | фильтры-тумблеры | **не кнопки** → `.ui-chip--filter` (см. 3.5) |
| `.recv-step` −/+ (степпер) | compound | остаётся локальным (см. §5) |

### 3.3 Карточки/панели → `.ui-card`

| Локально | На что |
|---|---|
| `.cash-stock-levels`, `.stock-receiving`, `.stock-journal`, `.stock-inventory` (крупные панели-контейнеры) | `.ui-card` как поверхность-контейнер |
| `.ctx-card` (карточка сводки, текст) | `.ui-card` |
| `.ctx-card` c большим числом + счётчиками (метрика) | `.ui-card--stat` (см. UX-4) |
| `.cash-stock-row` (строка товара в Остатках) | `.ui-card--edge`; цвет канта `--edge` = статус (см. UX-1); `--interactive` — только если строка кликабельна (открывает действие/деталь) |

### 3.4 Поля → `.ui-field`

| Локально | На что |
|---|---|
| `.recv-field` (поставщик, номер накладной; поля диалога списания) | `.ui-field` (label снаружи + контрол) |
| `.recv-add-field>input` (поиск товара в приёмке) | `.ui-field` |
| `.inv-search` (поиск в инвентаризации) | `.ui-field` |
| `.inv-fact>input` (факт. количество) | `.ui-field>input`; состояние «пусто» (dashed-бордер) — сохранить модификатором `.is-empty` |
| `.recv-cost` (сумма + суффикс валюты) | локальный compound, **визуально выровнен** на токены `.ui-field` (`--surface-sunken`, `--border-default`, `--radius-sm`, focus → `--accent` + `--focus-ring`); суффикс — inline-adornment. Новый атом не заводим (один потребитель) |

### 3.5 Чипы/статусы → `.ui-chip`

| Локально | На что |
|---|---|
| `.stock-status-tag.low` / `.out` (статус остатка) | `.ui-chip--status` `is-warning` / `is-danger` (см. UX-1) |
| `.recv-scanner-badge` («Сканер активен») | `.ui-chip--status is-live` (активный сканер = «живой» индикатор) |
| `.jtype.plus` / `.warn` / `.minus` (тип движения) | `.ui-chip--status` по тону (см. 4) |
| `.barcode-chip` (штрихкод mono + «основной») | `.ui-chip` нейтральный c mono-текстом; «основной» — `.ui-chip--status is-neutral ui-chip--xs` |

### 3.6 Фильтры → `.ui-chip--filter`
Три разных segmented-контрола (`.seg` в Остатках: все/мало/нет; `.period` в Журнале:
сегодня/неделя/всё; фильтр типа движения) → единый ряд `.ui-chip--filter` с `.is-active`,
как история Клиента (S1). Контейнер — flex-ряд с `--space-2` gap; никаких `.seg`/`.period`.

## 4. Тон движения журнала (`.jtype` → `.ui-chip--status`)

Единый семантический маппинг типа движения на тон статус-чипа. Подтверждённые разведкой
типы фильтра журнала: `purchase` / `sale` / `refund` / `adjustment` (списание — не отдельный
enum, а `adjustment`/движение с отрицательной дельтой).

| Тип движения | Смысл | Тон | Класс |
|---|---|---|---|
| `purchase` (приход/приёмка) | +остаток | success | `is-live` |
| `sale` (продажа) | −остаток, штатно | neutral | `is-neutral` |
| `refund` (возврат) | +остаток обратно | booking (accent) | `is-booking` |
| `adjustment` (коррекция/инвентаризация/списание) | ±, ручная правка | warning для `≥0`, **danger при отрицательной дельте** (списание/недостача) | `is-warning` / `is-danger` |

План уточняет фактические имена типов и знак дельты по `journalModel.ts`; правило тона —
по типу + знаку, а не по строковому имени.

## 5. Compound-элементы: решение

Принцип эпика — «тонкий React только для повторяющейся разметки» (`Money`, `LedgerRow`).
В «Складе» два кандидата на «сложный компонент», но каждый встречается **по одному разу**,
поэтому новых shared-компонентов не заводим (YAGNI):

- **Степпер количества** (`.recv-step`: −/поле/+ со смежными границами) — остаётся локальным
  контролом в `ReceivingWorkspace`; только нормализуется на токены и получает полный
  `:focus-visible`. Геометрия смежных границ специфична, в атом-кнопку не втискиваем.
- **Строка журнала** (`.jrow`) — переодевается в **CSS-грамматику** `.ui-ledger-*` (не в
  React-компонент `LedgerRow`: у склада своя модель движения `JournalRow`, а не денежный
  `LedgerEntryView`). Раскладка строки: `.ui-ledger-time`(время) · `.ui-ledger-body`
  (title = товар + `.ui-chip--status` тип; detail = автор) · `.ui-ledger-aside`
  (кол-во «N шт» mono + `<Money signed />`). Даёт единый вид «строки операции» с историей
  Клиента, не плодя дубль-компонент.

## 6. UX-фиксы (полный набор, с критериями приёмки)

Каждый фикс — про **класс** огрехов, не про один случай.

**UX-1. Статус остатка — убрать тройной сигнал.**
Сейчас «мало/нет» показывается разом тремя способами: цветная полоса слева + подмена иконки
(`Boxes`→`AlertTriangle`) + текст-тег. Свести к согласованной паре, как долг у Клиента: кант
`.ui-card--edge` в тон (`--warning`/`--danger`) + **один** `.ui-chip--status` бейдж
(`is-warning`/`is-danger`). Иконку-якорь оставляем (scan-anchor), но она перестаёт быть
третьим независимым индикатором статуса.
*Приёмка:* у товара «мало»/«нет» статус читается кантом + одним бейджем; текст-тег
`.stock-status-tag` удалён; строки одной высоты.

**UX-2. Деньги — моно и едины везде.**
Все 7 реализаций → `<Money>`; движения и разницы — `<Money signed>` (приход/излишек зелёный,
расход/недостача красный), как ledger Клиента.
*Приёмка:* каждая сумма в разделе — `.ui-money` (mono + tabular); в журнале и инвентаризации
знак и цвет соответствуют направлению движения; ноль/пусто приглушены.

**UX-3. Единые фильтры.**
Три разных segmented-контрола → `.ui-chip--filter` (см. 3.6).
*Приёмка:* фильтры Остатков и Журнала визуально идентичны фильтрам истории Клиента; одно
active-состояние; доступны с клавиатуры (`:focus-visible`).

**UX-4. Сводки-метрики на единый паттерн.**
Правые колонки-сводки (`.ctx-card` + `.ctx-big` большое число + счётчики) → `.ui-card--stat`
(label малым `--text-xs` `--text-secondary`, значение крупным mono), как карточки Баланс/Долг
у Клиента. Денежные метрики — `<Money>` в слоте значения; критические счётчики (нет/мало,
недостача) тонируются `.ui-card--stat.is-danger` только при `>0`.
*Приёмка:* метрики стоимости склада / итога приёмки / нетто журнала / инвентаризации выглядят
одинаково; крупное число — mono; danger-тон только когда есть проблема.

**UX-5. Строка журнала — язык ledger.**
`.jrow` (ad-hoc 6-колонок) → грамматика `.ui-ledger-*` (см. §5): тип = `.ui-chip--status`,
сумма = `<Money signed>`, время = mono.
*Приёмка:* строка движения визуально согласована с историей операций Клиента; тип-чип
тонируется по маппингу §4; отрицательные движения — красным со знаком «−».

**UX-6. Иерархия и состояния кнопок.**
«Провести приёмку/инвентаризацию» = **одна** `.ui-btn--primary --block` на вкладке; иконочные
+/− на строке = `.ui-btn--sm` с полным `:hover`/`:focus-visible`/`:active`; списание и удаление
строки = тон `--danger`; сброс = `--ghost`.
*Приёмка:* на вкладке одна заливка-кнопка главного действия; деструктивные действия читаются
как danger; все иконочные кнопки фокусируемы с клавиатуры и отвечают на нажатие.

**UX-7. Дисциплина шкал (инвариант §8 эпика).**
~30 хардкод-мест → токены: отступы `--space-*`, скругления `--radius-*`, типографика
`--text-xs/sm/...`; кластер шрифтов 12/14px → `xs(11)`/`sm(13)`, акцент весом (700), не размером;
motion → `--duration-*`/`--ease-*`. Ширины колонок таблиц (грид-темплейты `88px 66px…`) —
допустимы как раскладочные константы, но выравниваются по `--space`-кратным где разумно.
*Приёмка:* в изменённых правилах `22-stock.css` нет сырых `px` для отступов/радиусов/шрифтов
(кроме обоснованных грид-ширин); grep по `\dpx` в тронутых блоках чист от нормализуемых.

## 7. Влияние на тесты

Тесты, завязанные на удаляемые/переименовываемые классы, чинятся в том же слайсе (не
ослабляя проверки — переводим на устойчивые селекторы или на новые классы):

- `StockLevelsWorkspace.test.tsx` — `querySelectorAll('.stock-status-tag.low/.out')`,
  `querySelector('.cash-stock-list')`: перевести на роль/текст статуса или на `.ui-chip--status`.
- `JournalWorkspace.test.tsx`, `ReceivingWorkspace.test.tsx` — в основном `aria-label`/role
  (устойчивы), проверить после переезда.
- Unit-модели (`stockLevels`, `journalModel`, `receivingModel`, `inventoryModel`) — логику не
  трогаем; не должны затрагиваться.

Правило: если тест ассертит на конкретный класс, который мы убираем, — заменяем на ассерт по
смыслу (роль/текст/`aria`), а не удаляем проверку.

## 8. Гейт слайса, namespace, каскад

- **Гейт:** `bun test` (вся сюита + отдельный прогон `App.test`) **и** `bun run build`
  (`tsc -b && vite`) зелёные. `tsc -b` тайпчекает и тест-файлы — зелёный `bun test` не
  гарантирует зелёную сборку; финал слайса обязан включать `bun run build`.
- **Namespace:** только `.ui-*` из общего слоя; новых секционных `stock-*` дублей не плодим.
- **Каскад:** `02-ui-kit.css` грузится до `22-stock.css` — во время миграции секционные
  правила ещё выигрывают, поэтому переезд покомпонентный (атом → удалить локальное правило).
- **i18n:** переиспользуем существующие ключи `op.stock.*`; хардкод-строк не добавляем.
- **Деньги-path (FROZEN):** визуальная миграция денег (`<Money>`) не меняет расчёты/валидацию
  себестоимости, сумм, дельт — только рендер. Логика `*Model.ts` не трогается.

## 9. Риски

- **Регрессии раскладки при перекройке (UX-4/UX-5).** Митигируется live-превью раздела до
  мержа (skill `operator-wpf-preview` / `bun run dev`) — это визуальный слайс, владелец смотрит.
- **Тесты на классах.** Митигируется §7 — чиним в слайсе, переводя на устойчивые селекторы.
- **Compound-геометрия степпера.** Оставляем локальным; риск — забыть `:focus-visible`.
  Явный критерий в UX-6.
- **Размер слайса.** «Склад» крупнее «Клиентов» (4 вкладки). Митигируется декомпозицией плана
  по вкладкам: каждая вкладка — отдельная задача с гейтом; слайс собирается инкрементально.
