# Operator «Склад»: редизайн боковой панели + стандартизация сканера/поиска

**Дата:** 2026-07-08
**Статус:** утверждено, план — следующий шаг
**Контекст:** ветка `feat/operator-clients-center-redesign` (переключиться на отдельную ветку перед реализацией)

## Проблема

Экран «Склад» состоит из 4 вкладок (Остатки/Приёмка/Журнал/Инвентаризация), все на общих CSS-классах
`.stock-summary`/`.ctx-card`/`.mv`/`.totrow` (`src/AFK4.Operator.App.Web/src/styles/22-stock.css`). Пользователю
нравятся Касса/Карта/Брони, не нравится правая панель Склада — она выглядит как россыпь мелких плоских
блоков без иерархии, в отличие от «героя + hairline-секции + сплошная CTA» на эталонных экранах.

Отдельно — строка «сканер/поиск товара» в Приёмке и Инвентаризации реализована тремя разными визуальными
способами (см. ниже), хотя фича одна и та же (`useBarcodeScanner` + ручной текстовый поиск).

Так как `.stock-summary` — общий класс на все 4 вкладки, чинить только одну вкладку нельзя: правки идут
единым паттерном сразу по всем четырём.

## Часть 1 — Правая панель («Сводка»)

### Эталон (уже валидирован пользователем на Кассе/Карте/Брони)

Единая цельная панель (border+radius+shadow, как `.context-panel` на Карте): наверху «герой» — цветной
левый кант + uppercase-подпись (11px, tertiary) + крупное моно-число + подпись-примечание, ниже —
hairline-разделённые секции с плоскими строками (подпись слева / значение справа моно, без рамок), внизу —
сплошная CTA-кнопка на всю ширину.

Токены — только существующие (`--accent`, `--warning`, `--danger`, `--text-tertiary`, `--surface-elevated`,
`--shadow-card` и т.п.), новых не заводим.

Реализация: общий React-компонент `stock/StockHero.tsx` (проп `tone: 'neutral' | 'ok' | 'warning' |
'attention' | 'muted'`, `label`, `value`, `sub?`) — переиспользуется во всех 4 вкладках вместо 4 копий
одного и того же JSX/CSS.

### Остатки (`StockLevelsWorkspace.tsx`)

- Герой 1: «Стоимость склада» — тон `neutral`, значение = `summary.totalValueMinorUnits`, подпись = «N ед ·
  по средней закупочной» (как сейчас).
- Герой 2: «Нужно дозаказать» — значение = `orderItems.length`; тон по худшему статусу:
  `attention` если `summary.outCount > 0`, иначе `warning` если `summary.lowCount > 0`, иначе `muted`.
  Подпись: «мало · N   нет в наличии · M».
- Секция «К заказу» (только если `orderItems.length > 0`): список товаров как сейчас (`order-item`),
  визуально подчинена панели (без отдельной рамки-карточки).
- CTA «Оформить приёмку» — рендерится только при `orderItems.length > 0` (как сейчас), внизу панели.

### Приёмка (`ReceivingWorkspace.tsx`)

- Секция «Накладная» (поставщик / № накладной) — без изменений в логике, только визуально подчинена
  единой панели (не отдельный бокс).
- Герой: «Итого» — тон `neutral` если `lines.length > 0`, иначе `muted`; значение = `totals.sumMinorUnits`.
- Плоские строки: «Позиций» → `totals.positions`, «Единиц» → `totals.units`.
- CTA «Провести» — без изменений в логике (disabled при `lines.length === 0 || posting`).
- Статусы `post.kind === 'done' | 'error'` — без изменений.

### Журнал (`JournalWorkspace.tsx`)

- Секция «Период» (чипы) — без изменений.
- Герой: «Чистое» — значение = `summary.netQty`; тон `ok` если > 0, `warning` если < 0, `muted` если 0.
  (Тот же приём, что уже сделан для Журнала Кассы — «Итого» лидером.)
- Плоские строки: «Приход» (`+qty · Money`, зелёный акцент), «Продано» (`-qty`), «Списано» (`-qty · Money`,
  янтарь) — тональные модификаторы как сейчас (`.in`/`.wn`), просто без обёртки `.totrow`-карточки.

### Инвентаризация (`InventoryWorkspace.tsx`)

- Секция «Прогресс» (бар + «Пересчитано X/Y») — без изменений в логике, визуально подчинена панели.
- Герой: «Итог по стоимости» — значение = `totals.netSumMinorUnits` (со знаком); тон `attention` если < 0
  (недостача), `ok` если > 0 (излишек), `muted` если 0.
- Плоские строки: «Расхождений» → `totals.discrepancies`, «Недостача» → `-shortageUnits ед · Money`
  (`warning-text`), «Излишек» → `+surplusUnits ед · Money` (`inv-pos`).
- CTA «Провести» + `<p className="ctx-note">` — без изменений в логике.

## Часть 2 — Стандартизация строки сканера/поиска (Приёмка + Инвентаризация)

### Текущее расхождение (три разных языка для одной фичи)

| Экран | Бейдж «сканер активен» | Поле поиска |
|---|---|---|
| Касса/POS (эталон) | `.pos-scanner-badge` — пульсирующая точка, accent-soft фон, без рамки | `.pos-search` — иконка+инпут в общей рамке, sunken-фон, на всю ширину |
| Приёмка | `.ui-chip--status.is-live` — обычный зелёный чип с рамкой, без пульса | `.ui-field` инпут на всю ширину + отдельная строка-подсказка текстом |
| Инвентаризация | нет бейджа — вся строка обведена акцентной рамкой с градиентом + мигающий текстовый курсор `|` | `.inv-search` — фиксированная ширина `min(220px, 30vw)`, sunken-фон |

Причём фича идентична — везде один и тот же `useBarcodeScanner` + ручной текстовый поиск.

### Целевое состояние

Эталон — Касса, как уже валидированный пользователем экран:

1. **Общий бейдж** — вынести `.pos-scanner-badge`/`.pos-scanner-pulse` из `11-pos.css` в общий слой
   (`02-ui-kit.css`, например `.scanner-badge`/`.scanner-pulse`), использовать одинаково на всех трёх
   экранах (POS/Приёмка/Инвентаризация). Убрать `.ui-chip--status.is-live` вариант в Приёмке и
   акцентную рамку+мигающий курсор в Инвентаризации.
2. **Общее поле поиска** — привести оба поля (`recv-add`/`inv-scanbar`) к паттерну `.pos-search`:
   иконка+инпут в одной рамке, sunken-фон, focus-ring, растягивается на всю ширину строки (убрать
   фиксацию `min(220px, 30vw)` в Инвентаризации).
3. **Пояснительный текст** (`op.stock.receiving.addHint` / `op.stock.inventory.scanHint`) — остаётся,
   это не статус-сигнал, а мини-инструкция по использованию поля; но в одном и том же оформлении
   (маленькая подпись под/рядом с полем) на обеих вкладках, без мигающего курсора.
4. Реализация — общий React-компонент `stock/ScanSearchBar.tsx` (проп `hint`, `value`, `onChange`,
   `placeholder`), используется в `ReceivingWorkspace.tsx` и `InventoryWorkspace.tsx`; бейдж
   «Сканер активен» — часть этого компонента (всегда показывается, т.к. сканер слушает всегда, когда
   вкладка активна и есть право).
5. i18n-ключи не меняются (`op.pos.scan.active` уже общий, `addHint`/`scanHint`/`search`-плейсхолдеры
   остаются раздельными по экранам).

## Не в скоупе

- Функциональная логика приёмки/инвентаризации/журнала/остатков — не меняется, только визуальное
  оформление сайдбара и строки сканера.
- POS (`BackendPosWorkspace.tsx`) — donor эталона, но сам не редизайнится (уже хорош); при выносе
  `.pos-scanner-badge`/`.pos-scanner-pulse` в общий слой — обновить импорт в `BackendPosWorkspace`,
  не меняя вид.
- Новые i18n-ключи, новые цветовые токены — не нужны.
