# P1. Агент говорит правду

Дата: 2026-09-24. Спека: `../specs/2026-09-24-player-shell-rewrite-design.md`, §4.2, §4.3,
§6.4. Первый план из нарезки P1–P9.

## Зачем

Оболочка может быть сколько угодно красивой, но покажет она то, что ей скажет агент. Сейчас
агент говорит неправду:

- «на связи» всегда;
- «нет связи» и «последняя минута» не наступают никогда;
- состояние приходит раз в сердцебиение, опросом канала;
- код посадки живёт и после обрыва связи;
- «грейс» называется «лимитом долга»;
- игры запускаются в сессии 0 от SYSTEM, то есть невидимо.

## Что делаем

1. **Контракты.**
   - Конверт канала v2: `ShellPipeMessage` с полями `hello`, `state`, `request`, `reply`,
     словари типов.
   - Кодек кадров: 4 байта длины + UTF-8 JSON, предел 1 МиБ.
   - Новые поля `PlayerShellStateDto`: `ObservedAtUtc` (время платформы в момент сборки — хост
     считает по нему поправку часов), `LastContactUtc`, `SeatingCodeExpiresAtUtc`, `ApiBaseUrl`.
   - Классификатор: `grace` → `connectivity`.
   - Старые `PlayerShellCommandDto` и `PlayerShellCommandResultDto` удаляются.
   - Контракты TS и Dart перегенерируются.
2. **Сборщик состояния.** Вынести из `Worker.CreatePlayerShellState` в
   `PlayerShellStateBuilder` — чистый класс над хранилищами:
   - «на связи» — был успешный контакт не старше окна от последнего интервала сердцебиения;
   - заперт и без связи → `offline`, код посадки не отдаётся;
   - идёт сессия и до конца аренды меньше 60 с → `ending`;
   - код посадки отдаётся только на запертом ПК, на связи и до истечения;
   - адрес API — из настроек агента.

   Данные из сердцебиения (код, срок, оформление, интервал) живут в
   `ShellHeartbeatSnapshot`, а не в полях работника.
3. **Канал `afk4-shell-v2`.** Постоянный двусторонний, один клиент.
   - На Windows — ACL: SYSTEM полный доступ; администраторы и интерактивный пользователь —
     чтение и запись. Учётку игрока впишет мастер в P5, до тех пор — интерактивный вход.
   - Хост шлёт `hello {protocol: 2}`. Другая версия протокола получает `bye`.
   - Агент отдаёт состояние сразу, затем при каждом значимом изменении и раз в 5 с. Тиканье
     остатка секунд изменением не считается: оболочка считает сама по сроку аренды.
   - Изменение будит канал сразу: после команды lock/unlock, после сердцебиения.
   - Запросы: `launch {appId}`, `assist`. На каждый приходит ответ `reply` с тем же
     `requestId`.
   - Старые каналы `afk4-player-shell` и `afk4-player-shell-commands` удаляются вместе с
     серверами и опциями.
4. **Запуск игр.**
   - Только при идущей сессии (`active`, `grace`, `ending`). Исключение — приложение с
     `AllowWithoutSession`.
   - Запуск в сессии игрока — тем же `CreateProcessAsUser`, каким поднимается оболочка. Вне
     Windows и в интерактивном запуске — в своей сессии, как у супервизора.
5. **Хост.**
   - `ShellPipeClient` вместо `NamedPipePlayerShellStateClient` и `LauncherCommandClient`.
   - `shell:requestOperator` зовёт агента (`assist`) — был заглушкой.
   - `shell:pause` убирается: паузы у игрока нет.
   - Адрес API из состояния хост начнёт использовать в P3: до тех пор хватает переменной
     окружения.

## Проверка

- **Shared Contracts:** кодек — круговой обмен, обрыв посреди кадра, слишком длинный кадр.
  Классификатор. Сериализация новых полей.
- **Агент:**
  - сборщик — `offline`, `ending`, срок и сокрытие кода, окно «на связи», адрес API;
  - сервер канала — hello → состояние, пробуждение по сигналу, пульс, ответы на `launch` и
    `assist`, чужой протокол → `bye`;
  - обработчик команд оболочки — отказ без сессии, запуск при сессии, вызов администратора.
- **Хост:** тесты моста на Windows-дорожке. Проект собирается и на macOS, но не запускается.
- **Ворота:** `scripts/verify.sh dotnet`; контракты — `bun run gen` и проверка актуальности;
  Windows-дорожка на раннере GitHub.

Чего не докажет ни одна из этих проверок: ACL канала против настоящего обычного пользователя и
запуск игры на экране игрока. Это приёмка P5 на живом ПК.
