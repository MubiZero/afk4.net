# Хранилище файлов клубов

Логотипы клубов, обложки и фото зала лежат в объектном хранилище. Без него загрузка отказывает
всюду: и в мастере установки, и в панели управляющего. Готовые эмблемы логотипов от этого не
зависят — они отдаются статикой самой платформы (`wwwroot/branding/presets`).

Признак настроенности виден на экране здоровья платформы: пока переменные не заданы, там висит
карточка «Хранилище файлов — не настроено». Это сделано намеренно: иначе о проблеме узнаёт клуб,
который первым попробовал загрузить логотип.

## Что уже есть

MinIO стоит в Coolify как сервис `afk4-update-artifacts-staging` и обслуживает пакеты обновлений:

| адрес | назначение |
| --- | --- |
| `updates.afk4.net` | S3-совместимый API |
| `updates-console.afk4.net` | веб-консоль MinIO |

Заводить второй сервис не нужно — нужен **второй бакет** в этом же MinIO.

## Порядок настройки

1. **Бакет.** В консоли MinIO создать бакет `afk4-media-staging`.

   Отдельно от `afk4-updates-staging` намеренно: у пакетов обновлений и картинок клубов разный
   доступ (пакеты забирает агент по ссылке, картинки открыты всем) и разный срок жизни.

2. **Публичное чтение.** Картинку должны забирать приложение игрока и экран игрового ПК, без токена
   и без подписи. В консоли MinIO: бакет → Anonymous → добавить правило на префикс `/` с доступом
   `readonly`.

   Только чтение. Запись остаётся по ключам — иначе в бакет сможет писать кто угодно.

3. **Ключ доступа.** Создать отдельный Access Key для платформы (не переиспользовать ключ
   обновлений) и ограничить его этим бакетом.

4. **Переменные Platform API** в Coolify — раздел «Хранилище файлов» из
   `deploy/coolify/staging.env.template`:

   ```
   Media__S3__Endpoint=https://updates.afk4.net
   Media__S3__Bucket=afk4-media-staging
   Media__S3__Region=us-east-1
   Media__S3__PublicBaseUri=https://updates.afk4.net/afk4-media-staging
   Media__S3__AccessKey=<секрет Coolify>
   Media__S3__SecretKey=<секрет Coolify>
   ```

   Ключи — секретами, runtime-only. После сохранения нужен **передеплой**: без него контейнер
   продолжит работать со старой конфигурацией.

## Проверка

1. Экран здоровья платформы (`/admin/health`) — карточка «Хранилище файлов» должна исчезнуть.
2. В панели клуба загрузить логотип и открыть его адрес в браузере: картинка должна отдаваться
   без авторизации.
3. Тот же файл в мастере установки на шаге оформления.

Если загрузка отвечает «Media storage is not configured» — переменные не доехали до контейнера
(забыт передеплой или опечатка в имени). Если отвечает ошибкой S3 — проверять ключ и права бакета.

## Ограничения, заложенные в коде

- Потолок размера — 10 МБ (`Media:MaxBytes`).
- Тип файла определяется по сигнатуре, а не по расширению; принимаются PNG, JPEG и WebP.
- У логотипа клуба, логотипа зала и обложки назначение одиночное: новая загрузка вытесняет
  прежнюю, а не копит мусор. Галерея так себя не ведёт.
