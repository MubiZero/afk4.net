# Домены и адреса AFK4

Status: схема принята частично — заведено то, что работает сегодня. Последнее обновление
2026-09-03.

## Правило, из которого всё следует

**Запись в DNS заводится вместе с приложением, которое на этот адрес отвечает, а не заранее.**
Имя, указывающее на сервер, где для него нет маршрута в Traefik, не «ждёт своего часа»: оно
отдаёт чужую заглушку, сертификат Let's Encrypt на него не выпускается, и посетитель видит
ошибку TLS. Пустая зона честнее полузаполненной.

## Что есть сейчас

Проект переехал на свой домен 2026-09-03. Записи зоны `afk4.net`:

| Тип | Имя | Значение | Прокси |
|---|---|---|---|
| A | `api.afk4.net` | `207.180.237.97` | нет |
| A | `platform.afk4.net` | `207.180.237.97` | нет |
| A | `updates.afk4.net` | `207.180.237.97` | нет |
| A | `updates-console.afk4.net` | `207.180.237.97` | нет |
| MX | `afk4.net` | `mail.mubi.dev` (10) | — |
| TXT | `afk4.net` | `v=spf1 mx -all` | — |
| TXT | `_dmarc.afk4.net` | `v=DMARC1; p=none; …` | — |
| TXT | `_smtp._tls.afk4.net` | `v=TLSRPTv1; …` | — |
| CAA | `afk4.net` | `0 issue "letsencrypt.org"`, `0 iodef "mailto:postmaster@mubi.dev"` | — |

К записи CAA Cloudflare автоматически дописывает свои удостоверяющие центры (`digicert.com`,
`pki.goog`, `ssl.com`, `comodoca.com`) — они нужны для его собственных краевых сертификатов,
это штатное поведение, а не чужое вмешательство.

Учётная запись ACME в CAA намеренно не указана. Сертификаты выпускают двое — Traefik в
Coolify для приложений и Stalwart для почты, — у каждого своя учётная запись, и пиннинг
одной сломал бы вторую. У `mubi.dev` пиннинг есть, потому что там выпускает только Stalwart.

### Что где живёт

| Имя | Что отвечает | Приложение в Coolify |
|---|---|---|
| `api.afk4.net` | Platform API | `afk4-platform-api-staging` |
| `platform.afk4.net` | Platform Control | `afk4-platform-control-staging` |
| `updates.afk4.net` | хранилище пакетов обновлений (MinIO) | сервис `afk4-update-artifacts-staging` |
| `updates-console.afk4.net` | консоль MinIO | тот же сервис |
| `mail.mubi.dev` | почта | сервис `mail-mubi-dev` (Stalwart) |

Среда по-прежнему помечена как `Staging` (`ASPNETCORE_ENVIRONMENT`), и имена приложений в
Coolify сохранили суффикс `-staging`: переименование ничего не даёт, а ссылки на UUID есть
в переменных GitHub. Первый клуб подключается к этой же среде; отдельный production
разворачивается тогда, когда появится нужда держать две.

Почтовый хост осознанно не переезжает на `afk4.net`: обратная зона IP указывает на
`mail.mubi.dev`, и на этом имени наработана репутация отправителя. Домен в адресе письма
(`no-reply@afk4.net`) от имени сервера не зависит.

**Поддоменов на клуб нет.** Раньше клуб определялся по адресу (`клуб.afk4.net`); в приложении
игрока от этого отказались — клуб выбирается внутри приложения из каталога
(`2026-08-11-customer-app-flutter-design.md`). Значит ни wildcard-записи, ни
wildcard-сертификата не требуется.

### Ещё не заведено

`afk4.net` и `www.afk4.net` — лендинга пока нет, а имя, ведущее на сервер без маршрута,
отдаёт чужую заглушку и не получает сертификат. `status.afk4.net` — монитор доступности
сейчас пишет в Telegram, показывать нечего.

## Что двигалось вместе с адресами

Смена хоста ломает не DNS, а всё, где адрес записан отдельно. При переезде 2026-09-03
поменяны одновременно:

- домены приложений в Coolify (оба адреса какое-то время жили рядом, чтобы ничего не
  оборвалось на полпути) и конфигурация сервиса MinIO — `MINIO_SERVER_URL`,
  `MINIO_BROWSER_REDIRECT_URL` и метки Traefik;
- переменные Platform API: `AllowedHosts`, `Cors__PlatformWebOrigins__0`,
  `Install__ApiBaseUrl`, `DcGate__WebhookUrl`,
  `OrganizationAdminCompatibility__DownloadUrl`;
- `VITE_PLATFORM_API_BASE_URL` у Platform Control — **переменная времени сборки**: без
  пересборки панель продолжает ходить на старый адрес, даже когда открывается по новому;
- переменные репозитория GitHub: `AFK4_STAGING_PLATFORM_BASE_URL`,
  `AFK4_ALLOWED_PLATFORM_BASE_URLS`, `AFK4_STAGING_MINIO_ENDPOINT`,
  `AFK4_STAGING_UPDATE_PUBLIC_BASE_URI`;
- значения по умолчанию в клиентах: `SetupWizardApiClient`, `PlayerShellOptions` — мастер
  установки и оболочка игрока зашивают адрес платформы как запасной;
- рунбуки, шаблон переменных и монитор доступности.

Чего переезд **не** трогает: адреса уже опубликованных пакетов обновлений. Они неизменяемы
по замыслу и указывают на старый хост; пакеты перевыпускаются следующей сборкой. Устройств
на момент переезда зарегистрировано не было, поэтому `Install__ApiBaseUrl` в машинных
конфигурациях агентов никого не осиротил — при первой установке запишется новый адрес.

## Прокси Cloudflare

Почтовые записи — всегда без прокси (серое облако). Для будущего `api.afk4.net` включение
прокси нужно решать отдельно: через него идут постоянные соединения SignalR (карта зала,
команды устройствам), и краевой прокси добавляет свои таймауты и разрывы. Staging сегодня
работает напрямую, и это самый предсказуемый вариант для первого клуба.
