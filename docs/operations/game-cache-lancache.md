# Кеш игр клуба

Обновление игры весом 50 ГБ на 20 ПК — это 1 ТБ из интернета. С кешем игра приходит из интернета один раз, а остальные
ПК забирают её по сети клуба.

**Клубу ничего не ставить и не настраивать.** Кеш встроен в нашего агента на ПК администратора и включён по умолчанию.
Заявка в Valve не нужна. Протокол — тот же, что у открытого [LANCache](https://lancache.net): Steam сам ищет кеш по
имени `lancache.steamcontent.com` и, если кеш молчит, качает из интернета.

Последнее обновление 2026-10-28 (решение владельца: всё делает наше ПО, без действий клиента).

## Как это устроено

- **ПК администратора** (роль `manager_workstation`) — кеш филиала. Сервер платформы называет его так в сердцебиении
  (`GameCacheHost`), и агент поднимает встроенный кеш (`GameCacheServer`):
  - HTTP на порту 80, правило брандмауэра Windows только для частной сети и локальной подсети;
  - отвечает на `/lancache-heartbeat` как LANCache: `204` и заголовок `X-LanCache-Processed-By`;
  - проксирует и кеширует только Steam (`*.steamcontent.com`) и Epic (список имён в `GameCacheNames`), и только для
    частных адресов. Открытым прокси он не становится;
  - ключ кеша как у LANCache: у клиента Steam — `steam` + путь (одни и те же куски приходят с разных серверов CDN),
    у остальных — имя + путь; строка запроса в ключ не входит;
  - один кусок качается из интернета один раз, даже если его разом просят несколько ПК; в кеш кладётся только целый
    кусок; запросы с `Range` проходят без кеша.
  - **Диск** — тот, где больше свободного места, папка `AFK4GameCache`. Кеш занимает не больше половины доступного места
    и всегда оставляет запас: 30 ГБ или 15 % диска, что больше. Когда места нет, уходит то, что дольше всех никто не качал.
  - Если так выходит меньше 20 ГБ, кеш не поднимается: на паре гигабайт он вытеснял бы каждый кусок сразу, а игровые ПК
    ходили бы через ПК администратора без пользы. Агент проверяет место снова раз в час; Панель называет причину.
    (Найдено на VM 28.10: на диске 64 ГБ со свободными 29 ГБ квота выходила нулевой.)
  - Агент сообщает «кеш поднят» и сколько в нём лежит. Если порт 80 занят чужой программой, кеш не поднимается, агент
    повторяет попытку раз в 5 минут, а игровые ПК качают как раньше.
- **Игровые ПК** получают адрес ПК администратора. Их агент раз в минуту проверяет `/lancache-heartbeat`
  (`GameCacheService`):
  - пока кеш отвечает, держит в `hosts` свой блок между метками `# AFK4 game cache begin/end`: имя Steam и 15 имён Epic
    (список [uklans/cache-domains](https://github.com/uklans/cache-domains)), и сбрасывает кеш DNS Windows;
  - кеш замолчал (ПК администратора выключен) — блок убирается. Steam и без этого обошёл бы молчащий кеш, а Epic упёрся
    бы в мёртвый адрес. Чужие строки `hosts` агент не трогает.
- Сам ПК администратора к кешу не направляется: он и есть кеш.
- **Панель:** «Управление» → «Игры» → «Кеш игр клуба» показывает, где кеш, сколько хранит и сколько ПК его видят:
  «Кеш на ПК администратора ADMIN-PC, хранит 120.0 ГБ · Кеш видят 7 из 9 ПК». Там же галочка «Кеш игр включён».

Код:
- агент: `src/AFK4.Agent.Service/Network/GameCacheServer.cs` (кеш) и `GameCacheService.cs` (hosts);
- сервер: `src/AFK4.Platform.Api/Games/BranchGameCache.cs`, `Endpoints/GameCacheEndpoints.cs`;
- контракты: `src/AFK4.Shared.Contracts/Games/GameCacheContracts.cs`.

## Для больших клубов: свой сервер LANCache

Если ПК администратора слабый, с маленьким диском или выключается на ночь, клуб может поставить отдельный сервер LANCache
и указать его адрес в той же карточке («Для больших клубов: свой сервер LANCache»). Тогда встроенный кеш гасится, а игровые
ПК идут к этому серверу тем же путём. Это необязательно, и предлагать это стоит только тем, кто сам хочет.

Установка (Ubuntu Server, отдельный диск под кеш, кабель до коммутатора):

```bash
sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2 git
git clone --depth=1 https://github.com/lancachenet/docker-compose lancache
cd lancache   # в .env: LANCACHE_IP, CACHE_ROOT, CACHE_DISK_SIZE
sudo docker compose up -d monolithic
```

## Ограничения

- **Riot и Battle.net** раздают игры с имён по маске (`*.dyn.riotcdn.net`), а `hosts` маски не понимает. Им нужен DNS
  клуба (контейнер lancache-dns и DHCP роутера), то есть настройка сети клиента. По умолчанию этого не делаем.
- **Профиль сети Windows «Общедоступная»** закрывает порт кеша на ПК администратора, как и порт офлайн-аренды. Мастер
  установки должен ставить профиль «Частная»; проверить на живом ПК.
- **Лицензии** кеш не даёт: каждый игрок входит в свой аккаунт Steam. Один аккаунт на все ПК нарушает соглашение Steam.
- Кешируется только HTTP, на котором Steam и Epic отдают игры. HTTPS проходит мимо.
- **Steam Local Network Game Transfers** (передача между ПК без кеша) — отдельная настройка клиента Steam. Агент её пока
  не выставляет: ключ её конфигурации надо найти на живом ПК со Steam.

## Проверка

- Проверено на VM 28.10.2026 (заглушка LANCache на Маке): игровой ПК записал блок в `hosts`, Панель показала «видят 1 из 1»,
  после выключения кеша блок убран. Встроенный кеш проверен тестами агента (кусок из интернета один раз, второй раз с
  диска; чужие имена — 403; квота).
- Живой ПК со Steam — скачать игру на одном ПК, затем на другом: второй раз скорость упирается в сеть клуба (около
  100 МБ/с на гигабите). В журнале агента ПК администратора — «Game cache serves from …».
