# Демо на примерах данных: Панель и экран игрока

Панель AFK4.NET, которую можно открыть в браузере без установки и без входа: учебный клуб
«AFK4 Dushanbe» (двенадцать ПК в трёх залах, гости с балансами и долгами, открытая смена,
чаевые, склад, отчёты). Нужна, чтобы владелец клуба потрогал Панель до разговора о подключении.

Рядом с Панелью на том же сайте лежит демо экрана игрока: то, что видит гость на ПК клуба. Оно
собрано так же и описано ниже, в разделе «Экран игрока».

Последнее обновление 2026-10-01.

## Как устроено

- Это та же Панель, собранная с флагом `VITE_AFK4_DEMO=1`. Флаг включает учебный бэкенд из превью
  разработчика (`src/devMockBackend.ts` и `src/devHostBridge.ts`): все запросы отвечает сама
  страница, **ничего не уходит в сеть**. Адреса сервера, ключей и настоящих данных в сборке нет.
- Администратор уже вошёл — формы входа, пароля и ПИН-кода нет. Нажал «Выйти» — увидит обычную
  форму входа — в сеть она ничего не отправит, но и проверять её в демо незачем: обновление
  страницы вернёт вошедшего администратора.
- Всё, что посетитель сделал, живёт в памяти вкладки. Обновил страницу — клуб вернулся к исходному
  виду. Кнопка «Начать заново» в полосе «Демо» делает то же и заодно чистит хранилище браузера.
- Полосу «Демо» не закрыть: посетитель не должен принять выдуманный клуб за чей-то настоящий.
- Кнопок окна (свернуть, развернуть, закрыть) и рамки для растягивания в демо нет — во вкладке
  браузера окна приложения нет.

Что запоминается до обновления страницы: посадить гостя (в том числе гостя, заплатившего наличными
вперёд), продлить, перенести, поставить на паузу и снять, завершить сессию с оплатой и без, команды
ПК (заблокировать, разбудить, вернуть в зал из обслуживания, перезагрузить, выключить), профиль клуба
и его настройки, события, письма с отчётами, настройки защиты ПК, брони, лояльности и приглашений.
Остальные действия отвечают «готово», но данные не меняют — у заглушки нет полной модели клуба.

Живых событий от ПК нет: связь показана как «на связи», но ПК сами ничего не присылают — вызов
администратора, заказ из бара и смена статуса ПК видны только такими, какими они лежат в примерах.
Единственное исключение — результат команды ПК: заглушка сообщает его через полсекунды, и карта
перечитывается (место сразу меняет вид).

Примеры устроены так, чтобы показать недавние возможности: в клубе есть ПК без киоска («PC-06»,
«Не игровое место»), гость с долгом и гость с днём рождения, ПК с вызовом администратора, ПК с
упавшей командой, ПК на обслуживании. Во вкладке «Устройства» — все двенадцать ПК клуба.

## Сборка

```bash
cd src/AFK4.OrganizationAdmin.Web
bun run build:demo
```

Результат — папка `dist-demo/`: `index.html` и `assets/`. Пути относительные (`base: './'` в
`vite.config.ts`), поэтому сайт работает и в корне домена, и в подпапке. Маршрутов нет — одна
страница, серверных правил переписывания адресов не нужно.

Проверить собранное локально:

```bash
bunx vite preview --config src/AFK4.OrganizationAdmin.Web/vite.config.ts --outDir src/AFK4.OrganizationAdmin.Web/dist-demo --port 4175
```

В полосе «Демо» есть ссылка «Экран игрока» (`./shell/`) — на соседнее демо ниже.

## Экран игрока

Тот же приём, что у Панели: оболочка ПК (`src/AFK4.Player.Shell.Web`), собранная с флагом
`VITE_AFK4_DEMO=1`. Флаг включает учебный хост (`src/host/devHost.ts`) — тот, на котором экран
листается в превью разработчика, — и полосу «Демо» над экраном (`src/demo/DemoFrame.tsx`).
**Ничего не уходит в сеть**: настоящего адреса сервера в сборке нет, а запрос к чужому адресу
учебный хост отклоняет, не отправляя.

```bash
cd src/AFK4.Player.Shell.Web
bun run build:demo      # результат — dist-demo/, пути относительные: сайт работает и в /shell/
bunx vite preview --outDir dist-demo --port 4175
```

Что видит посетитель:

- **Полоса «Демо»** над экраном, закрыть её нельзя. В ней: переключатель «Что на экране» (свободный ПК,
  подошли к ПК, идёт сессия, время на исходе, нет связи — сессия идёт, нет связи с клубом,
  обслуживание, сбой ПК, подключение), «Начать заново» (чистит хранилище и перезагружает страницу) и
  ссылка на Панель (`../`). Названия — в каталоге строк оболочки (`playerShell.demo.*`, три языка).
- **Оболочка живая.** Мышь или клавиша на свободном ПК — «подошли», окно входа. Войти можно с любым
  девятизначным номером и ПИН-кодом `123456`. Дальше — выбор времени, старт, игры из библиотеки и
  «Мои приложения», продление, заказ из бара (стойка «принимает» и «приносит» сама), пополнение
  баланса по QR (банк «подтверждает» с третьего опроса), чаевые, итог с оценкой. Баланс один на все
  экраны и живёт в памяти вкладки.
- **Размер.** Оболочка рассчитана на весь монитор, а вкладка браузера ниже и с полосой. Поэтому в
  демо размер шрифта считается от высоты окна (`src/demo/demo.css`): оболочка уменьшается целиком,
  пока не поместится, и ни одна кнопка не оказывается под полосой или за краем. На телефоне демо
  не рассчитано.

Выкладка: `demo-pages.yml` собирает оба демо и кладёт Панель в корень сайта, экран игрока — в
`/shell/`, одним артефактом. Запускается правкой любого из двух приложений, общих пакетов
(`packages/**`), строк (`locales/**`) или самого workflow, а также вручную.

Боевая сборка оболочки учебного хоста не содержит — это проверяет тест
`src/demo/prodBundle.test.ts`: он собирает оболочку обе версии и ищет в JS строки учебного хоста
(в боевой их быть не должно, в демо — должны). Вручную то же:

```bash
cd src/AFK4.Player.Shell.Web
bun run build
grep -l "api.example.test" dist/assets/*.js    # пусто — учебного хоста в боевой сборке нет
```

## Выкладка — GitHub Pages, `demo.afk4.net`

Решено 2026-09-26: репозиторий публичный, и Pages для него бесплатен; статика не трогает сервер
и общую с другим проектом очередь деплоев Coolify. Workflow `.github/workflows/demo-pages.yml`
собирает `bun run build:demo` обоих приложений и выкладывает их одним сайтом (Панель в корне,
экран игрока в `/shell/`) с каждой правкой любого из них в `main` (и вручную — «Run workflow»).

Один раз, до первой выкладки:

1. **Pages в настройках репозитория**: Settings → Pages → Source: «GitHub Actions».
2. **DNS** (Cloudflare, зона `afk4.net`): `CNAME demo → mubizero.github.io`, без прокси (серое
   облако) — иначе GitHub не выпустит сертификат. Запись заводится вместе с выкладкой, не раньше
   (`dns-and-hosts.md`).
3. После первой выкладки в Settings → Pages поставить «Enforce HTTPS», когда сертификат выпущен.

Имя сайта держит файл `CNAME`, который workflow кладёт в сборку.

## Боевая сборка учебный бэкенд не содержит

Флаг подставляется при сборке константой: в обычной `bun run build` ветка с заглушкой и её модуль
выбрасываются. Проверка после любой правки `main.tsx` или `devHostBridge.ts`:

```bash
cd src/AFK4.OrganizationAdmin.Web
bun run build
grep -l "f77b708c-1dc9-4cb3-9c19-21797f7035fc" dist/assets/*.js
```

Пусто — заглушки в боевой сборке нет (строка — идентификатор учебного филиала из
`devHostBridge.ts`). Файл нашёлся — сборка для клубов не годится.
