# Демо-Панель на примерах данных

Панель AFK4.net, которую можно открыть в браузере без установки и без входа: учебный клуб
«AFK4 Dushanbe» (двенадцать ПК в трёх залах, гости с балансами и долгами, открытая смена,
чаевые, склад, отчёты). Нужна, чтобы владелец клуба потрогал Панель до разговора о подключении.

Последнее обновление 2026-09-25.

## Как устроено

- Это та же Панель, собранная с флагом `VITE_AFK4_DEMO=1`. Флаг включает учебный бэкенд из превью
  разработчика (`src/devMockBackend.ts` и `src/devHostBridge.ts`): все запросы отвечает сама
  страница, **ничего не уходит в сеть**. Адреса сервера, ключей и настоящих данных в сборке нет.
- Администратор уже вошёл — формы входа, пароля и ПИН-кода нет. Нажал «Выйти» — увидит обычную
  форму входа — в сеть она ничего не отправит, но и проверять её в демо незачем: обновление
  страницы вернёт вошедшего администратора.
- Всё, что посетитель сделал, живёт в памяти вкладки. Обновил страницу — клуб вернулся к исходному
  виду. Кнопка «Начать заново» в полосе «Демо» делает то же и заодно чистит хранилище браузера.
- Полосу «Демо» не закрыть: посетитель не должен принять выдуманный клуб за чей-то настоящий.
- Кнопок окна (свернуть, развернуть, закрыть) и рамки для растягивания в демо нет — во вкладке
  браузера окна приложения нет.

Что запоминается до обновления страницы: посадить гостя, продлить, перенести, завершить сессию с
оплатой и без, настройки защиты ПК, брони, лояльности и приглашений. Остальные действия отвечают
«готово», но данные не меняют — у заглушки нет полной модели клуба. Живых событий нет: связь
показана как «на связи», но ПК сами ничего не присылают — вызов администратора, заказ из бара и
смена статуса ПК видны только такими, какими они лежат в примерах.

## Сборка

```bash
cd src/AFK4.OrganizationAdmin.Web
bun run build:demo
```

Результат — папка `dist-demo/`: `index.html` и `assets/`. Пути относительные (`base: './'` в
`vite.config.ts`), поэтому сайт работает и в корне домена, и в подпапке. Маршрутов нет — одна
страница, серверных правил переписывания адресов не нужно.

Проверить собранное локально:

```bash
bunx vite preview --config src/AFK4.OrganizationAdmin.Web/vite.config.ts --outDir src/AFK4.OrganizationAdmin.Web/dist-demo --port 4175
```

## Выкладка — действие владельца

Любой хостинг статики. Имя вроде `demo.afk4.net` и запись DNS — решение владельца
(`dns-and-hosts.md`). Если выкладывать через Coolify, помнить: очередь деплоев общая с другим
проектом (`coolify-staging-deploy.md`) — чужие деплои не трогать и не перезапускать.

Обновлять демо после изменений Панели в `main`: пересобрать и выложить `dist-demo/` заново.

## Боевая сборка учебный бэкенд не содержит

Флаг подставляется при сборке константой: в обычной `bun run build` ветка с заглушкой и её модуль
выбрасываются. Проверка после любой правки `main.tsx` или `devHostBridge.ts`:

```bash
cd src/AFK4.OrganizationAdmin.Web
bun run build
grep -l "f77b708c-1dc9-4cb3-9c19-21797f7035fc" dist/assets/*.js
```

Пусто — заглушки в боевой сборке нет (строка — идентификатор учебного филиала из
`devHostBridge.ts`). Файл нашёлся — сборка для клубов не годится.
