# Рефокус «Клуб» и «Платежи/Лояльность» — зафиксированные решения

Дата: 2026-07-20
Часть эпика: «Оператор = единая админка» (первый кирпич, экраны)
Статус: решения приняты в brainstorming; детальная спека каждого экрана — перед его реализацией.
Порядок: под-проект 1 (медиа-загрузка,
`2026-07-20-operator-media-upload-subsystem-design.md`) → под-проект 2 (Клуб, зависит от медиа ради

## Под-проект 2 — «Клуб»: из заглушки в профиль клуба

Сейчас: 2 поля (Name, City) на весь экран. Причина «пустоты» — пустая модель данных, не верстка.

**Гейт всего раздела:** `manageBranchSettings` (`branches.settings.manage`) — owner/доверенный админ.
Кассир/техник раздел не видят. Это первый образец ролевой изоляции для будущей абсорбции owner-панели.

**Четыре блока (все подтверждены пользователем):**
1. **Лицо для игрока** (видно в приложении/бронировании): название, короткое описание, логотип
   (через под-проект 1 — server-mediated upload в MinIO; лимит 10 МБ, png/jpeg/webp).
2. **Адрес и контакты:** город, адрес, телефон, Telegram, сайт (опц.).
3. **Часы работы:** структурированный редактор по **7 дням** (открытие/закрытие + тумблер
   «выходной»); хранение JSON; машинно-читаемо → потом «открыто сейчас» и т.п.
4. **Настройки филиала:** часовой пояс, язык по умолчанию, валюта (read-only — уровень сети).

**Бэкенд (Platform.Api + миграция):** новые колонки филиала — `description`, `address`, `phone`,
`telegram`, `website`, `workingHours` (JSON/jsonb), `timezone`, `locale`. Расширить
`BranchProfileDto`/`UpdateBranchProfileRequest` + валидация.
**Граница time-handling:** часовой пояс ХРАНИМ/редактируем как конфиг, но НЕ перепроводим в логику
lease/биллинга сейчас (отложенный рискованный пункт time-handling-аудита — не смешивать).

**Раскладка:** одна колонка сгруппированных карточек (`mgmt-form`/`mgmt-section-title`) + справа
живой предпросмотр «как видит игрок» (название/лого/часы/адрес) — управление вниманием. Адаптивно,
тач-таргеты ≥44px (готовность к мобильной обёртке).

## Под-проект 3 — «Платежи и лояльность»: один связный экран «деньги ↔ игрок»

Сейчас: два несвязанных таба (шлюзы | лояльность), склеенных через tab-strip.

**Решение:** убрать табы, **одна страница = одна история** «деньги ↔ игрок», две смысловые половины:

**Как игрок платит вам** (приём денег):
- **Наличные** — всегда включено (строка-статус, для полноты картины).
- **Перевод на карту** (dcgate) — карты + привязка Telegram, свои кнопки-действия.
- **Онлайн-оплата Eskhata** — реквизиты, свой «Сохранить», статус-чип.

**Как вы возвращаете** (лояльность):
- Карточки правил кэшбэка + «Ограничения» (уже сделаны в kit-миграции, задача 2) — со своей
  кнопкой сохранения секции.

**Модель сохранения:** табов нет; каждая секция самодостаточна (шлюзы — мгновенные действия; Eskhata
— свой save; лояльность — свой section-save). Это снимает старый конфликт двух save-моделей, из-за
которого их и разнесли по табам. Секции показываются по правам (`managePaymentGateways` /
`manageLoyaltySettings`): нет права — нет секции.

**Переиспользование:** карточки лояльности (задача 2 миграции) и разметка шлюзов на kit (задача 3)
НЕ выброшены — рекомпонуются в эту единую страницу. Адаптивно, тач-таргеты ≥44px.
