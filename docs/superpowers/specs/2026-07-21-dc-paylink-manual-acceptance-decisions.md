## Новая реальность приёма платежей

- **Eskhata Merchant (Eskhata Bank) — ОСНОВНОЙ способ приёма.** Банк выдал тестовые реквизиты →
  интеграция Merchant API движется. (Раньше на UI был «настроен · не активен».)
- **DC через Telegram-автоподтверждение — отвалилось** (текущий `dcgate`: webhook зачислял кошелёк).
  Продуктово выводится из игры в пользу схемы ниже. **Пользователю тех-детали про поломку не
  показываем** — это внутренняя информация.
- **Новый DC — приём по платёжной ссылке:**
  формат `http://pay.dc.tj/?A={card}&s={amount}&c={comment}&f1=133`
  - `A` = номер карты приёма
  - `s` = сумма
  - `c` = комментарий (напр. id заказа `order13497`)
  - `f1=133` и остальные параметры — константа, не меняются.
  Из ссылки собирается **QR**, который игрок оплачивает. **Банк НЕ сообщает, пришла ли оплата** →
  способ **полуручной**: факт получения оплаты **подтверждает админ вручную**. Поэтому DC — **менее
  приоритетный**, чем Eskhata.

## Что уже есть в коде (переиспользовать, не плодить)

- `dcgate`-money-path: `DcGateClient`/`DcGateAdminClient`, `EfBranchPaymentGatewayResolver`, webhook
  зачисления кошелька; на нём висят онлайн-пополнение и авто-подтверждение броней
  ([[afk4-online-booking-autoconfirm-epic]]). **Миграция на pay-link не должна их сломать.**
- `ManualPaymentProvider` + `ManualPaymentRequest` (уже используется для ручных платежей в Кассе,
  `EfPosService`/`PosEndpoints`) — вероятная основа для «подтверждения полученной оплаты админом».

## Открытые вопросы для brainstorming (позже)

- Где генерируется ссылка/QR: в Кассе (POS) в момент приёма платежа, или на стороне игрока
  (Player.Shell / онлайн-пополнение)? Скорее POS + онлайн.
- Как выглядит «ручное подтверждение получено»: очередь ожидающих подтверждения платежей у админа?
  Кто/где подтверждает (Касса? отдельный экран)?
- Судьба старого `dcgate`/Telegram: деприкейт с сохранением webhook, пока не мигрируют зависимые
  потоки, или полное удаление? (Money-path — осторожно.)
- Что этот setup-экран конфигурирует для DC: какая карта(ы) принимает перевод, формат комментария.
