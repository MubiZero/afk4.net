# Миграция отставших экранов «Управления» на общий дизайн-kit

Дата: 2026-07-20
Раздел: Operator App → «Управление»
Затрагивает: `src/AFK4.Operator.App.Web/src/management/**`, легаси-воркспейсы, CSS, i18n

## Проблема (корень)

В разделе «Управление» есть два поколения экранов:

- **На новом kit** (нравятся): Клиенты, Товары, Тарифы, Сотрудники, Залы. Собраны из общих
  кирпичей — `MgmtTable` (тулбар + колонки + честный empty-state), `MgmtDrawer` (боковое
  редактирование), `mgmt-form`/`mgmt-form-grid`, `ui-btn*`, `ui-chip*`, `EmptyState`,
  `CriticalActionConfirmation`.
- **Отставшие** (не нравятся): «Платежи и лояльность» (вкладка «Платёжные шлюзы» + «Лояльность»),
  «Клуб», «Новости». Они монтируют старые легаси-компоненты как есть, мимо kit.

Три экрана не мигрировали на общий язык. Лечение — не «покрасить», а перевести на те же кирпичи.

## Целевой дизайн по экранам

### 1. Платежи → «Платёжные шлюзы» (`payments/GatewaysTab.tsx` + `PaymentGatewaysWorkspace.tsx`)

Сейчас: сырой блок dcgate (`PaymentGatewaysWorkspace`, голые `<label>`/`<button>`, квадратный
чекбокс, `window.confirm`, `<p>`-empty) + современный `EskhataGatewayForm`, разделённые `<hr>`.

Цель — **два одинаковых по языку провайдер-блока** (секции с `mgmt-section-title` + статус-чип),
без `<hr>`:

- **«Приём по картам» (dcgate)** — переписать разметку `PaymentGatewaysWorkspace` на kit:
  - Форма добавления карты: `mgmt-form` + `mgmt-form-grid`, поле «Номер карты», скоуп
    org/branch через `mgmt-check` (вместо квадратного чекбокса), кнопка `ui-btn ui-btn--primary`.
  - Список карт: строки в едином визуальном языке; статус карты и Telegram-здоровье — через
    `ui-chip ui-chip--status` (варианты is-neutral/is-ok/is-warn по статусу). Никаких
    вручную стилизованных `payment-card-*` — переиспользуем принятые классы.
  - Пустой список: `EmptyState` (иконка + заголовок + описание), не голый `<p>`.
  - Telegram-привязка (телефон → код → пароль): те же `mgmt-form` инпуты и `ui-btn`.
  - Отключение карты — money-path → `CriticalActionConfirmation` (как «Снять с продажи» в
    Товарах) вместо `window.confirm`.
  - Поведение, контракты API, стейт-машина привязки — **1:1, меняется только разметка/классы**.
- **«Eskhata Merchant»** (`EskhataGatewayForm`) — уже на kit; выровнять в общий ряд секций
  (заголовок + статус-чип), убрать `eskhata-divider`.

Ширина экрана: `wide`. Модель «мгновенных действий» (свои кнопки у блоков), общего save-бара нет —
как сейчас.

### 2. «Лояльность» (`payments/LoyaltyTab.tsx`)

Уже на `mgmt-form`, но: тесная раскладка правил, «пусто/бедно», оторванный блок лимитов.

- **Правила → карточки.** Каждое из трёх (Пополнение / Магазин / Игровое время) — карточка
  `loyalty-rule-card`: тумблер вкл + название + подсказка + **крупное поле %** (не втиснутое
  справа). Три карточки стопкой.
- **Живой пример в каждой карточке** — лечит «пусто/бедно» честно, без выдумок: считается на
  клиенте из введённого %. Пример: при % = 10 и валюте TJS → «Пополнил 100 с. → +10 бонусов».
  База примера — фиксированная сумма 100 (константа), формат через `Money`/currency. Пример
  тускнеет/скрывается, когда правило выключено.
- **Блок лимитов → «Ограничения начисления»** с явной подсказкой, что лимит и минимум
  применяются ко всем правилам выше. Остаётся парой полей (`Лимит, {валюта}` / `Минимум,
  {валюта}`), но с понятным заголовком и связью.

Ширина: `form`. Save-бар — глобальный (в `ManagementScreen`), как сейчас.

### 3. «Клуб» (`ClubDestination.tsx` + `SettingsProfileSection.tsx`)

Сейчас: плоский `settings-form-grid` из 4 инпутов (2 редактируемых + 2 read-only «серых»).

- Одна опрятная панель `mgmt-form` с `mgmt-section-title` «Профиль клуба».
- Редактируемые поля (Название, Город) — обычные инпуты `mgmt-form-grid`.
- Справочные (Валюта, Филиал) — **read-only мета-строки** (label + статичное значение), а не
  disabled-инпуты, которые читаются как «сломанные».
- Фейковых полей не добавляем — экран по сути маленький; честно компактный, но структурный.

Ширина: `form`. Save-бар — глобальный, как сейчас.

### 4. «Новости» (`NewsDestination.tsx` + `NewsWorkspace.tsx`)

Сейчас: сырая `settings-form-grid` форма + голый `<ul>` списком.

Цель — паттерн Товаров, **но создание и редактирование оба в `MgmtDrawer`** (у новости длинное
«тело» — в drawer'е просторнее; один паттерн на оба сценария):

- `MgmtTable`: колонки **Заголовок · Филиал · Статус · Окно публикации**.
  - Статус: `ui-chip` «Опубликовано» / «Черновик» (по `isPublished`).
  - Филиал: имя филиала или «Все филиалы» (branchId=null).
  - Окно публикации: даты publish/expires через `formatDate` (или «—»).
  - Тулбар: заголовок + первичная кнопка «Создать новость». Поиск — опционально (по заголовку),
    если дёшево; иначе не добавлять (YAGNI).
  - Честный `EmptyState` при пустом списке.
- Клик по строке → `MgmtDrawer` (режим редактирования); «Создать новость» → тот же `MgmtDrawer`
  с пустой формой (режим создания).
  - Поля формы 1:1 из текущего `NewsWorkspace`: заголовок, филиал (select), тело (textarea),
    картинка (url), опубликовано (тумблер), publishAt/expiresAt (datetime-local).
  - Футер drawer'а: `Сохранить` (`ui-btn--primary`) + `Удалить` (`ui-btn--danger`, только в
    режиме редактирования). Удаление — через `CriticalActionConfirmation` (публикация — внешне
    видимый контент, удаление стоит подтверждать).
  - Валидация (title/body обязательны; publish < expires) — портируется 1:1.
- API-контракты (`news.list/listBranches/create/update/remove`) — без изменений.

Ширина: `full` (master-detail, как Товары).

## Общие принципы миграции

- **Только разметка/классы/раскладка меняются; API-контракты, стейт-машины, валидация,
  permission-гейты, идемпотентность, money-path guard'ы — переносятся 1:1.** Это не рефактор
  логики, а перевод на дизайн-kit.
- Переиспользовать принятые классы (`mgmt-*`, `ui-*`, `table-panel`/`ctable-*`) и примитивы
  (`EmptyState`, `Skeleton`, `Money`, `CriticalActionConfirmation`, `PanelModal`), не плодить
  новые `payment-card-*`/`news-item-*`/`settings-form-grid` в этих экранах.
- **i18n честно:** все новые строки — через `@afk4/i18n`, с реальными ru/en/tg. tg — настоящий
  таджикский (гард `tg===ru`), не копия ru. Новые ключи: заголовки секций, «Приём по картам»,
  «Ограничения начисления», пример начисления, empty-states, колонки таблицы Новостей и т.п.
- Новые/переписанные CSS-классы — в существующих CSS-файлах раздела, тема-aware (light=подъём
  белой панелью + `--shadow-card`, не затемнение — см. surface-иерархию оператора), акцент emerald.

## Вне скоупа (YAGNI)

- Приём платежей через Eskhata Merchant API (отдельный отложенный эпик) — статус максимум
  «настроен · не активен», как сейчас.
- Новые бэкенд-эндпоинты, новые поля профиля клуба, серверный by-barcode и т.п.
- Полный dirty-tracking Новостей в глобальный unsaved-guard (drawer со своим save — как сейчас у
  NewsDestination `onDirtyChange(false)`), если не всплывёт дёшево.

## Порядок реализации (слайсы)

1. **Клуб** — самый маленький, обкатать язык read-only мета-строк.
2. **Лояльность** — карточки правил + пример + «Ограничения».
3. **Платёжные шлюзы** — переписать dcgate-разметку, выровнять с Eskhata.
4. **Новости** — MgmtTable + MgmtDrawer (create+edit) + подтверждение удаления.

Каждый слайс: разметка → тесты → `bun run build`. Ветка `feat/operator-management-redesign`
(текущая) или отдельная — по ходу.
