# Авто-подтверждение онлайн-броней + холд денег

**Дата:** 2026-06-18
**Область:** `src/AFK4.Platform.Api/Reservations` (бэкенд) + Customer shell (мобильный self-service) + операторский экран «Брони»
**Тип:** продуктовая фича на денежном пути (cross-module epic)
**Статус:** Slice 1 — сделано (в `main`); Slice 2 (холд) — бэклог, решения зафиксированы

## Идея (владелец, 2026-06-18)

Онлайн-бронь ставится клиентом из мобильного приложения **сразу, без подтверждения
оператором** — «свободно время → бронируй, если есть баланс». Меньше работы оператору,
больше удобства игроку. Лейн «онлайн-заявки» на операторе остаётся запасным клапаном
для спорных/недофинансированных случаев.

## Что уже было на бэке

- `CreateOnlineAsync` — самостоятельная онлайн-бронь игроком (SeatId обязателен).
- Проверка занятости уже работает: `FindConflictAsync` ловит пересечения по месту/времени
  с активными бронями **и** блокирующими сессиями; `ValidateReservationShapeAsync` — форму.
- Раньше создавалась всегда в статусе `pending` (ждала оператора). Баланс не проверялся.

## Slice 1 — СДЕЛАНО (в `main`)

`CreateOnlineAsync` авто-подтверждает онлайн-бронь (`confirmed` вместо `pending`),
**если кошелёк игрока положительный и нет долга** (`ShouldAutoConfirmOnlineAsync` через
`LedgerBalanceProjector.GetWalletSummaryAsync`); иначе остаётся `pending`. Read-only по
деньгам. Тесты: `EfReservationOnlineAutoConfirmTests` (баланс → confirmed; ноль/долг → pending).

Балансовый гейт здесь — «есть ли деньги вообще» (>0, без долга), **не** «≥ ориентир. стоимости».
Точная сумма и заморозка — это Slice 2.

## Slice 2 — ХОЛД ДЕНЕГ (бэклог, гейт на мобилку)

Модель «проверка + ХОЛД»: при брони замораживаем сумму, списываем при посадке,
авто-возвращаем при отмене/неявке.

### Зафиксированные решения владельца (2026-06-18)

1. **Сумма холда — от billing-выбора игрока в приложении.** Игрок сам выбирает тариф
   (стандартный/ночной/…) ИЛИ пакет времени (напр. пакет на 3 ч) + ПК + время; холд =
   выбранный тариф × длительность (или резерв пакет-времени). НЕ фикс-депозит, НЕ
   branch-default-тариф — точная сумма из выбора. ⇒ **бронь должна нести billing-выбор**
   (зеркало старта сессии: `tariffRuleVersionId` / `billingMode` / `tariffVersionId` /
   `playerPackageId`), а заполняет его мобильный self-service UI.
2. **No-show:** авто-возврат холда **через 15 мин после старта** брони, если игрока не
   посадили; бронь → no-show. Срок настраиваемый.
3. **Недостаток баланса:** **отклонять бронь** (hard reject), а не pending. «Бронь только
   с деньгами».

### Механика

- **Холд** = ledger-запись (`AccountType=wallet`, отрицательная, `EntryType="reservation_hold"`),
  привязанная к брони. Привязка: добавить `ReservationId` на `LedgerEntryEntity` (миграция)
  ИЛИ через `Reason`. Релиз — обратная запись через `ReversesLedgerEntryId`.
- **Посадка** (старт сессии у забронированного игрока): холд переходит в предоплату сессии —
  интеграция с session billing.
- **Авто-релиз по no-show** — фоновый hosted service (образец: `AutoProtectionHostedService`
  в `Sessions/`): по тайм-ауту снимает зависшие холды, помечает бронь.

### Блокер и последовательность

Холд завязан на **мобильный флоу бронирования** (пикер тарифа/пакета) — без него бронь не
несёт billing-выбора, оценивать нечего. ⇒ делать **вместе с мобильным self-service booking**
(или мобильный флоу первым), НЕ на операторе вслепую. Строить бэкенд-холд без потребителя,
который заполняет billing-выбор, — это код «в стол» + риск на денежном пути (YAGNI).

Связано с customer-shell self-service и reservations API.
