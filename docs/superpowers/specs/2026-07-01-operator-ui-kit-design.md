# Operator UI-kit: единый визуальный язык оператора

- **Дата:** 2026-07-01
- **Статус:** проектирование одобрено, готово к плану реализации
- **Ветка старта:** `feat/operator-pos-receipts-panel` (см. Открытые вопросы — возможно, новая ветка)
- **Затрагивает:** `src/AFK4.Operator.App.Web` (React + CSS), `packages/tokens`

## 1. Проблема

Экран «Клиенты» выглядит разрозненно: разные размеры, формы, active-состояния у визуально
одинаковых элементов. Причина — не десяток отдельных багов, а **отсутствие общего слоя
компонентов**. Под капотом одного экрана:

- **5 реализаций «чипа»**: `clients-segment-chip`, `clients-history-filter`,
  `client-context-chip`, `client-row-badge`, `state-flag` — три размера шрифта (10/11/12px),
  два веса, и **разные** active-состояния у segment-chip и history-filter (визуально одинаковых).
- **6+ стилей кнопок**: `clients-primary-action`, `clients-debt-action`,
  `client-detail-reservation`, ghost-ссылки и т.д.
- **4+ вида карточек**: `client-row`, `client-chip`, `client-package-row`, `clients-wallet-form`.
- **Шкалы мимо токенов**: сырые `9/7/5/3px` вперемешку с `--space-*`; литеральные `6/14/999px`
  вместо `--radius-*`; сырые `10/11/12/18px` при живой type-scale `--text-xs…2xl`; `100ms`
  вместо `--duration-*`.

При этом разделы **Касса / Карта / Брони** («эталон») выглядят цельно — они следуют единому
негласному языку (только токены; деньги/время моноширинным с `tabular-nums`; карточка = левый
цветной кант + подъём тенью на hover; состояние задаётся **цветом**, не новым классом). Клиенты
и Склад от этого языка отвалились.

Ключевой факт: во всём приложении **нет ни одного React-компонента-обёртки** для
кнопки/чипа/карточки — везде голый `<button className="pos-primary-action">` + CSS-класс. Каждый
раздел завёл свои классы (`pos-*`, `booking-*`, `clients-*`) по одним правилам, но с дублированием.

## 2. Цель и НЕ-цель

**Цель.** Извлечь язык эталона в общий переиспользуемый слой (`.ui-*` CSS + два тонких React-хелпера),
перевести на него **все** разделы оператора (слайсами), удаляя секционные дубли; Клиентов и Склад
подтянуть до уровня эталона; Клиентам заодно починить точечные UX-косяки.

**НЕ-цель.** Не редизайним эталон — Касса/Карта/Брони после миграции выглядят **как раньше** (по
сути переименование классов). Не вводим React-компоненты `<Button>/<Chip>/<Card>` (ломает идиому
проекта). Не трогаем бизнес-логику, деньги-путь, i18n-контракты.

## 3. Принятые решения (развилки)

| Развилка | Решение |
|---|---|
| **Форма примитивов** | Общие CSS-классы `.ui-*` + тонкий React только для `<Money>` и `<LedgerRow>` (там, где повторяется разметка). Совпадает с идиомой «голый элемент + класс». |
| **Радиус миграции** | Сходятся **все** разделы оператора, но **слайсами по разделу** (не один гигантский коммит). Эталон мигрируется с паритетом. |
| **Глубина по Клиентам** | Унификация стиля **+ UX-фиксы** (§7). |

## 4. Архитектура общего слоя

### 4.1 Файлы

- **`src/AFK4.Operator.App.Web/src/styles/02-ui-kit.css`** (новый) — грузится сразу после
  `01-base.css`, до секционных `06…21`. Содержит атомы `.ui-*` на чистых токенах.
  Порядок загрузки важен: секционные файлы каскадно **позже**, поэтому во время миграции их
  старые классы продолжают работать; после переезда раздела его дубли-атомы удаляются, в
  секционном файле остаётся только раскладка.
- **`src/AFK4.Operator.App.Web/src/operatorPrimitives.tsx`** (существует) — добавляем
  `<Money>` и `<LedgerRow>` рядом со `StateFlag/Skeleton/EmptyState`.
- **`packages/tokens/tokens.css`** — правок по умолчанию не требует; токенов достаточно. Если
  по ходу вскроется нехватка (напр. `--text-2xs`), добавляем точечно и фиксируем в спеке-дельте.

### 4.2 Namespace

Префикс `.ui-` — явный «общий слой», легко грепается. Существующие shared-классы без общего
префикса (`state-flag`, `panel-head`, `status-pill`) переносим под `.ui-*` по мере миграции их
потребителей (не форсированно).

## 5. Атомы (CSS)

Все атомы: только токены (`--surface-*`, `--border-*`, `--text-*`, `--accent*`, `--radius-*`,
`--space-*`, `--control-*`, `--duration-*`, `--ease-*`, `--font-mono`); никаких сырых значений.

### 5.1 `.ui-btn`

Одна кнопка вместо шести классов.

- **Варианты** (модификатор):
  - `--primary` — заливка `--accent`, текст `--text-on-accent` (из `pos-primary-action`).
  - `--secondary` — нейтральный контур: `--surface-card` + `--border-default`, текст `--text-strong`.
  - `--danger` — мягкий красный: контур `--danger-soft-border`, текст `--danger-text`, hover → фон `--danger-soft-bg`.
  - `--ghost` — как ссылка: без фона/бордера, текст `--accent-text`.
- **Размеры**: `--sm/--md/--lg` = `--control-sm/md/lg`. По умолчанию `md`.
- **Состояния (все обязательны)**: `:hover`, `:active` → `transform: scale(.98)`, `:focus-visible`
  → `--focus-ring`, `:disabled` (контур `--border-default`, фон `--surface-muted`, текст
  `--text-quaternary`), `loading` (спиннер **внутри** кнопки, ширина не прыгает).
- **Переходы**: `--duration-fast` + `--ease-out`; анимируем только `background`/`border-color`/`box-shadow`/`transform`.
- **Схлопывает**: `pos-primary-action`, `pos-secondary-action`, `booking-primary-action`,
  `clients-primary-action`, `clients-debt-action`, `client-detail-reservation`,
  `clients-wallet-correction-link`, `empty-state-action`.

### 5.2 `.ui-chip`

Один чип вместо пяти. **Одно** active-состояние на всех.

- **Роли** (модификатор):
  - `--filter` — тумблер. active = `--accent` бордер + `--surface-accent-soft` + `--accent-bright`.
    (Единая конвенция убирает расхождение segment-chip vs history-filter.)
  - `--status` — тон через переменную `--tone`: `live`(success) / `booking`(accent) / `warn`(warning)
    / `danger` / `neutral`. Заливка `*-soft-bg`, текст `*-text`, бордер `*-soft-border`.
  - `--count` — счётчик в шапке (нынешний `StateFlag`): `label` + `strong`. Опциональная точка —
    нейтральная/тональная, **не** зелёная по умолчанию.
- **Размер**: один. Высота `--control-sm`, текст `--text-xs` (11px), `--radius-pill`. Бейджи
  «Долг/Неактивен» — `.ui-chip --status` того же размера (уходит разнобой 10/11/12px).
- **Состояния**: `:hover` (бордер `--border-accent`), `:focus-visible` → `--focus-ring`, `.active`.
- **Схлопывает**: `clients-segment-chip`, `clients-history-filter`, `client-context-chip`,
  `client-row-badge`, `state-chip`, `booking-duration-quick button`, `pos-category-row button`,
  `state-flag`.

### 5.3 `.ui-card`

Одна карточка/панель.

- **База**: `--surface-card`, hairline `--border-default`, `--radius-md`, паддинг `--space-3`.
- **`--interactive`**: hover → `translateY(-2px)` + `--shadow-card` + бордер `--accent`
  (из `pos-product-card`/`seat-tile`); `:focus-visible` → `--focus-ring`.
- **Кант-состояние** через переменную `--edge` (цвет): `border-left: 3px solid var(--edge, transparent)`
  (из `booking-status-card`/`seat-tile`/`client-row`: active=`--success`, debt=`--danger`, и т.д.).
- **`--stat`**: карточка метрики (Баланс/Долг): `label` малым `--text-xs` `--text-secondary`,
  значение крупным mono. `--stat.is-danger` → тон danger.
- **Концентричность**: скругление вложенного `≤` скругления родителя.
- **Схлопывает**: `client-row`, `client-chip`, `client-package-row`, `clients-wallet-form`
  (обёртка), `pos-product-card`, `booking-status-card`, `clients-wallet-recent`.

### 5.4 `.ui-field`

Метка снаружи + контрол.

- **Метка**: persistent, над полем (`--text-xs`, `--text-secondary`). Placeholder-as-label запрещён.
- **Контрол**: высота `--control-md`, `--surface-sunken`, `--border-default`, `--radius-sm`,
  паддинг `0 var(--space-3)`. `:focus` → бордер `--accent` + `--focus-ring`.
- **Ошибка**: inline под полем, `role="alert"`, тон danger. Валидация на blur, ввод не блокируется.
  Submit не дизейблим до попытки (только на время in-flight).
- **Схлопывает**: `clients-wallet-form input`, `clients-package-select select`, поля модалок.

## 6. React-хелперы

### 6.1 `<Money value currency tone? />`

- Рендерит `<span class="ui-money">`: `--font-mono` + `font-variant-numeric: tabular-nums`.
- Формат — из const-мапы `@afk4/money` (TJS → суффикс «с.», целые, NBSP-разделитель тысяч,
  ASCII-минус для отрицательных). Значение приходит в MAJOR-единицах (конвертация minor→major —
  на границе UI, как принято в проекте).
- **Тон знака**: `--pos` (доход, `--success-text`) / `--neg` (расход, `--danger-text`) /
  нейтральный. По умолчанию — по знаку значения; можно переопределить пропом.
- **Зачем**: единая точка формата денег вместо россыпи inline-спанов; деньги становятся
  моноширинными **везде**, как в эталоне.

### 6.2 `<LedgerRow op />`

- Структура: `время(mono) · заголовок · подзаголовок · <Money> · действие(hover)`. Класс `.ui-ledger-row`.
- Действие («Вернуть») — по `:hover`/`:focus-within` строки; рендерится только для обратимых
  операций (см. §7.2).
- **Зачем**: один компонент на три места (`HistorySection`, мини-лента кошелька `WalletSection`,
  `ClientLedgerRail`) — убирает тройной дрейф верстки строки операции.

## 7. UX-фиксы Клиентов

Каждый — с критерием приёмки.

1. **Строка клиента (`ClientList`).** Справа всегда **одно** число — баланс через `<Money>`.
   Долг — маленьким `.ui-chip --status --danger` под именем (не второй цифрой стопкой).
   *Приёмка:* все строки одной высоты; у клиента с долгом справа одно число, долг виден как бейдж.
2. **«Вернуть» в истории (`HistorySection`/`LedgerRow`).** Появляется по hover/`focus-within`
   строки; показывается только у обратимых операций (у «Возврат · сторно» — нет).
   *Приёмка:* в покое колонка «Вернуть» не рябит; действие доступно с клавиатуры (focus-within);
   у сторно-строки «Вернуть» отсутствует.
3. **Счётчик «Долги» в шапке.** УЖЕ КОРРЕКТНО (правка не требуется): проверка кода
   (`BackendPlayersWorkspace.tsx:733`) показала, что счётчик тонируется `tone='warning'`
   (амбер-точка `--warning`), а не зелёным — «зелёная точка» была мисридом скриншота. Пункт
   сводится к верификации; миграция `StateFlag → .ui-chip--count` отложена в кросс-секционный
   слайс (StateFlag общий для Карты/Кассы).
   *Приёмка:* тон «Долги» = warning/danger, не accent-green (уже так).
4. **Дубль «Пакеты».** Убрать стат-карточку «Пакеты»; счётчик пакетов — бейджем на вкладку
   «Пакеты» (`.ui-chip --count` малый). Остаются Баланс + Долг; Долг тонируется danger только `>0`.
   *Приёмка:* число пакетов показано один раз (на вкладке), стат-карточек две.
5. **Формы кошелька (`WalletSection`).** Сумма — пустое поле, placeholder «0.00»; причина —
   placeholder-пример, не пред-заполненное значение.
   *Приёмка:* поля пусты при открытии; отправка пустой суммы не проходит валидацию (inline-ошибка).
6. **Иерархия кнопок кошелька.** Одна `--primary` (Пополнить); «Списать долг» — `--danger`
   поменьше; «Ручная корректировка» — `--ghost`-ссылкой или в `...`-меню (`ClientActionsMenu`).
   *Приёмка:* на панели кошелька одна заливка-кнопка; вторичные визуально тише.

## 8. Дисциплина шкал (инвариант мигрированного кода)

- **Типографика**: только `--text-xs/sm/base/lg/xl/2xl`. Кластер 10/11/12 → **xs(11) + sm(13)**,
  акцент весом (700), не размером. Крупные суммы — `--text-xl/2xl` mono.
- **Отступы** → `--space-*` (никаких 9/7/5/3px).
- **Скругления** → `--radius-*` (никаких литеральных 6/14/999).
- **Motion** → `--duration-*` / `--ease-*` (никаких `100ms`/`120ms` литералов).
- **Деньги/время/количества** → `--font-mono` + `tabular-nums` (через `<Money>` или класс).

## 10. Тестирование и верификация

- **Юнит/DOM**: `bun test` по затронутым разделам (happy-dom + jest-dom); `App.test` отдельным
  прогоном. Проверяем: наличие интерактивных состояний, отсутствие пропавших действий,

- **Сборка**: `bun run build` (`tsc -b && vite`) — гейт каждого слайса.
- **Визуальный паритет эталона (S3–S5)**: live-превью WPF (skill `operator-wpf-preview`,
  `bun run dev` mock) — глазами сверяем, что Касса/Карта/Брони не изменились.
- **Опционально**: guard-тест, что секционные CSS-файлы не переопределяют атомы (после миграции
  раздела в его файле не должно оставаться дублей `*-primary-action` / `*-chip`). Решение —
  на этапе плана.

## 11. Риски

- **Регрессии в эталоне (S3–S5).** Митигируется паритет-подходом (атомы извлекаются **из**
  эталонных конвенций, поэтому после переименования вид тот же) + live-превью-сверкой.
- **Каскад/специфичность.** `02-ui-kit.css` грузится раньше секционных → во время миграции
  старые классы выигрывают, поломки нет; удаление дублей — только после переезда раздела.
- **Расхождение `.ui-btn` vs `pos-*` в переходный период.** Сходящееся дублирование (все едут в
  одну сторону), трекается слайсами S3–S5; не оставляем висеть бессрочно.
- **Размер эпика.** Шесть слайсов; риск «застрять на S3+». Митигируется тем, что видимая ценность
  (Клиенты) уезжает уже в S1 — остальное можно докатывать в фоне.
