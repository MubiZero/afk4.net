# «Платежи и лояльность» — один экран «деньги ↔ игрок» без табов

Дата: 2026-07-21
Ветка: `feat/operator-payments-loyalty-onepage`
Часть эпика: «Оператор = единая админка», под-проект 3 (после Клуба).
Статус: дизайн одобрен пользователем в brainstorming → реализация.
Опирается на решения: `2026-07-20-operator-club-payments-rethink-decisions.md` (§Под-проект 3).

## 1. Цель

Сейчас раздел «Платежи и лояльность» — это два несвязанных таба (Шлюзы | Лояльность),
склеенных таб-стрипом. Табы появились как костыль вокруг конфликта двух save-моделей:
шлюзы работают на мгновенных действиях (свои кнопки), а лояльность висела на глобальном
save-баре `ManagementScreen`. Цель — **убрать табы** и собрать одну связную страницу
«деньги ↔ игрок», где каждая секция сохраняется сама.

Задача чисто фронтовая: **бэкенд не трогаем**. Eskhata-сущность/эндпоинт, loyalty-эндпоинт
и dcgate уже в main; онлайн money-path заморожен внешним bank-bot. Новых миграций нет.

## 2. Раскладка

Одна колонка, `contentWidth="wide"` (картам dcgate нужно место), **без** глобального
save-бара. Две озаглавленные зоны (заголовок через существующий `.mgmt-section-title`):

**Зона 1 — «Как игрок платит вам»** — гейт `managePaymentGateways`.
- **Перевод на карту** — `PaymentGatewaysWorkspace` (карты dcgate + привязка Telegram).
  Модель мгновенных действий, свои кнопки.
- **Онлайн-оплата Eskhata** — `EskhataGatewayForm`. Свой «Сохранить» + статус-чип
  «настроен · не активен».

**Зона 2 — «Как вы возвращаете»** — гейт `manageLoyaltySettings`.
- Правила кэшбэка (3 карточки) + лимиты — как сейчас, но с **собственной секционной
  кнопкой «Сохранить»** (дизейбл пока `!dirty`, busy при сохранении). `useLoyaltySettings`
  уже отдаёт `save/saveState/dirty/disabled` — подключаем к кнопке.

Нет права на зону → зоны нет (посекционная изоляция, без пустых блоков и размытия прав).
Если у сессии оба права — обе зоны стопкой; если одно — только своя зона.

Наличные **не показываем**: у них нет ничего для настройки, экран — конфигурация онлайн-
способов + лояльность. Приём наличных живёт в Кассе.

## 3. Save-модель

Табов нет; каждая секция самодостаточна:
- dcgate — мгновенные действия (без изменений);
- Eskhata — свой save (без изменений);
- Лояльность — свой section-save (перенос с глобального save-бара на кнопку внутри секции).

`loyalty.dirty → onDirtyChange` сохраняем — гард «несохранённые изменения» при уходе с
раздела продолжает работать.

## 6. Тесты + гейт

Фронт (`bun test`, happy-dom):
- `PaymentsLoyaltyDestination`: обе зоны при обоих правах; только зона шлюзов при
  `managePaymentGateways`; только зона лояльности при `manageLoyaltySettings`; **нет** таб-стрипа;
  **нет** глобального save-бара; кнопка сохранения лояльности дизейблится/включается по dirty.
- `LoyaltySection`: сохранение процентов в bps через свою кнопку (перенос существующих тестов
  лояльности), отсутствие preview.
- Обновить/переименовать существующие тесты под новые имена компонентов.

Полный гейт: `bun test` (оператор) + `bun run build` (`tsc -b` тайпчекает и тест-файлы) +
i18n `bun test`. Бэкенд-тесты не затрагиваются (кода бэка не меняем), но прогнать сборку
затронутых фронт-пакетов обязательно. App.test — id `payments` уже существует, сверить зелёный.

**Гейт слияния:** визуальная приёмка пользователем (как по всей ветке эпика).
