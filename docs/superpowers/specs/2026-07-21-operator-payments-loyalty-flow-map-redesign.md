# Платежи и лояльность — переосмысление как «карта потока денег»

**Дата:** 2026-07-21
**Экран:** Оператор → Управление → Платежи и лояльность
**Статус:** дизайн-спека (ждёт ревью пользователя → writing-plans)

## Проблема

Экран остаётся «страницей настроек» (панели + формы), даже после инкрементального редизайна
(полоса + зоны). Пользователь отверг это: нужно ПЕРЕОСМЫСЛИТЬ, не держась за нынешний UI/UX, и
говорить визуальным языком любимых рабочих вкладок — **Карта / Касса / Брони**.

Направление выбрано по двум макетам-концептам (`scratchpad/concept-{a,b}.html`): **каркас B**
(карта потока, язык Карты) **+ живой калькулятор экономики из A** в панели кэшбэк-станции.

## Что строим (метафора)

Экран — это карта одного маршрута денег, а не список форм:

```
Игрок → Способы приёма (dcgate-карты, Eskhata) → Клуб (хаб) → Кэшбэк-правила → обратно Игроку
```

- Холст (`.flow-canvas`, идиом `.map-board`) со схемой потока: узел «Игрок», хаб «Клуб» (с цифрой
  «принято сегодня»), кластер приёма (станции-карты + Eskhata), кластер возврата (3 кэшбэк-правила
  + лимиты), и пунктирная дуга-петля возврата от кэшбэка к игроку.
- Каждый способ приёма и каждое правило — **станция** (карточка-плитка, идиом `.seat-tile`):
  точка-статус + название + чип состояния, кликается.
- Клик по станции → её конфигурация в **правой панели** (идиом `MapSidePanel`: hero-заголовок +
  секции). Панель всегда показывает одну вещь — экран не разрастается формами.
- Тот же жест, что оператор уже знает по Карте: «кликнул объект на холсте → детали справа».

## Ключевое решение: живой калькулятор экономики (из A)

При выборе кэшбэк-станции панель справа показывает не просто «тумблер + процент», а **живой
предпросмотр возврата**: ползунок «игрок пополняет N с.» + пересчёт «вернётся игроку кэшбэком Y с.»
и «эффективная ставка Y/N %», с учётом потолка за операцию и минимальной суммы. Двигаешь процент/
лимит/сумму — числа меняются мгновенно, до «Сохранить».

**Честность (рабочий стиль #37):** НЕ показываем «маржу клуба» — у нас нет данных о себестоимости,
это было бы выдуманное число. Показываем только то, что реально считается из настроек: сумму
возврата игроку и эффективную ставку. Логика лимитов настоящая (капается кэшбэк, ниже минимума —
ноль), а не декоративная.

## Границы (что НЕ трогаем)

- Бэкенд, контракты, миграции, money-path — без изменений. Переиспользуем существующие клиенты и
  хук `useLoyaltySettings`, эндпоинты dcgate/Eskhata/loyalty как есть.
- Гейтинг по правам без изменений: нет `managePaymentGateways` → кластер приёма скрыт; нет
  `manageLoyaltySettings` → кластер возврата скрыт (нет права — нет части схемы).
- Money-конвенция как в проекте: суммы белые (`--text-primary`), жёлтый только под warning.

## Архитектура компонентов

Каталог `management/destinations/payments/flow/`:

- **`PaymentsFlowDestination`** (замена нынешнего `PaymentsLoyaltyDestination`): держит выбранную
  станцию (`selectedStationId`), собирает данные обеих зон, рендерит холст + панель. Рендерится в
  `ManagementScreen` с `contentWidth="full"` (нужен весь workspace), внутри — master(холст)/
  detail(панель) грид как у `MapWorkspace`.
- **`FlowCanvas`** — узлы (Игрок, Клуб-хаб) + два кластера станций + дуга-петля (inline SVG).
  Чистая презентация: получает станции + `onSelect`.
- **`FlowStation`** — плитка станции (статус-точка + имя + чип). `is-selected` = кольцо подсветки
  цветом состояния (идиом `.seat-tile.is-selected`).
- **`FlowPanel`** — правая панель; по типу выбранной станции рендерит нужный конфиг:
  - карта dcgate → детали (маскированный PAN, охват, статус, здоровье Telegram, последнее
    сообщение) + действия (отключить с подтверждением; поток привязки телефон→код→пароль).
  - станция «добавить карту» → форма провижена (номер + охват).
  - Eskhata → форма реквизитов (baseUrl/companyId/posId/hashKey), статус «настроен · не активен».
  - кэшбэк-правило → тумблер + процент + **`EconomicsPreview`** (живой калькулятор) + лимиты.
  - хаб «Клуб» → обзор (принято сегодня, сводка состояния).
- **`EconomicsPreview`** — чистая функция/компонент: вход (сумма, проценты правил, потолок,
  минимум) → выход (возврат игроку, эффективная ставка). Юнит-тестируемо в изоляции.
- **`useGateways`** — извлекается из монолитного `PaymentGatewaysWorkspace` (техдолг: сейчас
  список + провижен + отключение + attach-flow + статусы живут одним куском). Холсту нужен список
  для станций, панели — состояние выбранной + действия. Хук владеет данными и действиями, оба
  консьюмера делят его. `PaymentGatewaysWorkspace` после этого либо удаляется (единственный
  консьюмер — этот экран), либо становится тонкой обёрткой над хуком. Проверить отсутствие других
  импортов перед удалением.

## Состояния (per-zone независимость сохранена)

`PaymentsLoyaltyDestination` уже грузит каждую зону отдельно — делаем это ВИДИМЫМ:

- **Загрузка**: скелетон-силуэт схемы (узлы/кластеры как shimmer той же геометрии, что готовая
  схема) — контент не прыгает. Идиом `.management-skeleton-line`, задержка 200ms.
- **Пусто** (новый филиал): 0 карт → пунктирная станция «Добавить карту» с подсказкой прямо в
  кластере; кэшбэк выключен. Ничего не подделано зелёным — честно видно, что настраивать нечего.
- **Ошибка**: падает ТОЛЬКО зона приёма (баннер + «Повторить»), зона возврата рядом работает — и
  наоборот. Отражает реальную архитектуру (`PaymentsLoyaltyDestination.tsx:13-17`).

## Переиспользование стилей флагманских вкладок

Новый файл `styles/24-payments-flow.css` (не пухнуть в 15-settings). Мироринг идиом (свои классы
`payments-flow-*`, значения из `@afk4/tokens`):
- `.seat-tile` / `.seat-tile.is-selected` (`06-map-grid.css`) → станция + выделение.
- `.map-board` inset-текстура (`06-map-grid.css`) → холст.
- `.seat-hero` + `.context-section` / `.detail-row` (`07-map-sidepanel.css`, `06-map-grid.css`) →
  hero и секции правой панели.
- `RuleCard` тумблер+процент+пример (`LoyaltySection.tsx`) → конфиг кэшбэк-станции.
- `.ui-chip--status.is-live/.is-warning/.is-neutral` → статус-чипы станций.
- Дуга-петля — новый элемент (прямого аналога нет), но акцентный цвет + dash-анимация как у
  «в ожидании» на карте/бронях. Уважать `prefers-reduced-motion` (гасить бег пунктира).

## Тесты (bun test + build)

- `EconomicsPreview` — чистые юнит-тесты формулы: капирование, порог минимума, ноль-процент,
