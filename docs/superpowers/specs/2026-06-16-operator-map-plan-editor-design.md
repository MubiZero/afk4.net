# Operator «Карта» — вид «План» вместо «Списка» + редактор расстановки (B2)

**Дата:** 2026-06-16
**Эпик:** Operator App «Карта», Этап 1. Завершает кусок **B2** (и тянет за собой полную
**B1-геометрию** как бэкенд-основу).
**Контекст:** командный центр карты (A1–A3) и данные B1 уже в `main`. См.
`2026-06-15-operator-map-design.md` (исходная декомпозиция) и память `afk4-operator-map-epic`.

---

## Суть и решение

Текущая Карта имеет два вида: **Сетка** (плитки, сгруппированы по залам) и **Таблица** (плоский
несортируемый список тех же мест текстом в 7 колонках). Таблица низкоценна: ни сортировки, ни данных,
которых нет в Сетке; половина её колонок (Устройство/Команда/Биллинг) — ровно тот тех-шум, что A1
убрал с плиток, а полную детализацию по месту даёт правая панель.

**Решение:** заменить вид «Таблица» на вид **«План»** — реальную top-down планировку зала с живыми
статусами и встроенным режимом редактирования расстановки. Это возврат к исходному решению Этапа 0
«Сетка · План (без Оба)».

**Виды после B2:** `Сетка · План`.
- **Сетка** — без изменений: абстрактный грид, сгруппированный по залам, работает **всегда** (без
  координат). Дефолт и фолбэк. Координаты в Сетку НЕ тащим — пространство живёт только в Плане
  (иначе дубль).
- **План** — единственный координатный вид. Два состояния: **смотреть** (все, право `floor_map.view`)
  и **править** (право `layout.manage`, есть у `branch_manager`).

**Рендер:** плоский **top-down** (не изометрия). Модель данных одинакова для top-down и изо — изо
остаётся возможной косметикой потом, без переделки данных.

**В объёме B2:** места + зоны + **стены** (полная B1-геометрия).

**Вне объёма (YAGNI):** изо-перспектива; мультивыделение/группировка элементов; история отмены (undo).
Первая версия — базовый drag + инспектор + сохранение черновика одной транзакцией.

## Бэкенд (B1-геометрия)

**Сущности** (`src/AFK4.Platform.Api/Data/Entities/`):
- `SeatEntity` +=
  - `PosX int?`, `PosY int?` — ячейка сетки (целые, снап бесплатный);
  - `Rotation int` (default `0`; значения 0/90/180/270);
  - `SeatType string` (default `"pc"`; `pc/console/vr/sim/billiard/boardgame/counter`).
- `ZoneEntity` +=
  - `GeoX/GeoY/GeoWidth/GeoHeight int?` — прямоугольник зоны в ячейках;
  - `Color string?` (токен/hex), `ZoneType string?`
    (`reception/wardrobe/wc/lounge/bar/kitchen/hall`).
- `WallEntity` (новая): `WallId, OrganizationId, BranchId, X1, Y1, X2, Y2, CreatedAtUtc` — отрезок
  стены между узлами сетки. Скоуп тенанта как у Seat/Zone (`OrganizationId + BranchId`).

**Контракты:**
- `SeatStatusDto` += `PosX, PosY, Rotation, SeatType`.
- `FloorMapDto` += геометрия зон (`GeoX/GeoY/GeoWidth/GeoHeight/Color/ZoneType`) + список стен.
- Все новые поля nullable / с дефолтами → старые клубы читаются без раскладки, фронт уходит в фолбэк.

**Сохранение раскладки:** расширяем существующие `FloorMapBulkUpdateRequest` +
`EfFloorMapEditService` (НЕ новые эндпоинты): позиции мест, геометрия/тип/цвет зон,
добавление/удаление стен — **одной транзакцией**. Редактор шлёт всю раскладку разом по «Сохранить»,
а не по каждому drag.

**Миграция:** EF Core / PostgreSQL, `src/AFK4.Platform.Api/Data/Migrations/`. Аддитивна (всё
nullable/default) → существующие данные не ломает.
- ⚠️ `dotnet ef` на Linux капризен — генерация по проверенному рецепту (память `afk4-env-quirks`).
- ⚠️ Coolify-workflow **блокирует мерж** коммитов, трогающих `Data/Migrations/**`, пока миграцию не
  применят к staging-БД вручную и не вызовут `workflow_dispatch` с
  `confirm_migrations_applied=true`. Тот же рунбук, что отработал на `AddSessionBillingMode`.
  Заложено явным шагом деплоя в плане.

**Тесты бэка:** контракт-тесты сериализации новых полей DTO; `EfFloorMapEditService` — сохранение и
чтение полной раскладки (места+зоны+стены) и тенант-изоляция стен.

## Фронт: архитектура и координаты

**Система координат (одна на всё):** раскладка в целочисленных ячейках (`PosX/PosY`). Модуль
`floorPlanGeometry.ts` (чистые функции): `cellSize` (px), `cellToPx(x,y)`, `pxToCell(px,py)` (снап
при drag), `boundingBox(elements)` (границы холста = bbox всех элементов + поля). Pan/zoom — через
`transform: translate() scale()` на обёртке холста (зум колесом/кнопками, пан — drag по пустому/
средней кнопкой). SVG-слой и DOM-слой живут в одной обёртке → одна система координат на оба.

**Рендер — гибрид (подход A):** SVG-подложка рисует сетку, зоны (rect+label) и стены (line); поверх —
DOM-слой мест (`PlanSeat`, абсолютное позиционирование, переиспользует визуальный язык `SeatTile`:
статус-полоса/чип/иконка). Так зоны/стены — векторные «из коробки», а места бесплатно получают
статус-язык, доступность (клавиатура/screen-reader) и hover/focus. Canvas прибережён на случай тысяч
мест (не наш масштаб).

**Новые файлы** (рядом с `MapWorkspace.tsx`, дробим по ответственности):
- `floorPlanGeometry.ts` — координаты/снап/bbox (юнит-тестируемо).
- `floorPlanState.ts` — типы раскладки (`PlanSeat/PlanZone/Wall`), маппинг DTO→состояние,
  нормализация черновика → `FloorMapBulkUpdateRequest`.
- `FloorPlan.tsx` — холст-вид: обёртка pan/zoom, SVG-подложка + DOM-слой мест. Props: `seats`,
  `zones`, `walls`, `mode: 'view'|'edit'`, колбэки. В `view` клик по месту → `onSelectSeat`.
- `PlanSeat` (в `FloorPlan` или отдельным файлом) — место на холсте, визуальный язык `SeatTile`.
- `FloorPlanEditor.tsx` — обёртка режима правки: палитра + холст(`mode=edit`) + инспектор + панель
  «Сохранить/Отмена». Держит локальный `draft` раскладки.
- `FloorPalette.tsx` — палитра элементов.
- `FloorInspector.tsx` — инспектор выбранного элемента.

**Переиспользуем (не пишем заново):** тон/статус — `floorMapState.ts` (`resolveTone`,
`seatStatusLabel`); деньги — `formatMinorUnits`/`currencySymbol`; зоны-подписи — `zoneLabel`; права —
`operatorPermissions`; примитивы `Skeleton`/`EmptyState`/`Toast`/`ActionFeedback`; селекты —
`PanelSelect`; i18n — `@afk4/i18n` (ru/en/tg), новые ключи `op.map.plan.*`.

**Правки `MapWorkspace.tsx` (точечно):** `MapViewMode` `'grid'|'table'` → `'grid'|'plan'`; ветка
`table` в рендере → `<FloorPlan>` / `<FloorPlanEditor>`; переключатель видов и i18n; удаление Таблицы
(разметка `.seat-table*`, ключи `op.map.colPc/colState/colPlayer/colRemaining/colDevice/colCommand/
colBilling`, `op.map.viewTable`, `op.map.tableLabel`). В просмотре Плана правый `MapSidePanel`
работает ровно как в Сетке.

## Режим редактирования

**Вход/выход:** на Плане кнопка «Редактировать» видна только при праве `layout.manage`. Вход →
экран перестраивается: **слева палитра, по центру холст (`mode=edit`), справа инспектор**. Живые
статусы на время правки замораживаются (правим раскладку, не мониторим). Выход:
- «Сохранить» → `FloorMapBulkUpdateRequest` одной транзакцией → возврат в живой просмотр;
- «Отмена» → сброс черновика (при несохранённых правках — подтверждение).

**Черновик:** все правки в локальный `draft` (в `FloorPlanEditor`); бэкенд не дёргаем на каждый
drag — только по «Сохранить». Это и даёт дешёвую отмену.

**Палитра (`FloorPalette`):**
- **Места** по типам — но только из **уже существующих** мест зала, ещё не размещённых (без
  координат). Палитра НЕ создаёт места из воздуха (места заводятся в setup-wizard) — расставляет
  имеющиеся. Неразмещённые показываются стопкой «ещё не на плане».
- **Зона** — добавить прямоугольник-зону (тянешь рамку на холсте).
- **Стена** — режим рисования: клик-клик по узлам сетки = отрезок.

**Холст в правке:** drag места → снап в ячейку; drag зоны → перенос, ручки по углам → ресайз; стены
— добавление/удаление кликом. Клик по элементу = выбор → инспектор. Клик по пустому = снять выделение.

**Инспектор (`FloorInspector`)** — свойства выбранного:
- *Место:* тип (`PanelSelect`), поворот (0/90/180/270, кнопки-стрелки), привязка к зоне (авто по
  попаданию в прямоугольник зоны — показываем какая), «убрать с плана» (вернуть в стопку).
- *Зона:* имя, цвет (палитра токенов), тип, удалить.
- *Стена:* удалить (геометрия задаётся рисованием).

## Состояния, ошибки, масштаб

- **Загрузка** раскладки → скелет холста (не спиннер-флеш).
- **Нет раскладки** → `EmptyState` «Зал ещё не размечен» + кнопка «Разметить план» (только при
  `layout.manage`; без права — текст «обратитесь к менеджеру»).
- **Нет права на правку** → кнопки «Редактировать» нет; холст только на просмотр.
- **Сохранение упало** → ошибка остаётся текстом с конкретикой от бэка; черновик НЕ теряем (можно
  повторить «Сохранить»). Успех → визуальный feedback (`ActionFeedback`) + возврат в просмотр.
- **Несохранённый черновик** + «Отмена»/уход → подтверждение.
- **Конфликт координат** (два места в одну ячейку) → снап не даёт наложить: занятая ячейка
  подсвечивается, дроп отклоняется.
- **Масштаб входных данных:** 0 мест → пустой холст-приглашение; 1 и 500+ — оба валидны (скролл/зум,
  ничего не сжимаем); место без координат → стопка «не на плане», не теряется.
