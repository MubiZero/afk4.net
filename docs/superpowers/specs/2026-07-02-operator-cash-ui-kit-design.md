# Operator UI-kit — S3 «Касса»: дизайн паритет-миграции (реконсиляция атома)

**Статус:** одобрена стратегия «Реконсиляция атома».
**Родительский эпик:** [`2026-07-01-operator-ui-kit-design.md`](2026-07-01-operator-ui-kit-design.md)
(§9 слайс S3 «Касса: переезд, удаление `pos-*` дублей»). Предыдущие слайсы: S1 Клиенты, S2 Склад
(в main).

## 1. Контекст и находка

Касса — эталонный (нравящийся) раздел; атомы `.ui-*` были извлечены ИЗ него в S0, но **слегка
причёсаны/усреднены**. Разведка вскрыла ~9 расхождений атома с фактическим видом Кассы. Т.к. Касса
нравится, цель S3 — **визуальный паритет** (не сломать вид), заодно убрав дубли `pos-*`/`cash-*`.

**Стратегия (одобрена): реконсиляция атома.** Где эталон = «как надо», подтягиваем ОБЩИЙ атом под
него (правильный модификатор / новый аддитивный вариант), сохраняя вид Кассы 1:1 и делая атом лучше
для всех. Где расхождение микроскопично — принимаем значение атома (не плодим оверрайд). Где структура
реально специфична — оставляем тонкий cash-слой. Кросс-секционное — не трогаем (отдельный слайс).

**Ключевой факт:** реконсиляция выходит **почти полностью аддитивной** (новые варианты/модификаторы,
не правка существующих правил) → уже сделанные Клиенты/Склад почти не затрагиваются. Единственная
проверка регресса — пере-прогон превью Клиентов/Склада после атом-правок (ожидаемо чисто).

## 3. Деньги → `<Money>`

Все `formatMoney(value, currencyCode)` в Кассе (38 мест: CashShiftHeader ×2, CashShiftWorkspace ×21,
ShiftReportModal ×7, CashOperationsLedger ×4, CashReceiptsLedger ×4) → `<Money minorUnits currencyCode>`
(+ `signed` для движений/разниц в леджерах). Значения приходят как объекты `{minorUnits}` либо число —
на границе подставляем `.minorUnits`. Логику `cashModel.ts`/`shiftReport.ts` НЕ трогаем (money-path FROZEN).

**Герой-числа** (`.cash-shift-hero`/`-block`, mono + `--text-xl` + тон attention/ok/muted): оставить
класс-обёртку для размера/тона, внутрь — `<Money>` (как `<strong><Money/></strong>` в стат-карточках).
`.cash-shift-hero` — дубль `.ui-money` по mono/tabular; после переезда его mono/tabular убрать (наследует
от `<Money>`), оставить только размер/тон.

## 4. Изменения общих атомов (все аддитивные)

Единственные правки `02-ui-kit.css` — ADDITIVE (не меняют существующие правила → Клиенты/Склад целы):
- **`.ui-card--elevated`** — `background: var(--surface-elevated); box-shadow: var(--shadow-card);`
  (для `.cash-shift-card`). Reserved-комментарий обновить.
- Проверить, что `.ui-btn--lg` даёт паритет GO (height control-lg — да; uppercase — если нужен, POS-правило).
- Тона денег (`--pos/--neg/--muted`) — уже есть, новых не нужно.
Новый `.ui-btn--secondary` НЕ заводим (pos-secondary маппится на базовый `.ui-btn`, YAGNI).

## 5. НЕ трогаем в S3 (кросс-секционное — отдельный слайс)

- `.cash-tab`/`.cash-tabs` — общий таб-бар (используется и Складом). Остаётся.
- `.critical-confirmation-actions` — общая обёртка подтверждений (модалки Карты). Кнопки модалок Кассы
  внутри неё — как в S2: не мигрируем на `.ui-btn` в этом слайсе.
- `StateFlag`/`.state-flag` — общий с Картой; `→ .ui-chip--count` откладываем.

## 6. Приёмка и гейт

- **Визуальный паритет** — главный критерий. Проверяется live-превью Кассы (POS/Смена/Журнал) до мержа;
  вид не должен измениться, кроме принятых микросдвигов (#6 −1px hover, #7 +4px padding) и осознанной
  миграции ленты (#8) — их владелец подтверждает на превью.
- **Регресс-гейт Клиентов/Склада**: после атом-правок пере-глянуть Клиентов и Склад на превью (ожидаемо
  без изменений — правки аддитивные).
- **Тесты**: `bun test` (вся сюита) + отдельный `App.test` + `bun run build` зелёные. Тесты Кассы
  ассертят по роли/тексту (не по классам) — миграция классов их не ломает; `App.test` завязан на
  `.pos-orders-ticker`/`.pos-embed`/`.cash-shift-exports` — эти классы сохранить (структурные).
- **i18n**: только существующие ключи `op.cash.*`; хардкод-строк не добавляем.
- **Money-path FROZEN**: только рендер денег меняется.

## 7. Декомпозиция (для плана)

Крупный раздел → слайсами-задачами: (0) атом `.ui-card--elevated` + проверка `--lg`; (1) POS
(`BackendPosWorkspace`: GO/secondary кнопки, категории→`.ui-chip--filter`, product-card, поиск, деньги,
чек-строки); (2) Смена (`CashShiftWorkspace`/`Header`/`CommandBar`: карточки→`.ui-card--elevated`, герои
+`<Money>`, командные кнопки); (3) Журнал/леджеры (`CashOperationsLedger`/`CashReceiptsLedger`/
`CashJournalWorkspace`: лента→`.ui-ledger-*`, деньги signed); (4) Модалки (`Open/Close/Movement/Report`:
поля→`.ui-field`, submit→`.ui-btn--primary`); (5) финальная чистка `11-pos.css`/`21-cash.css` от дублей +
токен-нормализация + гейт + регресс-глянец Клиентов/Склада.

## 8. Риски

- **Регресс любимого вида** — главный. Митигируется реконсиляцией (атом под эталон) + live-превью до мержа.
- **Каскад-ловушка** (как в S2): оставленные контейнеры (`.pos-category-row`, `.cash-*`) с тег-селекторами
  `.X button` перебивают атомы — в чистке сносить дочерние правила мигрированных элементов.
- **Ледж-миграция (#8)** меняет раскладку журнала Кассы — единственное намеренное визуальное изменение;
  подтверждается на превью (или откат к тонкому 4-кол. слою, если владельцу не зайдёт).
- **Атом-правки → Клиенты/Склад**: минимизировано аддитивностью; обязательный регресс-глянец на превью.
