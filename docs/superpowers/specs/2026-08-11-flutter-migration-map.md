# Карта функциональности для переезда на Flutter

Дата: 2026-08-11. Первый шаг плана миграции: инвентаризация того, что переезжает,
что отмирает по дороге и какие правила поведения обязаны выжить.

Решение принято: стек становится **C# (сервер, служба агента, установщик) + Flutter (все
интерфейсы)**. TypeScript и WPF уходят. Этот документ — не план работ, а его основание:
перечень предмета миграции.

## 1. Предмет миграции

| Приложение | Строк | Файлов тестов | Куда едет | Пригодность Flutter |
|---|---:|---:|---|---|
| Оператор (админка клуба) | 32 700 | 168 | Android, iOS, Windows | отличная |
| Platform Control (админка платформы) | 10 300 | 71 | браузер | **под вопросом** |
| Клиентское | 1 900 | 23 | Android, iOS | отличная |
| Оболочка игрового ПК (веб-часть) | 1 200 | 17 | Windows-киоск | требует проверки |
| Мастер установки (веб-часть) | 2 000 | 3 | Windows-установка | **узкое место** |
| Общие пакеты: kit, токены, локализация, деньги, форматирование | 8 600 | 5 | общий Dart-слой | отличная |
| **Итого** | **~57 000** | **287** | | |

Плюс три WPF-хоста: Оператор, Оболочка игрового ПК, Мастер установки — они исчезают целиком,
их роль берёт на себя Flutter-приложение под Windows.

Остаётся на C# без изменений: серверное API, служба агента (блокировка рабочей станции,
grace-режим, офлайн-аренда времени), контракты, ядро мастера установки, публикация обновлений,
сидер данных.

### Главный вывод инвентаризации

Восемь приложений **не одинаково пригодны** к переезду, и цель «ровно два языка» упирается в два
из них.

**Platform Control живёт в браузере.** Это внутренняя админка платформы: таблицы, формы, фильтры,
много текстового ввода. Flutter Web для такого — слабое место фреймворка: тяжёлая первая
загрузка, худшая работа с текстовыми полями и вспомогательными технологиями. Варианты: смириться,
сделать её настольным приложением, или оставить на React. Последнее означает, что TypeScript из
проекта не уходит и цель двух языков не достигнута.

**Мастер установки — узкое место.** Он ставится на чистую машину установщиком, который сегодня
несёт с собой .NET. У Flutter другой рантайм; установщик придётся пересобирать, а это самый
выстраданный кусок проекта (перенос вместо докачки, история с кодом ошибки 1053, сборка строго
на новом PowerShell). Рекомендация: переносить его **последним**, когда конвейер Flutter уже
отлажен на остальных.

## 2. Карта Оператора

Восемь разделов. В скобках — что внутри.

**Карта зала.** Сетка мест, состояние каждого, боковая карточка места с действиями (запуск,
продление, завершение, управление ПК). Только сетка — вид «План» удалён и не воскрешать.

**Касса.** Три вкладки: продажи (кассовый терминал плюс заказы из оболочки игрового ПК),
смена (открытие, закрытие, движения наличных, сверка), журнал (операции, чеки, одобрения).

**Брони.** Лента времени, ящик брони, подбор клиента, полоса заявок на бронь.

**Клиенты.** Таблица плюс выдвижной ящик: профиль, кошелёк (пополнение, погашение долга,
корректировка, возврат), пакеты времени, история, ПИН, деактивация.

**Склад.** Остатки, приёмка, журнал движений, инвентаризация, штрихкоды.

**Отчёты.** Свод, смены и касса, выручка. Диапазон дат, выгрузка CSV.

**Управление.** Семь направлений: клуб (профиль филиала), залы и устройства, товары, тарифы и
пакеты, платежи и лояльность, сотрудники и роли, новости.

**Сеть.** Филиалы (свод по сети), подписка (только чтение), установка устройств, журнал аудита
организации, обновления.

Доменных клиентов API — 30 штук; они и есть готовая нарезка Flutter-приложения по функциям.

## 3. Карта остальных приложений

**Клиентское:** вход, главная, кошелёк, покупки, брони, история, профиль.

**Оболочка игрового ПК:** вход, активная сессия, продление, пополнение, магазин, заказы,
лояльность, новости, экран блокировки, меню самообслуживания.

**Мастер установки:** вход по телефону, восстановление пароля, выбор филиала, выбор роли,
регистрация устройства, финальный экран.

**Platform Control:** организации (паспорт клуба, вкладки), биллинг (тарифы, подписки, счета,
задолженность), здоровье и инциденты, оповещения, аналитика, лимиты, фичи, роли, анонсы,
офбординг, обновления, настройки, двухфакторная аутентификация.

## 4. Правила поведения, которые обязаны выжить

Это самая ценная часть карты. В React они закреплены тестами, которые в Dart не поедут; если их
не выписать, они останутся только в памяти проекта. Каждое правило при переносе обязано получить
тест на новой стороне — иначе оно потеряно.

**Деньги.**
- Суммы в контрактах — в минорных единицах; форматирование ждёт мажорные. Перевод делается ровно
  на границе интерфейса, иначе получаются суммы в сто раз больше.
- Валюта TJS отображается как «с.», целыми, разделитель тысяч — неразрывный пробел, минус — ASCII.
- Защита денежных операций стоит **в двух слоях**: на пяти клиентских эндпоинтах и в исполнителе
  отложенных действий. Один слой обходится через очередь одобрений.
- Долг — не поле, а виртуальный счёт, вычисляемый из книги операций.
- Онлайн-пополнение зачисляется вне смены (смена не указывается) — иначе ломается сверка кассы.
- При отказе в доступе показывать «неизвестно», а не «долгов нет».

**Склад.**
- Себестоимость средневзвешенная и пересчитывается **только при закупке**, никогда при
  корректировке.
- Остаток — сумма движений, а не хранимое поле.
- Инвентаризация: скан находит строку и ставит на неё фокус, а не увеличивает счётчик на единицу;
  проведение создаёт идемпотентные корректировки на разницу и защищено от двойного проведения.
- Поиск по штрихкоду — клиентский; серверного поиска по штрихкоду нет.
- Порог «мало осталось» задаётся на товар; ноль означает «не предупреждать».

**Время и филиалы.**
- Сутки считаются по часовому поясу филиала, а не сервера.
- Связь клуба трёхзначна: «нет данных» — это не «нет связи».

**Доступ.**
- Организационные эндпоинты защищены от подмены чужого идентификатора через контекст сотрудника.
- Телефон — глобальный идентификатор входа; вход разрешает имя, почту и подтверждённый телефон.
- Восстановление пароля всегда отвечает успехом, чтобы нельзя было перебрать существующие учётки.
- Журнал аудита режется по действующему лицу.

**Текст и локализация.**
- Три языка: русский, английский, таджикский. Таджикский не должен совпадать с русским (кроме
  оговорённых заимствований) — это охраняется тестом.
- Множественные числа — через ICU с первой строки, без ручной склейки обрывков.
- Данные карты зала хранят английские токены и локализуются при отрисовке.
- Термины: счёт (не инвойс), место, ПК, клуб, филиал, сеть.

**Правила писем и уведомлений.**
- Письмо анонса уходит ровно один раз.
- Лестница ограничений: исключение важнее тарифа, тариф важнее умолчания.

## 5. Что отмирает по дороге

- Заглушка backend для разработки (964 строки) — во Flutter будет свой механизм.
- Полосы перетаскивания окна и прочая обвязка WPF-рамки.
- Мост между WPF и вебом: скрипт начальной загрузки, отображение локальной папки на виртуальный
  хост, обмен сообщениями с окном.
- Слой CSS целиком: 27 файлов Оператора плюс общий kit — во Flutter это тема и виджеты.
- Пять сборок Vite и связанная с ними инфраструктура.
- Осиротевший отчёт «Действия оператора»: жив на сервере и уходит в плановые рассылки, но в
  интерфейс не выведен — при переезде либо вывести, либо осознанно похоронить.

## 6. Узлы риска

1. **Platform Control в браузере** — решение по нему определяет, уходит ли TypeScript совсем.
2. **Установщик** — смена рантайма затрагивает самый хрупкий кусок; переносить последним.
3. **Киоск-режим оболочки игрового ПК** — поверх всех окон и блокировка ввода; в WPF из коробки,
   во Flutter под Windows через ручные системные вызовы.
4. **287 файлов тестов** не переезжают. Правила из раздела 4 обязаны получить тесты заново, иначе
   миграция молча растеряет поведение.
5. **Комиссия магазина за пополнение баланса** в клиентском приложении — проверить до подачи.

## 7. Предлагаемый порядок

От малого к большому, чтобы конвейер сборки и публикации отлаживался на дешёвом:

1. **Клиентское** (1 900 строк) — заодно первым едет в магазины, отлаживает подпись и публикацию.
2. **Общий слой** (тема, локализация, деньги, форматирование, атомы интерфейса) — вытаскивается
   из первого приложения, когда становится ясна его форма.
3. **Оболочка игрового ПК** (1 200 строк) — первый Windows-таргет, проверка киоск-режима.
4. **Оператор** (32 700 строк) — основной объём; внутри режется по разделам из раздела 2.
5. **Platform Control** — после решения по узлу 1.
6. **Мастер установки** — последним, вместе с пересборкой установщика.
