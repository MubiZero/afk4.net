# P4. Интерфейс оболочки

Дата: 2026-09-24. Спека: `../specs/2026-09-24-player-shell-rewrite-design.md`, §3, §4.4, §7–§9.
Экраны — концепт «Экран места» (артефакт владельца). Нынешний интерфейс выбрасывается целиком.

## Что нашло чтение кода

- Шрифтов Golos Text и JetBrains Mono в репозитории нет. Берём пакеты `@fontsource` (OFL):
  Vite кладёт файлы в сборку, у ПК без сети они есть. Кириллическое расширение закрывает
  таджикские буквы.
- Префикс строк `shell.*` занят Панелью и Platform Control — у оболочки `playerShell.*`.
- У `@afk4/host-bridge` нет подписки на сообщения хоста; каждый клиент пишет свою. Подписка
  добавляется в пакет.
- Учебного хоста в браузере у мастера нет, есть у Панели (`devHostBridge.ts`, только в dev-сборке).
  Оболочка повторяет этот образец: сценарии состояний переключаются в браузере без WPF и агента.
- Хост и интерфейс едут одним MSI: новый интерфейс вливается вместе с новым хостом (P3) или
  после него. Сами по себе старый хост и новый интерфейс друг друга не поймут.

## Нарезка

Четыре PR поверх P1 (#443) — интерфейсу нужны поля состояния v2.

### P4a. Каркас

- Тема `player` в `@afk4/tokens`: тёмная, единственная, заслон контраста — как у остальных тем.
- Шрифты в оболочке; основной текст не мельче 18 px на 1080p, кнопки от 56 px — размеры от
  ширины экрана.
- `onHostMessage` в `@afk4/host-bridge`; `formatMoney` в `@afk4/money` («12 с.»).
- Типы моста v2 (§4.4) — записи C#, TS генерируется: запросы `auth.signIn`, `app.launch`,
  `assist.call`…, события `state.changed`, `auth.changed`, `input.idle`….
- Поля состояния, которых нет у агента: место, зона, владелец сессии, права организации —
  необязательные; заполняет агент в P3 из сердцебиения P2a.
- Экран выбирается функцией от состояния агента, входа и локального режима (§3), без адресов.
- Отсчёт — отдельный компонент, тикает сам по границе секунды с поправкой на часы ПК
  (`ObservedAtUtc`).
- Учебный хост: `?scenario=idle|approach|session|ending|grace|offline|maintenance`.
- Экраны: «Свободен» (витрина-заглушка и знак ПК), «Нет связи», «Обслуживание».

### P4b. Вход

Окно входа (номер и ПИН-код, QR с кодом посадки), отказы входа, приветствие вошедшего и выход;
окно раскрывается из угла знака ПК.

«Сколько играем» по `start-offers` и старт переехали в P4c: их типы живут в P2c (#446), а ветка
P4 стоит на P1. Они приходят, когда стопки P1 и P2 вольются в `main`.

### P4c. Выбор времени и сессия

Режется на части, по PR на каждую:

- **P4c-1 — «Сколько играем»:** цены по `start-offers`, старт по тарифу и по пакету.
- **P4c-2 — сессия:** каркас (вкладки, колонка «время и деньги»), продление по `extend-offers`,
  «Встать раньше» по `end-quote`.
- **P4c-3 — бар, пополнение по QR, итог с оценкой.** Чаевые — после спеки P8.

Решения P4c-1:

- **Оболочка садит без кода посадки.** Код одноразовый, и вход по QR его гасит, а новый приходит
  только со следующим сердцебиением. Первый же запрос цен после входа по QR уходил бы с погашенным
  кодом и засчитывался игроку неверной попыткой. Сервер теперь знает ПК токена
  (`PlatformPersonContext.DeviceId`): цены — `GET /api/me/this-pc/start-offers`, старт —
  `POST /api/me/sessions/start` с пустым кодом. Токен, привязанный к ПК, выдаётся только ключом
  этого ПК и сам доказывает, где человек сидит; телефону этот путь закрыт.
- Суммы, «до скольки» и «не хватает» приходят с сервера; «до скольки» — по часам клуба.
- Один ключ идемпотентности на один выбор: повтор после обрыва получит ту же сессию.
- Отказ старта — своими словами по коду сервера; после денежного отказа и закрытого тарифа цены
  перечитываются.
Решения P4c-2:

- Колонка «время и деньги» справа от игр: остаток, «до скольки», «Продлить», «Встать раньше».
  Денежные кнопки — только у владельца сессии, вошедшего на этом ПК. Сессия игрока без входа на
  ПК (сел с телефона) — «Войти» поверх экрана сессии. Сессия стойки без счёта — «продлевает
  администратор» и кнопка вызова.
- Без связи с клубом продлить и встать раньше нельзя — кнопки закрыты, сказано почему.
- Продление — варианты с готовыми суммами (`extend-offers`), сессия по пакету и сессия стойки
  говорят, почему продлить отсюда нельзя. «Встать раньше» — сначала `end-quote`: сколько спишут и
  сколько вернётся, потом выход.
- Итог раннего выхода — сколько сыграно и что вернулось; 25 секунд или «Выйти» — выход, «Играть
  ещё» — снова выбор времени. Итог после конца по таймеру и оценка визита — P4c-3.
- Учебный хост: `?signedIn=1` — сразу вошедший владелец, продление и ранний выход отвечают.
- По дороге: двойная рамка поля телефона на входе Панели и мастера — отдельный PR (#459).

- По дороге нашлась дыра CORS: страницы собственных приложений (`player.afk4.local`,
  `operator.afk4.local`) стояли среди адресов разработчика и в продакшене получили бы отказ на
  каждом запросе. Починено отдельным PR (#457).

### P4d. Витрина и отделка

Карусель витрины с заранее декодированными картинками, движение по токенам §8, `prefers-reduced-
motion`, бюджет кадра.

## Проверка

- bun: экран на каждое состояние §3, выбор экрана — чистая функция с таблицей случаев; отсчёт;
  мост; заслоны токенов и строк (паритет, мёртвые ключи, голос).
- Сборка — `tsc -b && vite build`.
- Глазами — учебный хост в браузере, снимки по сценариям.
- Чего не докажет ничто из этого: как экран выглядит на мониторе клуба и держит ли он кадр
  рядом с игрой. Это приёмка на живом ПК (§8, §10).
