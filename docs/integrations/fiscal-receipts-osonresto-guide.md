## 1. Как это устроено

### Главная мысль

**Продажа никогда не ждёт аппарат.** Сначала оплата записывается на сервер, и сервер отмечает: «за эту оплату должен быть
фискальный чек». Потом касса, к которой подключён аппарат, сама забирает список долгов, печатает чеки и сообщает
серверу номер и фискальный признак каждого (`internal/orders/fiscal.go:21-23`,
`packages/core/lib/src/fiscal/fiscal_worker.dart:80-86`).

Пример из жизни. Это похоже на журнал у кассы: продавец записал «стол 5 оплатил 120 сомони наличными», а помощник у
аппарата печатает по журналу чек за чеком и ставит рядом номер. Кончилась бумага — записи ждут, продажи идут дальше.

### Кто с кем говорит

```
 ┌────────────── Касса (приложение staff, роль «Касса») ───────────────┐
 │ оплата / возврат ──► API сервера (Go)        FiscalWorker (Dart)    │
 │                     пишет долг в             раз в 20 с и после     │
 │                     fiscal_receipts          каждой оплаты:         │
 │                          ▲                   список → claim →       │
 │                          │ отчёт: done/      печать → отчёт         │
 │                          │ pending/failed          │                │
 └──────────────────────────┼─────────────────────────┼────────────────┘
                            │                         │ JSON по HTTP, POST /api/<метод>
                            │          ┌──────────────┴───────────────┐
                            │          │ Android / десктоп: напрямую  │
                            │          │ http://<IP аппарата>:8002    │
                            │          │ Браузер на Windows: через    │
                            │          │ мост http://127.0.0.1:8017   │
                            │          │ (cmd/fiscalbridge, один exe) │
                            │          └──────────────┬───────────────┘
                            │                         ▼
                            │            Fiscat TP809 (фискальный регистратор)
                            │            печатает чек и сам отправляет его
                            └─ сервер не говорит с аппаратом напрямую      в налоговую (ОФД)
```

- **Сервер** хранит только две вещи: какие чеки должны быть и что ответил аппарат (`internal/orders/fiscal.go:21-23`).
  Сервер к аппарату не ходит.
- **Касса** печатает чеки. Работник (worker) есть только на устройстве с ролью «Касса» и с указанным адресом аппарата
  (`apps/staff/lib/fiscal/fiscal.dart:42-46`). Он запускается вместе с приложением (`apps/staff/lib/app/router.dart:249`).
- **Мост** нужен только браузеру. Страница по https не может обратиться к `http://<IP в локальной сети>`, а к
  `http://localhost` может (`docs/strategy/fiscal.md:24-28`, `cmd/fiscalbridge/main.go:1-3`).
- **iPad / Safari:** до аппарата не достучаться, нужна iOS-сборка. Пока это записано как «стоп»
  (`docs/strategy/fiscal.md:28`, `docs/strategy/fiscal-visit.md:14`).

### Где хранится настройка

| Что | Где | Кто меняет |
|---|---|---|
| Адрес аппарата для этой кассы (`http://192.168.1.60:8002` или мост `http://127.0.0.1:8017`) | только на устройстве, `DeviceConfig.fiscalBase`, ключ JSON `fiscal` (`apps/staff/lib/setup/device_config.dart:65-67,94,105`) | «Это устройство» → «Фискальный принтер» (`apps/staff/lib/setup/device_screen.dart:103-104`) |
| Чек обязателен, налоговый режим, код НДС | на сервере, `venues.settings.fiscal` = `{"required":true,"tax_type":"GENERAL","vat_code":"REDUCED1"}` (`internal/orders/fiscal.go:25-26`) | только владелец (`internal/platform/venue.go:253-256`); экран: `apps/staff/lib/screens/admin/venue_section.dart:407-410` |
| Адрес аппарата у моста | файл `fiscalbridge-printer.txt` рядом с exe, иначе в папке настроек пользователя (`cmd/fiscalbridge/main.go:225-253`) | мост сам находит аппарат, или флаг `-printer` |
| Идентификатор кассы для аренды чека (`holder`) | `SharedPreferences`, ключ `fiscal.holder`, один на установку (`apps/staff/lib/fiscal/fiscal.dart:82-88`) | создаётся сам |

### Пример: продажа

1. Гость платит 120,00 наличными. Касса записывает оплату на сервер. В той же транзакции сервер создаёт строку
   `fiscal_receipts` с `id = id оплаты`, статусом `pending` и составом заказа на этот момент
   (`internal/orders/store.go:1850-1856`, `internal/orders/fiscal.go:118-129`).
2. Касса сразу будит работника (`apps/staff/lib/screens/pos/pos_state.dart:792`). Работник спрашивает аппарат о
   состоянии, берёт список долгов и «захватывает» чек на сервере: чек привязывается к серийному номеру аппарата и на
   2 минуты закрепляется за этой кассой (`fiscal_worker.dart:184-191`, `internal/orders/fiscal.go:240-299`).
3. Работник собирает тело чека и вызывает `formReceipt` с `externalId = id оплаты`. Аппарат печатает чек и возвращает
   номер ФД и фискальный признак (ФП). Работник отчитывается серверу `done` (`fiscal_worker.dart:201-229,247-250`).
4. Под оплатой на кассе появляется «Фискальный чек: пробит» (`apps/staff/lib/fiscal/fiscal.dart:141-199`).

### Пример: возврат

1. Кассир возвращает 20,00 из этой оплаты. Сервер пишет возврат и долг чека возврата: `kind='refund'`,
   `id = id возврата`. Состав чека берётся из возвращённой позиции, а если её нет, повторяется состав чека оплаты
   (`internal/orders/store.go:2057-2063`, `internal/orders/fiscal.go:131-141`).
2. Чек возврата печатается только после чека самой оплаты. Это проверяют и сервер, и касса
   (`internal/orders/fiscal.go:279-287`, `fiscal_worker.dart:152-154`).
3. Работник печатает `formReceipt` с `operationType: REVERT_INCOME` (`fiscal_receipt.dart:109`).

## 2. Аппарат, протокол, мост

### Что поддержано

Поддержан **один аппарат и один протокол**: Fiscat TP809 от «Технология Групп», «Fiscat protocol 2.0». Обмен идёт
JSON по HTTP в локальной сети: `http://<ip>:8002/api/<метод>` (`docs/strategy/fiscal.md:1-5`,
`packages/core/lib/src/fiscal/fiscat.dart:5-9`). В документе упомянут ещё RS-232 (`docs/strategy/fiscal.md:5`), но в
коде **нет ни COM, ни USB**. Других моделей и протоколов (АТОЛ, Штрих, драйверы ККТ и т. п.) в коде нет.

### Транспорт

| Клиент | Как доходит до аппарата | Где |
|---|---|---|
| Android, macOS, Windows, Linux (сборка Flutter) | Dio прямо на `http://<ip>:8002` | `fiscat.dart:10-20`, адрес: `apps/staff/lib/fiscal/fiscal.dart:28-37` |
| Браузер (Flutter web) | Dio на `http://127.0.0.1:8017`, мост пересылает `/api/*` без изменений | `apps/staff/lib/fiscal/fiscal.dart:19-21`, `cmd/fiscalbridge/main.go:142-147` |
| Тесты | `HttpClientAdapter`-подделка внутри Dio | `apps/staff/test/fiscal_flow_test.dart:20`, `packages/core/test/fiscal_test.dart:35` |

**Поиск в сети.** Приложение проверяет порт 8002 на адресах .1–.254 своих частных подсетей /24, но не больше двух
подсетей (`apps/staff/lib/printing/platform_io.dart:15-24`, `apps/staff/lib/printing/network_scan.dart:9-53`). Это
только TCP-подключение. Мост проверяет точнее: шлёт `POST /api/deviceStatus` и ждёт JSON с полем `rc`
(`cmd/fiscalbridge/main.go:159-181`). В браузере поиска нет (`apps/staff/lib/printing/platform_web.dart:8-9`).

### Формат команд

- Всегда `POST /api/<метод>`, тело JSON. В каждом теле есть `formCode` для этого метода, например
  `DEVICE_STATUS`, `OPEN_SHIFT`, `RECEIPT` (`cmd/fiscatfake/main.go:173-178`).
- Имена параметров **чувствительны к регистру**. Подделка отвергает незнакомые ключи, потому что стандартный декодер
  Go регистр не различает (`cmd/fiscatfake/main.go:101-109`, `fiscat.dart:9`).
- Суммы передаются в **дирамах**, целым числом (`fiscat.dart:9`).
- Строки ограничены **байтами UTF-8**, а не символами: кириллическая буква занимает 2 байта. Название позиции — до 128 байт,
  кассир — до 64. Обрезка не режет букву пополам (`fiscat.dart:76-88`).
- `externalId` — до 36 символов ASCII (`cmd/fiscatfake/main.go:335-345`). У нас это UUID оплаты или возврата.

Методы, которые есть в протоколе (по подделке), и то, что из них использует наш клиент:

| Метод | formCode | Используем | Где |
|---|---|---|---|
| `deviceStatus` | `DEVICE_STATUS` | да | `fiscat.dart:50` |
| `openShift` / `closeShift` (печатает Z) | `OPEN_SHIFT` / `CLOSE_SHIFT`, обязателен `cashier` | да | `fiscat.dart:53-58` |
| `formReceipt` (`INCOME`, `REVERT_INCOME`, `EXPENDITURE`, `REVERT_EXPENDITURE`) | `RECEIPT` | да, только INCOME и REVERT_INCOME | `fiscat.dart:61`, `fiscal_receipt.dart:109` |
| `getFDByExternalID` | `PRINT_FD_BY_EXTERNAL_ID` | да, перед повтором | `fiscat.dart:65-73` |
| `getLastFD`, `getFDByNumber` | `PRINT_LAST_FD`, `PRINT_FD_BY_NUMBER` | нет | `cmd/fiscatfake/main.go:457-490` |
| `getXReport` | `GET_X_REPORT`, `ffdVersion: VER_1` | **нет** | `cmd/fiscatfake/main.go:228-238` |
| `addCash` / `removeCash` (внесение / изъятие) | `ADD_CASH` / `REMOVE_CASH` | **нет** | `cmd/fiscatfake/main.go:201-225` |
| `formCorrectionReceipt` | `CORRECTION_RECEIPT` | **нет** | `cmd/fiscatfake/main.go:241,371-374` |
| `openDrawer`, `writeCustomLog` | `OPEN_DRAWER`, `WRITE_CUSTOM_LOG` | нет | `cmd/fiscatfake/main.go:186-200` |

Печатать произвольный текст этот API не умеет, поэтому бегунки кухни через него не пройдут. Нужен отдельный чековый
принтер или ESC/POS на порту 9100, если аппарат его поддерживает. Это не проверено (`docs/strategy/fiscal.md:11-12`).

### Ответы и коды ошибок

- Успех: `{"rc":"SUCCESS","data":{...}}`. Ошибка: `{"rc":"<КОД>","message":"..."}` **с HTTP 200**
  (`cmd/fiscatfake/main.go:1-3,139-145`). Поиск документа отвечает «плоским» объектом без `rc`; клиент понимает оба
  вида (`fiscat.dart:26-47`).
- Коды разложены по классам, с которыми кассир может что-то сделать (`fiscat.dart:110-141`):

| Класс | Коды аппарата | Проходит сам? |
|---|---|---|
| `unreachable` | `UNREACHABLE`, `NO_ANSWER`, `BAD_ANSWER` (наши), `BRIDGE_ERROR` (мост) | да |
| `paperOut` | `OUT_OF_PAPER`, а также открытая крышка или нет бумаги в `deviceStatus` | да |
| `deviceError` | `FISCAL_MODULE_ERROR`, `UNKNOWN_ERROR` | да, до 5 попыток (`fiscal_worker.dart:97,232`) |
| `shiftTooLong` | `SHIFT_TOO_LONG` (смена открыта больше 24 ч, `internal/orders/fiscal.go:189`) | чинится автоматически |
| `notRegistered` | `CORE_IS_NOT_ACTIVATED`, `NOT_REGISTERED` | нет |
| `blocked` | `CORE_IS_BLOCKED` | нет |
| `expired` | `FISCAL_MODULE_EXPIRED`, `KEYS_ERROR` | нет |
| `clock` | `DATETIME_ERROR` | нет |
| `cashShort` | `CASH_NOT_ENOUGH` | нет |
| `needsRrn` | `INVALID_BANK_RRN` | нет: человек вводит RRN |
| `taxUnset` | не выбран налоговый режим (наш класс) | нет |
| `refused` | всё остальное, например `INVALID_DOC` | нет |

Тексты для кассира лежат в `apps/staff/lib/l10n/app_ru.arb:4031-4042`, для владельца в Telegram — в
`internal/orders/fiscal.go:182-194`.

**Различие «не дошло» и «ответ потерялся» — главное для идемпотентности** (`fiscat.dart:33-37,96-100`):
- `UNREACHABLE`: Dio не смог подключиться (`connectionTimeout`, `connectionError`). Чек точно не создан.
- `NO_ANSWER`: запрос ушёл, ответа нет. Чек **мог** напечататься.

### Таймауты

| Где | Значение | Ссылка |
|---|---|---|
| Клиент: подключение / отправка / ответ | 4 с / 10 с / 40 с (резак медленный, «нет ответа» не должно срабатывать раньше времени) | `fiscat.dart:13-17` |
| Мост: подключение к аппарату / заголовки ответа | 5 с / 30 с | `cmd/fiscalbridge/main.go:48-52` |
| Мост: проверка в поиске | 500 мс подключение, 3 с весь запрос; весь поиск 10 с; повторный поиск не чаще раза в 15 с | `cmd/fiscalbridge/main.go:66-82,160-164,286` |
| `/health` моста: TCP-проверка | 1,5 с | `cmd/fiscalbridge/main.go:132` |
| Аренда чека на сервере | 2 мин | `internal/orders/fiscal.go:177-179` |
| Повтор работника | каждые 20 с и после каждой оплаты или возврата | `apps/staff/lib/fiscal/fiscal.dart:26,73` |

Через мост ответ дольше 30 с превращается в `502 BRIDGE_ERROR` (класс `unreachable`), хотя чек мог напечататься. Это
безопасно: следующая попытка всегда сначала ищет чек по `externalId` (см. п. 3).

### Мост `cmd/fiscalbridge`

- Слушает только `127.0.0.1:8017` и ходит на порт аппарата 8002. **Порт аппарата задан константой**, флаг `-printer`
  принимает только IP (`cmd/fiscalbridge/main.go:24-29,42`).
- Принимает только `GET /health` и `GET|POST /api/*`, всё остальное отдаёт 404 (`main.go:127-150`).
- CORS: пускает `https://staff.osonresto.com`, свой список через `-origins`, и всегда `http://localhost:*` и
  `http://127.0.0.1:*`. Чужой Origin получает 403. На preflight отвечает `Access-Control-Allow-Private-Network: true`
  (`main.go:84-91,108-125`). Запрос без Origin (curl, скрипт) пропускается: браузер Origin присылает всегда
  (`main.go:108`).
- В лог пишет строку на запрос (метод, путь, статус, мс). **Тела чеков в лог не пишет** (`main.go:104-106`).
- Аппарат не найден → 502 `{"rc":"BRIDGE_ERROR","message":"printer not found"}` (`main.go:143-145`).
- Под Windows включает UTF-8 в консоли, иначе русский текст превращается в мусор (`cmd/fiscalbridge/console_windows.go`).
- Сборка: `make fiscalbridge-windows` → `dist/fiscalbridge-windows-amd64.exe` (`Makefile:26-29`). Установка по шагам
  описана в `docs/strategy/fiscal.md:55-73`.

## 3. Жизненный цикл

### Смена аппарата

- **Открытие.** Кассир открыл нашу смену → работник открывает смену аппарата, если она закрыта
  (`apps/staff/lib/screens/pos/pos_sheets.dart:1477`, `apps/staff/lib/fiscal/fiscal.dart:105-110`,
  `fiscal_worker.dart:253-262`). Если не получилось, кассир видит сообщение. Чеки подождут, а смена аппарата откроется
  с первым чеком, который пройдёт.
- **Смена не открыта при чеке** (`SHIFT_MUST_BE_OPENED`) → открыть и отправить ещё раз, один раз
  (`fiscal_worker.dart:218-219,226`).
- **Смена дольше 24 часов** (`SHIFT_TOO_LONG`) → закрыть (печатается Z), открыть, отправить ещё раз
  (`fiscal_worker.dart:220-222`). То есть Z может напечататься сам посреди дня.
- **Закрытие.** Закрылась **последняя** открытая смена заведения: на один аппарат приходится одна смена для всех кассиров
  (`apps/staff/lib/fiscal/fiscal.dart:112-124`, `apps/staff/lib/screens/pos/shift_team.dart:83`). Перед закрытием работник
  допечатывает долги. **Он не закрывает смену, пока есть чек без ответа аппарата**: после закрытия аппарат забыл бы
  `externalId`, и чек мог бы напечататься дважды (`fiscal_worker.dart:264-278`).
- **Z вручную:** кнопка в карточке аппарата (`apps/staff/lib/fiscal/fiscal_settings.dart:74-86,187-193`).
- **X-отчёт, внесение и изъятие в аппарате, сверка нашего Z с Z аппарата — не сделаны.** Сверка была в плане
  (`docs/strategy/fiscal.md:18`), но в коде её нет. Наличные кассы (`POST shifts/{id}/cash`) в аппарат не передаются.

### Чек продажи

Тело собирает `fiscalReceiptBody` (`packages/core/lib/src/fiscal/fiscal_receipt.dart:90-125`):

- **Позиции.** Состав фиксирует сервер в момент долга: блюда с модификаторами по-русски, плюс «Обслуживание»,
  «Доставка», «Чаевые» строками-услугами (`internal/orders/fiscal.go:73-105`). Блюдо уходит как `GOODS`, услуга как
  `SERVICE` (`fiscal_receipt.dart:113`).
- **Точная сумма.** Сумма оплаты делится между строками пропорционально, методом наибольшего остатка. Поэтому скидка,
  бонусы, сертификат, округление и раздельный счёт сходятся до дирама. Если доля строки не делится на количество,
  строка разбивается на две: 100,01 на троих → 2 × 33,34 + 1 × 33,33 (`fiscal_receipt.dart:28-72`). Если доля меньше
  количества (3 блюда на 2 дирама), в чеке остаются только блюда, которым достался дирам: это помечено как известный
  предел (`fiscal_receipt.dart:68`).
- **НДС.** Один код НДС на весь чек. НДС считается внутри суммы и округляется половиной вверх
  (`fiscal_receipt.dart:79-84,119-123`). Ставки кодов (в десятых процента): STANDARD 14 %, REDUCED1 7 %, REDUCED2 5 %,
  REDUCED3 2,5 %, REDUCED4 10 %, ZERO_TAX и ZERO_TAX_EXPORT 0 (`fiscal_receipt.dart:7`). Если код не выбран, при общем
  режиме берётся REDUCED1, при остальных ZERO_TAX. **Это догадка для пилота**, её подтверждает бухгалтер
  (`fiscal_receipt.dart:9-11`).
- **Налоговый режим** (`taxType`): из настроек заведения. Если там пусто, берётся режим, на который зарегистрирован
  аппарат, но только если аппарат называет ровно один (`fiscal_worker.dart:147-149`, `fiscat.dart:177-178`). Иначе чеки
  стоят с причиной «владелец не выбрал налоговый режим». Подделка отвергает чек с режимом, отличным от
  зарегистрированного (`cmd/fiscatfake/main.go:363-364`).
- **Способ оплаты.** Наличные идут в `receiptCash`, карта и перевод в `receiptNonCash`
  (`fiscal_receipt.dart:116-117`). Одна оплата — один чек. Смешанной оплаты в одном чеке нет: при раздельном счёте у
  каждой оплаты свой чек (`packages/core/test/fiscal_test.dart:264`).
- **RRN карты.** `bankRRN` уходит, только если введено ровно 12 символов (`fiscal_receipt.dart:118`). При обязательном
  чеке поле RRN для карты сразу открыто в окне оплаты (`apps/staff/lib/screens/pos/pos_sheets.dart:693-712`). Если
  аппарат ответил `INVALID_BANK_RRN`, чек становится `failed`, и кнопка «Пробить чек ещё раз» спрашивает RRN
  (`apps/staff/lib/fiscal/fiscal.dart:201-248`).
- **Сдача: в аппарат не передаётся.** `receiptCash` всегда равен сумме чека, `cashChangeAmount` не отправляется
  (`fiscal_receipt.dart:115-117`), хотя протокол поле знает (`cmd/fiscatfake/main.go:87`).
- **Бумажная копия гостю:** `shouldPrintSlip: true`. Что делает `false`, не проверено (`fiscal_receipt.dart:107-108`).

**Какие оплаты требуют чека.** Только наличные, карта и перевод, и только при включённом `settings.fiscal.required`
(`internal/orders/fiscal.go:116-121`). Бонусы, сертификат и `online` (онлайн-эквайринг) **чека не требуют**. Перевод
курьеру у двери требует чек только после того, как касса подтвердила, что деньги пришли (или превратила его в наличные)
(`internal/orders/store.go:1851-1856`, `internal/orders/courier.go:583-608`).

**Способ оплаты фиксируется.** Как только чек отправлен в аппарат, сменить способ оплаты нельзя: `409 fiscal_sent`,
нужно вернуть деньги и принять оплату заново (`internal/orders/store.go:2146-2153`).

### Чек возврата

- Вызов `REVERT_INCOME`, в `externalId` идёт id возврата (`fiscal_receipt.dart:109`, `internal/orders/fiscal.go:131-141`).
- Состав чека: снятая позиция, если возврат пришёл от отмены строки (`internal/orders/store.go:1440`). Иначе — состав
  чека оплаты.
- Сначала печатается чек оплаты (`internal/orders/fiscal.go:279-287`).
- Отказ курьеру у двери тоже даёт чек возврата (`internal/orders/courier.go:526-536`).
- Подделка требует, чтобы в аппарате набралось достаточно наличных (`CASH_NOT_ENOUGH`, `cmd/fiscatfake/main.go:429-435`).
  Мы внесение в аппарат не делаем, так что наличный возврат в новой смене может упасть. На настоящем аппарате не
  проверено.

### Обрыв связи, повтор, «чек напечатался, ответ потерялся»

Защита от двух чеков на одну оплату устроена в три слоя:

1. **Аппарат сам не отсеивает повторы.** Повторный `formReceipt` с тем же `externalId` создаёт второй чек: так следует
   из документа, подделка повторяет это поведение (`cmd/fiscatfake/main.go:5-6`, `docs/strategy/fiscal.md:72-73`).
2. **Захват на сервере** (`POST fiscal/{id}/claim`) увеличивает `attempts` и возвращает `attempts_before`. При
   `attempts_before > 0` работник **сначала** спрашивает аппарат `getFDByExternalID`. Если чек нашёлся, работник
   отчитывается `done` и ничего не печатает. Отправка идёт, только если аппарат ответил «нет такого»
   (`internal/orders/fiscal.go:288-297`, `fiscal_worker.dart:192-200`). Чек привязан к серийному номеру аппарата:
   другой аппарат его не допечатает (`409 fiscal_other_printer`). Пока действует аренда, другая касса его не возьмёт
   (`409 fiscal_busy`) (`internal/orders/fiscal.go:269-278`).
3. **Сервер отвергает второй ФД.** Если на уже пробитый чек пришёл отчёт `done` с другим номером ФД, сервер отвечает
   `409 fiscal_duplicate`. Отдельной транзакцией он пишет запись в журнал и шлёт владельцу в Telegram «Два фискальных
   чека на одну оплату» (`internal/orders/fiscal.go:355-364,403-421`). Тот же отчёт с тем же ФД принимается молча
   (`:356-357`).

Аппарат надёжно хранит `externalId` только в пределах открытой смены (`fiscat.dart:63-64`). Поэтому смену не закрывают,
пока есть чек без ответа (см. выше).

**Отчёт серверу идёт через офлайн-очередь.** Пробитый чек не потеряется, даже если сервер сейчас недоступен
(`apps/staff/lib/fiscal/fiscal.dart:53-62`). Очередь отправляет `Idempotency-Key`, и сервер на повтор отдаёт первый
ответ (`packages/core/lib/src/offline_queue.dart:228,266`, `internal/httpx/idempotency.go:18-24`).

**Касса без сети.** Оплата лежит в офлайн-очереди, поэтому долга на сервере ещё нет. Касса открывает ящик и печатает на
обычном принтере чек с пометкой «не фискальный». Фискальный придёт, когда оплата дойдёт до сервера
(`apps/staff/lib/printing/slip.dart:117-120`, `apps/staff/lib/printing/auto_print.dart:307-310`,
`pos_state.dart:788-791`).

### Кончилась бумага, аппарат не отвечает, отказ

- Перед каждым проходом работник читает `deviceStatus`. Если аппарат заблокирован, не зарегистрирован, открыта крышка
  или нет бумаги, проход останавливается и все чеки ждут (`fiscal_worker.dart:164-175`).
- Ошибка уровня аппарата (класс «проходит сам»): чек остаётся `pending` с кодом ошибки, проход останавливается, через
  20 с попытка повторяется (`fiscal_worker.dart:230-236`).
- Отказ, который требует человека: чек получает `failed`. Сервер пишет журнал `fiscal.failed` и **всегда** шлёт владельцу
  в Telegram «Фискальный чек не пробит … откройте «Контроль»». Выключателя у этого сообщения нет, потому что это
  обязанность по закону (`fiscal_worker.dart:238-239`, `internal/orders/fiscal.go:380-394`).
- «Пробить чек ещё раз» переводит `failed → pending`, при необходимости с RRN, и пишет журнал `fiscal.retry`
  (`internal/orders/fiscal.go:395-399`, `packages/core/lib/src/api.dart:504-505`).
- Список долгов показан в «Контроле»: неотпечатанные и неудачные чеки с причиной (`apps/staff/lib/fiscal/fiscal.dart:250-291`,
  `apps/staff/lib/screens/admin/control_section.dart:131`). Статус каждой оплаты виден в заказе и на экране «Оплачено»
  (`apps/staff/lib/screens/pos/order_details.dart:155-159`, `pos_sheets.dart:914-915`).
- Если аппарат офлайн от налоговой, он сам копит документы (`queueCount`) и отправит их позже (`fiscat.dart:168-169`).
  Касса показывает «нет связи, в очереди N» (`fiscal_settings.dart:183`).

### Права

- Читать и печатать долги может роль с правом смен (`httpx.Shifts`). Официанту отвечают 403 (`internal/orders/fiscal.go:210,240,304`,
  `internal/e2e/fiscal_test.go:71-73`).
- Фискальные маршруты открыты на **любом тарифе** (`internal/plans/gate.go:94-95`) и во время паузы заведения
  (`internal/httpx/httpx.go:350-353`).
- Настройки `fiscal` меняет только владелец (`internal/platform/venue.go:253-256`).

## 4. Данные на сервере

### Что хранится о каждом чеке

Таблица `fiscal_receipts` (`internal/db/migrations/00092_fiscal_receipts.sql`, `00124_fiscal_lines.sql`). **Строка
есть только там, где чек должен быть. Нет строки — чек не нужен.**

| Поле | Смысл |
|---|---|
| `id` | id оплаты (income) или возврата (refund) — это и есть `externalId` на аппарате |
| `kind` | `income` / `refund`; `check ((kind='refund') = (refund_id is not null))` |
| `payment_id`, `refund_id` | связь с оплатой и возвратом, `on delete cascade` |
| `amount` | сумма чека, `numeric(12,2)`, `> 0` |
| `status` | `pending` → `done` / `failed` (`failed` → `pending` при повторе) |
| `fd_number`, `fpd`, `shift_number`, `receipt_number` | ответ аппарата: номер ФД, фискальный признак, смена и чек в смене |
| `error` | `rc` аппарата или наш `UNREACHABLE` / `NO_ANSWER`, до 200 символов (`fiscal.go:336-339`) |
| `attempts` | сколько раз чек захватывали, основа для «спросить перед повтором» |
| `bank_rrn` | RRN карты, 12 символов, если его ввёл человек |
| `printer` | серийный номер аппарата, на который чек ушёл впервые: только он может его допечатать |
| `lease`, `lease_until` | какая касса печатает чек сейчас и до какого времени |
| `lines` (jsonb) | состав чека на момент долга: `[{name, qty, sum, service?}]` |
| `created_at`, `done_at` | |

Индексы: открытые долги по заведению (`where status <> 'done'`) и по `payment_id`.

К оплате в API добавлены вычисляемые поля `fiscal_status` (`not_needed|pending|done|failed`), `fiscal_error`,
`fiscal_fd` и `refund_fiscal` — худший статус среди чеков возврата (`internal/orders/store.go:66-71`,
`internal/orders/model.go:138-143`).

### API

| Метод | Что | Где |
|---|---|---|
| `GET /api/v1/venues/{v}/fiscal` | долги: `pending` и `failed`, самые старые первыми, до 200 штук, и `total` | `fiscal.go:210-236` |
| `POST .../fiscal/{id}/claim {printer, holder}` | захват: `{item, attempts_before}`; 409 `fiscal_done`, `fiscal_failed`, `fiscal_other_printer`, `fiscal_busy`, `fiscal_wait_income` | `fiscal.go:240-299` |
| `POST .../fiscal/{id} {status, fd_number, fpd, shift_number, receipt_number, error, bank_rrn}` | отчёт; для `done` обязательны `fd_number` и `fpd`; 409 `fiscal_duplicate` | `fiscal.go:304-422` |

### Миграция-образец для нового проекта

Это 00092 и 00124 одним файлом. `payments` и `refunds` замените таблицами своего проекта, `venue_id` — своим
владельцем данных (`business_id` и т. п.).

```sql
-- +goose Up
-- Фискальный чек, который должна оплата (income) или возврат (refund). Строка есть только там, где чек нужен.
-- id = id оплаты/возврата = externalId на аппарате: по нему аппарат находит чек, повтор не создаёт второй.
create table fiscal_receipts (
  id             uuid primary key,
  venue_id       uuid not null references venues(id) on delete cascade,
  kind           text not null check (kind in ('income', 'refund')),
  payment_id     uuid not null references payments(id) on delete cascade,
  refund_id      uuid references refunds(id) on delete cascade,
  amount         numeric(12,2) not null check (amount > 0),
  status         text not null default 'pending' check (status in ('pending', 'done', 'failed')),
  lines          jsonb,         -- состав на момент долга: [{name, qty, sum, service}]
  fd_number      bigint,
  fpd            text,
  shift_number   bigint,
  receipt_number bigint,
  error          text,          -- rc аппарата или UNREACHABLE / NO_ANSWER
  attempts       int not null default 0,
  bank_rrn       text,
  printer        text,          -- серийный номер аппарата, на который чек ушёл впервые
  lease          text,          -- какая касса печатает сейчас
  lease_until    timestamptz,
  created_at     timestamptz not null default now(),
  done_at        timestamptz,
  check ((kind = 'refund') = (refund_id is not null))
);
create index fiscal_receipts_open_idx on fiscal_receipts (venue_id, created_at) where status <> 'done';
create index fiscal_receipts_payment_idx on fiscal_receipts (payment_id);

-- +goose Down
drop table fiscal_receipts;
```

Долг создаётся **в той же транзакции**, что и оплата или возврат (`store.go:1850-1856`, `store.go:2057-2063`). Если сделать
это отдельным шагом, можно получить оплату без долга.

### Шаги

1. **Сервер.**
   1. Миграция из п. 4.
   2. В транзакции каждой оплаты и возврата вызвать «должен чек» по правилам продукта (`fiscal.go:116-141`). Состав
      фиксировать сразу (`fiscal.go:73-91`).
   3. Три маршрута из п. 4, право «смены» у кассира, доступ на всех тарифах и во время паузы.
   4. Настройка `settings.fiscal` меняется только владельцем и проходит проверку кодов (`venue.go:253-261`).
   5. Запрет менять способ оплаты после отправки чека (`store.go:2146-2153`).
   6. Сообщение владельцу о `failed` и `fiscal_duplicate` плюс журнал (`fiscal.go:380-421`).
   7. Добавить `fiscal_status` к оплате в ответе API (`store.go:66-71`).
2. **Клиент.**
   1. `FiscatClient` и `FiscalWorker` — только на устройстве-кассе с адресом аппарата (`fiscal.dart:42-80`).
   2. Отчёт через офлайн-очередь с `Idempotency-Key`.
   3. `kickFiscal` после оплаты и возврата, таймер 20 с.
   4. Открытие и закрытие смены аппарата вслед за своей сменой; закрытие — только после последней смены.
   5. UI: карточка аппарата (поиск, адрес вручную, мост в браузере, «Проверить», Z), статус под оплатой, «Пробить ещё
      раз» с RRN, список долгов, настройки владельца.
3. **Платформы.** Android, iOS и macOS должны пускать обычный HTTP по локальной сети. В resto на iOS есть
   `NSLocalNetworkUsageDescription` (`apps/staff/ios/Runner/Info.plist:5-6`), на macOS — `network.client`
   (`apps/staff/macos/Runner/Release.entitlements:7`). Явного `usesCleartextTraffic` в Android-манифесте нет.
   `FiscatClient` использует обычный `Dio()` с адаптером `dart:io` (`fiscat.dart:12-18`). Если в новом проекте поставить
   ему нативный адаптер (`native_dio_adapter`), включатся правила платформы для cleartext. Проверить на релизной сборке.
4. **Веб.** CSP страницы не должен закрывать `connect-src` к `http://127.0.0.1:8017`. В resto `connect-src` не
   ограничен специально (`cmd/staffweb/main.go:44-49`). Домен продукта нужно добавить в origins моста.

(`docs/strategy/fiscal.md:44`). Зелёные тесты не доказывают, что настоящий аппарат примет чек.

### Чек-лист перед боем

Порядок взят из `docs/strategy/fiscal-visit.md` и `docs/strategy/fiscal.md:42-53`:

- [ ] Чем касса: Windows + браузер (мост), Android (напрямую) или iPad (стоп).
- [ ] `deviceStatus` с ноутбука: зарегистрирован, онлайн, смена, бумага, `registrationInformation.taxCode`. Ответ

- [ ] Мост: exe на кассовом ПК, автозапуск через `shell:startup`, `/health` → `reachable:true`.
- [ ] В кассе: «Фискальный принтер» → найти → «Проверить».
- [ ] Ответы бухгалтера: режим, НДС, чаевые и сервис как услуга, RRN.
- [ ] **Пробный чек только с согласия бухгалтера.** На зарегистрированном аппарате любой чек настоящий:
      продажа и возврат — это два фискальных документа (`fiscal-visit.md:33-40`).
- [ ] Владелец меняет заводской пароль веб-интерфейса аппарата (`fiscal-visit.md:47-48`).
- [ ] Только после этого включить «Фискальный чек обязателен». Если что-то пошло не так, выключить: продажи идут как
      раньше.
- [ ] Отказы владельцу в Telegram приходят: проверить на одном `failed`.

## 6. Закон Таджикистана: что подтверждено и что проверить

### Что подтверждено в resto

**Текста закона или Налогового кодекса РТ в репозитории нет.** Ни одна строка кода не ссылается на статью. Подтверждено
только следующее, и только как факт о проекте, а не как норма закона:

- Для Chicago Burger фискальный чек обязателен, аппарат зарегистрирован. Это **слова владельца** от 2026-10-11
  (`docs/strategy/fiscal.md:3-4`).
- На зарегистрированном аппарате любой чек настоящий и уходит в налоговую (`docs/strategy/fiscal-visit.md:34`).
- Аппарат сам отправляет документы оператору, без связи копит их в очереди (`docs/strategy/fiscal.md:3-4`,
  `fiscat.dart:168-169,209-210`).
- Коды налоговых режимов и НДС взяты из протокола аппарата (`internal/orders/fiscal.go:28-32`). Подписи с процентами
  (упрощённый 6/13/18 %, со скидкой 50 % — 3/6,5/9 %, НДС 14/7/5/2,5/10 %) стоят в интерфейсе
  (`apps/staff/lib/fiscal/fiscal_settings.dart:200-221`) и **бухгалтером не подтверждены**. «Для общепита 7 %» в коде и
  документах помечено «вероятно» (`docs/strategy/fiscal.md:21-22`, `fiscal-visit.md:43`).
- Смена аппарата не может длиться больше 24 часов. Это правило аппарата (`SHIFT_TOO_LONG`), а не цитата закона
  (`internal/orders/fiscal.go:189`).

### Проверить у налоговой / поставщика аппарата

Ниже вопросы, а не утверждения.

**Налоговая / бухгалтер:**
1. Какие виды деятельности обязаны пробивать чек: общепит, салоны и услуги, доставка. С какого оборота и с какой даты.
2. Ставка НДС в чеке для общепита и для услуг при общем режиме. Нужен ли НДС в чеке при упрощённом режиме.
3. Нужно ли пробивать чаевые, сервисный сбор и доставку, и с каким признаком (товар / услуга).
4. Нужен ли чек на оплату бонусами и сертификатом. Resto его не пробивает (`fiscal.go:119`). Как пробивать продажу
   самого сертификата (аванс?).
5. Кто пробивает чек при онлайн-оплате через эквайринг (Alif и т. п.). Resto для способа `online` чек не создаёт.
6. Допустимо ли пробивать чек позже оплаты: сейчас при сбое аппарата он печатается через минуты, а при долгом сбое
   и позже. Нужно ли выдавать гостю бумажный фискальный чек сразу.
7. Нужно ли указывать в чеке полученные наличные и сдачу (сейчас сдача не передаётся).
8. Возврат: достаточно ли `REVERT_INCOME`, или нужен чек коррекции. Как оформлять возврат за прошлую смену или день.
9. Сколько аппарат может работать без связи с оператором, прежде чем его заблокируют.
10. Можно ли выдавать электронный чек (SMS/e-mail, `consumerContacts`) вместо бумажного.
11. Обязателен ли ежедневный Z-отчёт и сверка с учётом кассы.
12. Нужен ли RRN в чеке при оплате картой и чем его заменить при переводе на карту, где RRN нет.

**Поставщик аппарата («Технология Групп»):**
13. Отсеивает ли аппарат повтор `externalId` в `formReceipt`. Находит ли `getFDByExternalID` чек после закрытия
    смены. Какой вид имеет его ответ (`fiscal.md:46`).
14. Что печатает `shouldPrintSlip: false`. Проверяет ли аппарат `vatSum`. Как он округляет `sum` при дробном
    количестве.
15. Обязателен ли `bankRRN` при `receiptNonCash > 0`.
16. Ведёт ли аппарат счётчик наличных, нужен ли `addCash` в начале смены, чтобы прошёл наличный возврат
    (`CASH_NOT_ENOUGH`).
17. Принимает ли аппарат ESC/POS на 9100 для кухонных бегунков.
18. Есть ли у HTTP API аппарата авторизация. Наш клиент не шлёт никаких учётных данных (`fiscat.dart:31-32`), так что
    любой в той же сети может, похоже, вызвать `formReceipt`. Как это закрыть.
19. Срок фискального модуля (`fnLifetime`) и порядок его замены, перерегистрация при переезде.
20. Есть ли RS-232/USB-вариант для мест без локальной сети. Какие ещё модели сертифицированы в РТ и совпадает ли у них
    протокол.

**Платформы:**
21. Пускает ли текущий Chrome https-страницу к `http://127.0.0.1:8017`: правила Private/Local Network Access
    меняются, мост отвечает только PNA-заголовком (`cmd/fiscalbridge/main.go:120`). Проверить на кассовом ПК.
22. Релизные сборки Android и iOS доходят до `http://<ip>:8002` (см. п. 5, «Платформы»).
